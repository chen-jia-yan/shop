# 任务模板(每个交给 AI 的任务都按这个写)
> 用法:复制下面"模板"一份填好发给 AI。字段别省——省了它就自由发挥。

## 模板
**任务目标(一句话):**
<这次要达成什么>

**背景/上下文:**
<为什么做、和哪些现状/模块相关>

**范围(只允许动这些):**
<文件 / 模块清单>

**明确不做(红线):**
<不许碰的文件/逻辑/接口;不许"顺便优化">

**参考(定稿/契约):**
<设计定稿文件、CONTRACTS、要照抄的样式等>

**必须保持不变:**
<接口契约、并发/锁、续跑/幂等/重试、性能、数据安全等>

**具体要求(分小步):**
1. <第一步,可单独验收>
2. <第二步>

**验收标准(可判定通过/失败):**
- <点哪里、看什么、通过条件>

**验证方式:**
- 静态检查 + 单文件小测;不要真跑整个 worker(除非我同意)。

**风险与回退:**
<已知风险;改坏了怎么退回(基线副本/开关)>

## 迷你示例(填好的样子)
**任务目标:** 给 embedding 加超长兜底,不改切分。
**范围:** embedding 调用处(embed_chunk_batch / provider)。
**明确不做:** 不改切分逻辑、不拆存储里的 chunk、不动 worker。
**必须保持不变:** 表格完整性;重试/续跑/幂等。
**具体要求:** 1) 发送前估 token;2) 超 ~8000 的分窗 embedding 再 mean-pool 合并,chunk 存储仍完整。
**验收标准:** 之前报 8192 的文件能入库;普通块不触发兜底、行为不变。
**验证方式:** 静态 + 挑那个报错文件单测。
**风险与回退:** 合并可能略降检索精度;保留旧 embedding 路径开关可退回。
