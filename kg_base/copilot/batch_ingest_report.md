# 批次入库情况报告生成

把一批文件的入库结果,汇总成一份**给领导看的、专业且直观**的报告。只读数据、不改任何东西。

## 适用场景
- 一批文件传完 / 入库跑完后,需要一份结果汇总。
- 领导要看"这批传了多少、成了多少、哪些没成、为什么、接下来怎么办"。

## 开工前需要确认(缺哪项就先问我,别假设)
1. **批次范围** —— 要统计哪一批?可选:`今天` / `最近 N 小时` / `某个时间段(起止)` / 状态库里的某个批次标识(若有)。**默认**:上次生成报告之后到现在;若无记录则取今天。
2. **输出位置与文件名** —— 默认存 `reports/批次入库报告_<日期>.md`(不覆盖旧的)。
3. **语言** —— 默认中文(给领导看)。

> ⚠️ 若用户没一次说全,先把缺的问清楚再动手。

## 数据来源(只读)
- 入库状态存在 **SQLite 状态库**里(worker 用的那个)。**先读 `kb_admin/state_store.py`** 弄清真实的数据库路径、表名、字段名(状态列、文件名、错误信息、时间戳),**不要凭空假设 schema**。
- 只用 **SELECT 查询**。**严禁** INSERT/UPDATE/DELETE/ALTER,严禁改库、删库、删中间产物。
- 需要补充失败细节时,可只读项目日志文件;**不得启动 worker、不得真跑入库**。

## 报告结构(照这个模板产出)
```
# 批次入库情况报告
**批次范围**:<起止时间 / 批次标识>  **生成时间**:<datetime>

## 一句话结论
<一句话说清这批整体情况:共 X 个文件,成功率 Y%,主要问题是 Z。>

## 核心指标
| 指标 | 数值 |
| --- | --- |
| 文件总数 | <n> |
| ✅ 成功入库 | <n>(<pct>%) |
| ❌ 失败 | <n>(<pct>%) |
| ⛔ 卡死/超时 | <n>(<pct>%) |
| ⏳ 仍在处理 | <n> |
| 本批耗时 | <最早开始 ~ 最晚完成,总时长> |

## 状态一览
✅ 成功 <n>　❌ 失败 <n>　⛔ 卡死 <n>　⏳ 处理中 <n>
<用方块或百分比直观表示占比,例如:成功 ████████░░ 80%>

## 失败归因
| 原因分类 | 数量 | 占比 | 说明(人话) | 建议动作 |
| --- | --- | --- | --- | --- |
| <按下方"失败归因对照表"归类> | | | | |

## 需要关注 / 下一步
- <最该先处理的 1-3 件事,按影响排序>

## 附:失败文件清单(可选)
| 文件 | 原因分类 | 备注 |
| --- | --- | --- |
<文件名若含个人信息须脱敏;见铁律>
```

## 执行步骤
1. **定位数据** —— 读 `kb_admin/state_store.py`,拿到数据库真实路径、表名、字段名。
2. **圈定批次** —— 按"开工前"确认的范围,SELECT 出这批文件的记录(状态、文件名、错误信息、时间戳)。
3. **统计指标** —— 按状态分组计数,算成功率;用时间戳算本批耗时。
4. **归类失败** —— 对每条失败/卡死记录,按"失败归因对照表"匹配错误信息,归到对应分类并计数、算占比。
5. **提炼结论与建议** —— 写一句话结论;挑影响最大的问题给出下一步动作。
6. **渲染报告** —— 按模板生成 Markdown,写到输出位置(不覆盖旧报告)。
7. **自检** —— 过一遍下方"自检清单",再把报告路径告诉用户。

## 失败归因对照表(匹配错误信息里的关键词)
| 命中关键词 / 特征 | 归类 | 人话说明 | 建议动作 |
| --- | --- | --- | --- |
| `count_document_chunks` | 索引同步报错 | 文件处理完了但写入检索库那步报错,导致整条没完成 | 已知阻塞项,优先修这个方法 |
| `8192` / `maximum context` / `token` | embedding 超长 | 单块文本超过模型 8192 token 上限 | 在 embedding 层分窗兜底,不改切分 |
| `timeout` / `超时` | 重文件 OCR 超时 | 大文件 OCR 太慢被超时中断 | 看 OCR 提速(多变体/线程);放宽重文件判定 |
| `BrokenProcessPool` / `broken` | 进程池崩溃 | 子进程异常把进程池搞崩了 | 查当时内存/异常文件;看是否脏数据触发 |
| 文件名以 `~$` 开头 / `Thumbs.db` / `.lnk` / `.tmp` | 无效文件 | 系统临时/快捷方式文件,本不该进链 | 入口加过滤,别让它们入队 |
| OCR 初始化报错 | OCR 启动失败 | OCR 引擎没起来 | 查模型缓存、mkldnn 是否误开 |
| 其它 / 无法匹配 | 未归类 | 需人工看一眼 | 附原始错误摘要(脱敏) |

## 铁律(任何时候不得违反)
- **只读**:只做 SELECT 和读文件;绝不写库、改库、删库、删中间产物、改任何代码。
- **不跑 worker**:不执行入库、不启动后台进程,只静态读取已有结果。
- **PII 保护**:报告面向领导,**不得包含客户个人信息**。文件名若含人名/证件/保单号等,统计时正常用,但**在报告里脱敏**(如 `客户A_投保单.pdf` → `***_投保单.pdf`);错误信息里的个人数据要去除,只保留技术原因。
- **不臆造数字**:所有数值都来自真实查询;查不到就如实写"无数据",不编。
- 报告默认存 `reports/`,**不自动提交进仓库**(可能含敏感信息,由用户决定)。

## 自检清单(交付前过一遍)
- [ ] 批次范围、生成时间已写明
- [ ] 核心指标数值与分类计数能对上(各状态之和 = 总数)
- [ ] 每类失败都有数量、占比、人话说明、建议动作
- [ ] 文件名/错误信息已脱敏,无个人信息外泄
- [ ] 全程只读,未改任何代码或数据
- [ ] 报告路径已告知用户
