K5：jp-poc 的切片编号换成 Azure 里的 ￼

**为什么要做：**T1 导入后，Neo4j 里 jp-poc 的切片编号是 POC 图谱那一套（按内容算的 SHA256）。问答拿着这些编号去 jp-poc 取原文，会取不到。K5 把编号换成 jp-poc 索引里的真实编号。

怎么对上：两边的编号都是从同一段切片内容算出来的。所以从 jp-poc 只读取出每个切片的编号和内容，按 POC 图谱的算法重新算一遍，就能得到一张”POC 编号 → Azure 编号”的对照表。

前提：T1 已经写入成功；K2b 已经完成（`.env` 里配好了 jp 的搜索地址和查询密钥）。

## K5 的验收方法 ￼

1. 先预演：

```powershell
uv run python scripts/kg_remap_poc_chunks.py

```

把 5 类的数量发我（不要发样例编号以外的内容）。

我主要看”唯一匹配 + 多候选可确定”占全部的比例：

- 大部分都能匹配上：说明两边的内容一致，可以写入

- 大部分找不到：说明 POC 建图谱时用的内容，和写进 Azure 的内容不一样（比如写入 Azure 前加过标题）。这时不要写入，我们再调整算法

2. 我确认以后，再写入：

```powershell
uv run python scripts/kg_remap_poc_chunks.py --write

```

3. 写入后核对：

- 打印出的”写入前 / 写入后各 scope 节点数”里，hk 那几行完全一样

- 在 Neo4j Browser 运行（只读）：

```cypher
MATCH (c:Chunk {scope: 'jp-poc'}) RETURN c.remap_status AS status, count(*) AS cnt

```

‎`status` 为空（‎`null`）的就是已经换好编号的，数量应该等于预演里”可以写入”的数量

**4. 问答能顺着图谱取到原文了。**用 K2b 验收第 4 步的方法，以 ‎`saas_id: "jp"` 提一个和某个实体有关的问题。回答里的引用变多了，或者日志里出现 ‎`[AISearch] 取回结果 ... found=` 后面的数字不再是 0，就说明成功了。
