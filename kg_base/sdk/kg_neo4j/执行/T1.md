【要做的 6 件事】

1. 脚本参数（用 argparse）：
   --kg-db（默认 C:/Users/234393/Desktop/kg_api/data/kg.db）
   --csv（默认按开工前确认第 2 条找到的路径；文件不存在时不报错，只是没有内容摘要）
   --write：不加时只预演，不连接 Neo4j 以外的任何服务；加了才真正写入
   --wipe：只能和 --write 一起用。写入前删除 scope 为 jp-poc 的全部节点
   scope 写死为常量 SCOPE = "jp-poc"，不提供修改 scope 的参数

2. 安全规则（每一条都要做到，并在代码里用中文注释说明）
   - 所有 Cypher 都用 $scope 参数，并且由同一个函数执行。这个函数开头检查：参数里的 scope 必须等于 "jp-poc"，否则抛出异常
   - 只用 MERGE / SET / DETACH DELETE 操作 scope 为 jp-poc 的节点。不得创建或删除任何约束、索引，不得执行不带 scope 条件的语句
   - --wipe 分批删除：MATCH (n {scope: $scope}) WITH n LIMIT 1000 DETACH DELETE n RETURN count(*) AS deleted，循环直到删除数为 0
   - kg.db 用只读方式打开（file:...?mode=ro）
   - Neo4j 的地址、用户名、密码、数据库名从 KnowledgeSettings 读取，不得写在代码里，不得打印密码

3. 预演（不加 --write 时）只读 kg.db 和 csv，打印：
   - 节点数：按类型分别统计
   - 关系数：按 kg.db 里的原始关系名分别统计，并标出每一种会对应成哪个标准关系
   - 能找到内容摘要的切片数 / 切片总数
   - 会生成的文档数
   - 最后打印一行："预演结束，未写入任何数据。确认无误后加 --write 运行"

4. 写入（加 --write 时）。每批 500 条，用 UNWIND 写入，属性名与 SDK 保持一致（以开工前确认第 4 条为准）：
   - Entity：MERGE (e:Entity {scope: $scope, id: 原编号})，SET type、label、label_norm（用 SDK 的 normalize_label 计算）、origin = "poc_import"、created_at、updated_at（毫秒时间戳，整次导入用同一个值）
   - Document：按来源文件生成，document_id = "doc::" + 来源文件名的 sha256 前 16 位；SET filename、origin、时间
   - Chunk：MERGE (c:Chunk {scope: $scope, chunk_id: 原编号})，SET document_id、source_file、page_or_sheet、preview（正文前 200 个字符，没有就不写）、origin、时间
   - (Document)-[:HAS_CHUNK]->(Chunk)；kg.db 中的 mentioned_in 写成 (Entity)-[:MENTIONED_IN]->(Chunk)
   - 实体之间的关系，按下面的对照表写成标准关系；对不上的写成 RELATED_TO。每条关系都 SET r.raw_types = [原始关系名]、r.source = "poc"、r.weight = 1、时间
       包含 → CONTAINS；属于 → PART_OF；使用 → USES；依赖 → REQUIRES；前置步骤 → NEXT；
       执行 → HANDLED_BY（起点和终点交换）；
       原始名已经是 CONTAINS / PART_OF / USES / REQUIRES / NEXT / HANDLED_BY 的保持不变
     对照表写成文件顶部的一个字典常量 RELATION_MAP，并用中文注释说明"以后要调整对应关系，只改这里"
   - 关系类型不能拼接进 Cypher：按标准关系名分组，每组用一条写死关系类型的固定语句写入（7 条固定语句，分别对应 6 种标准关系和 RELATED_TO）
   - 写入前后各打印一次所有 scope 的节点数（MATCH (n) RETURN n.scope, count(*)），方便核对其他 scope 没有变化。这是唯一一条不带 scope 条件的语句，只读，单独写成一个函数，并在注释中说明

5. 结束时打印：写入的节点数、关系数（按标准关系分别统计）、对应成 RELATED_TO 的关系中出现最多的 20 种原始关系名及次数

6. 测试（不连接 Neo4j，用假 driver 记录收到的语句和参数；kg.db 用测试中临时创建的小 SQLite 文件）
   a. 关系对照：每种对照都对；"执行"会交换起点和终点；对不上的变成 RELATED_TO，原始名保留在 raw_types
   b. 执行语句的函数收到 scope 不是 "jp-poc" 时抛出异常
   c. 除了"统计所有 scope"那一个函数以外，假 driver 收到的每条语句都包含 $scope，参数里的 scope 都是 "jp-poc"
   d. 任何一条语句都不包含 CREATE CONSTRAINT、CREATE INDEX、DROP
   e. 不加 --write 时，假 driver 一条语句都没有收到
   f. document_id 的计算：同一个文件名两次结果相同，不同文件名结果不同
