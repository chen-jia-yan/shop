【通用规则】
一、工作方式
- 先做《开工前确认》（只读），贴出原始输出；等我回复"继续"后才能修改
- 只改本提示词列出的文件。需要改其他文件时，先停下来说明原因，等我同意
- 能新建文件就不要往已有文件里插入大段代码；已有文件只做最小改动
- 每改完一个文件，立即贴出 git diff --stat <文件> 和 git diff -w --stat <文件>。两者行数不一致时停下来
- 已有的类名、函数名、变量名一律不得改名。本提示词明确要求的除外

二、字符与编码
- 代码里的类名、函数名、变量名、缩进、运算符、括号、冒号只能用英文半角字符。中文只能出现在注释和字符串里
- 禁止出现零宽字符、不换行空格、全角空格、Tab 缩进
- 所有文件用 UTF-8（不带 BOM）保存。禁止用 PowerShell 的 >、>>、Out-File、Set-Content 写文件，只能用编辑工具改文件

三、禁止事项
- 不读取任何 .env 文件（.env.example 可以读）
- 不连接 Azure、Neo4j、MySQL、Redis、大模型。测试一律用手写的假实现
- git 只允许 status / diff / log / show / grep / ls-files。不得运行 add / commit / restore / checkout / reset / stash / clean / pull / push / merge
- 不得新增 # type: ignore、# noqa、pytest.skip、xfail、cast(Any, ...)。
  唯一例外：导入 tap_ingest_sdk 的那几行，照抄仓库已有的 # type: ignore[import-untyped] 写法
- 不修改 pyproject.toml、uv.lock，以及 ruff / mypy / pytest 的配置
- 测试和检查一律用 uv run，不用 python -m

四、安全规则
- 所有写入、删除 Neo4j 的 Cypher 必须带 scope 条件，并且 scope 用参数传入，不能拼接字符串
- 关系类型、实体类型不能拼接进 Cypher 字符串：先按统一名单校验，再作为参数传入（如 type(r) IN $types）
- 任何写入或删除 Azure 索引的代码，执行前必须检查"禁止写入的索引名单"（K2b 加入，默认包含 jp-poc）
