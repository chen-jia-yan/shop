# 五、最终结论
1. SDK 的 `LLMRelationExtractor` 不是自由落图：实体类型有固定归一列表，关系类型必须过 `LLM_RELATION_MAP + ALLOWED_RELATIONS`，未映射关系直接丢弃。
2. SDK 当前业务关系白名单实际是 6 类：`NEXT / HANDLED_BY / PART_OF / CONTAINS / USES / REQUIRES`。
3. `DefaultRelationExtractor` 依赖流程图结构和 `tap_ingest_sdk.lexicon` 词典，不是开放式实体抽取器，所以普通文档可能抽不到关系端点。

5. SDK 实体按 `(scope, id)` 合并；词典概念可跨语言合并，非词典实体通常按 `type + label` 合并。
6. POC 和 SDK 的 8 类基础实体类型一致，但 SDK 额外扩了 `Stage / Step / Action`。
7. POC 的关系类型比 SDK 宽很多；SDK 当前明显缺少大量 POC 语义关系，以及结构边 `related_chunk`。
8. 如果 SDK 新增关系类型，后端问答链路最少要同步改 `settings.py`、`tools.py`、`prompts.py` 这 3 处。

```python
_Q_EXACT = (
    "CYPHER 25 MATCH (e:Entity {scope: $scope}) "
    "WHERE e.label_norm = $norm "
    "RETURN e.id AS id, e.type AS type, e.label AS label, 1.0 AS score LIMIT $limit"
)

_Q_FULLTEXT = (
    "CYPHER 25 MATCH (e:Entity) "
    "SEARCH e IN (FULLTEXT INDEX entity_label_ft FOR $q LIMIT $k) SCORE AS score "
    "WITH e, score WHERE e.scope = $scope "
    "RETURN e.id AS id, e.type AS type, e.label AS label, score "
    "ORDER BY score DESC LIMIT $limit"
)

_Q_VECTOR = (
    "CYPHER 25 MATCH (e:Entity) "
    "SEARCH e IN (VECTOR INDEX entity_embedding FOR $vec "
    "WHERE e.scope = $scope LIMIT $limit) SCORE AS score "
    "WITH e, score WHERE score >= $min "
    "RETURN e.id AS id, e.type AS type, e.label AS label, score"
)

_Q_SUBGRAPH = (
    "CYPHER 25 MATCH (s:Entity {scope: $scope}) WHERE s.id IN $ids "
    "MATCH p = (s)-[*1..{hops}]-(n:Entity {scope: $scope}) "
    "WHERE ALL(r IN relationships(p) WHERE type(r) IN $business_types "
    "AND ($rel_types IS NULL OR type(r) IN $rel_types)) "
    "AND ($node_types IS NULL OR n.type IN $node_types) "
    "WITH p LIMIT $max_paths "
    "UNWIND relationships(p) AS r WITH DISTINCT r "
    "ORDER BY coalesce(r.weight, 1) DESC LIMIT $max_edges "
    "RETURN startNode(r).id AS source, startNode(r).label AS source_label, "
    "type(r) AS type, endNode(r).id AS target, endNode(r).label AS target_label"
)

_Q_CHUNKS = (
    "CYPHER 25 MATCH (:Entity {scope: $scope, id: $id})-[:MENTIONED_IN]->"
    "(c:Chunk {scope: $scope}) RETURN c.chunk_id AS chunk_id LIMIT $limit"
)
```

# 9. 如果 SDK 新增关系类型，后端问答链路要改哪些地方
## 9.1 必改项
1. 后端配置白名单 文件 `src\tap_ai\plugins\extensions\knowledge\settings.py`
```python
kg_relation_types: tuple[str, ...] = ("NEXT", "HANDLED_BY", "PART_OF", "REQUIRES")
```
- 这里要把新关系加进去，否则 Neo4jKnowledgeGraph 根本不会遍历它。

2. 工具 schema 枚举 文件 `src\tap_ai\plugins\extensions\knowledge\tools.py`
```python
"relation_types": {
    "type": "array",
    "items": {
        "type": "string",
        "enum": ["NEXT", "HANDLED_BY", "PART_OF", "REQUIRES"],
    },
},
```
- 这里不改，LLM/前端工具层就没法显式指定新关系。

3. 关系说明文案 文件 `src\tap_ai\plugins\extensions\knowledge\prompts.py`
```python
RELATION_LEGEND = "(关系说明: NEXT=流程下一步，HANDLED_BY=由该角色负责，PART_OF=所属阶段，REQUIRES=需要的材料/条件)"
```
- 这里不改，用户看到的解释会不完整。

## 9.2 可能要改的项
4. 默认关系白名单常量 文件 `src\tap_ai\plugins\extensions\knowledge\backends\neo4j_graph.py`
```python
DEFAULT_RELATION_TYPES = ("NEXT", "HANDLED_BY", "PART_OF", "REQUIRES")
```
- 如果你想让“默认配置”就包含新关系，这里也要同步。

5. 测试用例
- `tests\unit\test_react_graph.py`、相关知识库/图谱测试里如果对关系枚举有断言，也要跟着改。

## 9.3 不一定要改的项
- `service.py`、`plugin.py` 主流程一般不用动，它们只是透传 relation_types
- Neo4j 查询 Cypher 也不用改，`type(r) IN $business_types` 本来就是动态列表

> 结论
> 后端问答链路最关键要改 3 处：
> i. settings.py 的 kg_relation_types
> ii. tools.py 的 relation_types.enum
> iii. prompts.py 的 RELATION_LEGEND
