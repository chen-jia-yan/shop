## 改动 ②：服务端强制审批策略 + 删除唯一校验（安全红线）

### ②-1 单一权威的审批策略函数
- 在 kb_admin_actions.py 定义唯一判定函数，作为是否需要人工的唯一真相来源：
```
DESTRUCTIVE = {"delete_document", "retry_failed"}
WRITE = {"add_files", "scan_folder", "reindex"}

def requires_approval(action: str) -> bool:
    # 破坏性动作恒需人工，无视模型给的 needs_human
    return action in DESTRUCTIVE
```
- 在调度处（handle_admin_request / approve 执行前）：**忽略模型输出里的 needs_human**，一律以 requires_approval(action) 为准。DESTRUCTIVE 动作在未经 approve 时绝不执行，只能写成 ops_recommendations 的 proposed。
- 白名单外的 action 一律拒绝执行。

### ②-2 删除前服务端唯一定位校验
- 在真正执行 delete_document(doc_id) 之前，服务端强制校验目标唯一、且确实存在：
```
def resolve_delete_target(db, doc_id=None, name_pattern=None):
    rows = find_documents(db, doc_id=doc_id, name_pattern=name_pattern)
    if len(rows) == 0:
        raise ValueError("未找到匹配文档，拒绝删除")
    if len(rows) > 1:
        raise ValueError(f"匹配到 {len(rows)} 个文档，目标不唯一，拒绝删除")
    return rows[0]["doc_id"]
```
- 删除只接受**精确 doc_id**；若来自模型的是模糊名称，必须先 resolve 到唯一 doc_id 才能进入审批，匹配到 0 个或多个一律拒绝并要求人工澄清。绝不基于模糊匹配直接删。

## 改动 ③：/nl-command 加 feature flag（默认关）
- 增加配置项 ENABLE_NL_COMMAND，默认 False（从环境变量或配置读）。
- /api/admin/nl-command 入口第一行检查：若未开启，直接返回 403 + 提示“管理台未启用”。

## 改动 ④：收紧 add_files / scan_folder 的输入边界
- **不再整文件 read_bytes**：入队只记录文件路径，真正读取放到 worker 处理时。若需要算哈希，用分块流式，不把整文件读进内存：
```
import hashlib
def file_hash(path, chunk=1 << 20):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for blk in iter(lambda: f.read(chunk), b""):
            h.update(blk)
    return h.hexdigest()
```
- 加入队边界（超限则拒绝并返回清晰错误，不静默截断）：
  - 允许的后缀白名单：如 {.pptx, .xlsx, .pdf, .md, .docx}
  - 单次最多文件数：如 200
  - 单文件最大大小、单批总大小上限：如 100MB / 2GB
- scan_folder 限定在**白名单根目录**下，拒绝该目录之外的路径（用 os.path.realpath 归一化后校验前缀，防目录穿越）。

## 交叉约束与验收
- 任何 DESTRUCTIVE 动作：未 approve 前绝不执行；approve 后才通过 execute_admin_action 生效。模型把 delete 的 needs_human 设成 false 也无效。
- 删除模糊匹配到 0 或多个 → 拒绝并提示人工，不删。
- ENABLE_NL_COMMAND=False 时 /nl-command 返回 403。
- add_files 不再把整文件读进内存；超后缀/数量/大小/目录范围的入队被拒绝并有明确报错。
