# 任务:修复 Windows 上"venv 启动后跳回 base Python + 导入旧 venv"的启动链问题

## 已确认根因
Windows 上,worker 启动子进程时解释器重落地到 base(Python312),而非当前 venv(.venv-clean312);进程树表现为 venv → base 的同一脚本/模块反复重启。同时子进程 import 时用到了旧环境 .venv312 的 paddleocr/paddle,说明有环境变量(VIRTUAL_ENV / PYTHONPATH / PATH)残留指向旧 venv。与依赖版本、模块入口、supervisor 均无关。

## 请修复

### 1. 所有子进程启动都用 venv 的真实解释器路径
- 不要用 `sys.executable`(在 Windows venv 下可能是重定向到 base 的 stub)。
- 统一用:`venv_py = os.path.join(sys.prefix, "Scripts", "python.exe")`,作为所有 `subprocess.Popen/run` 的解释器,以及 `multiprocessing.set_executable(venv_py)`。
- 检查 run_worker.py 是否存在"自我 re-launch/自举"逻辑(自己又启动一遍自己);若非必要,移除;若必要,必须用 venv_py 且只启动一层。

### 2. 给所有子进程传入干净、指向新 venv 的环境
- 启动子进程时显式传 env(基于 os.environ 复制后覆盖):
  - `VIRTUAL_ENV = sys.prefix`
  - `PATH = os.path.join(sys.prefix, "Scripts") + os.pathsep + 原PATH`,并从 PATH 中移除任何包含旧 `.venv312` 的条目
  - 删除 `PYTHONHOME`;确保 `PYTHONPATH` 不包含 `.venv312`(如含则移除)
- 目标:子进程的 sys.path / site-packages 只解析到 .venv-clean312,绝不指向 .venv312。

### 3. 启动期自检日志
- worker 及每个子进程启动时打印:`sys.executable`、`sys.prefix`、`sys.base_prefix`、`VIRTUAL_ENV`、以及实际 import 到的 paddleocr 路径(`paddleocr.__file__`),用于确认全部指向 .venv-clean312。

## 约束
- 只用标准库;不删除 PaddleOCR 模型缓存;不改动批处理主逻辑,只修启动链与环境传递。

## 验收标准
- 进程树中所有 python 进程(worker + process_one_file + 池子进程)都是 `.venv-clean312\Scripts\python.exe`,**无任何 Python312\python.exe**。
- 自检日志显示各进程 `sys.prefix` 与 `paddleocr.__file__` 均在 .venv-clean312 下,不再出现 .venv312。
