## 5. 结论

| 链路 | 检索器类型 | 底层 store | RRF是否上路 |
| ---- | ---- | ---- | ---- |
| 评估（Answerer.search()） | HybridRetriever | AzureSearchStore (Azure AI Search jp-poc ) | ✅ 是（同一类、同一store） |
| 生产（RetrievalSkillRuntime.search_kb()） | HybridRetriever | AzureSearchStore (Azure AI Search jp-poc ) | ✅ 是（同一类、同一store） |

一句话：评估和生产用的是同一套 HybridRetriever，连同一个 Azure AI Search 索引 jp-poc，都走了 BM25 + 向量混合检索 + HeuristicReranker。之前报告说「评估用 BM25Retriever」是我被名字误导。
BM25Retriever 就是 HybridRetriever 的别名。RRF 的开关（`RRF_ENABLED`）作用在 `HybridRetriever.search()` 内部，两条链路都经过它，所以 RRF 的改动对两边都生效。

两个链路的 retriever 是不同实例（各自 new 了一个 Answerer），但因为都指向同一个 Azure Search 索引，检索行为一致。

## 详细说明
- 从定义上看，QlikSense 是一种 BI (Business Intelligence) 工具，核心用途是收集和分析大量数据，并帮助使用者通过自主取数、加工和探索来支持业务决策。[1]
- 知识库中还列出了几个与 QlikSense 直接相关的基础术语：
  - **QVD**: Qlik Sense / QlikView 导出的数据文件，是为快速加载优化的原生格式；
  - **QVF**: 包含加载脚本的文件，用于把数据源数据接入 Qlik Sense，并生成 QVD；
  - **Hub**: 访问应用、空间、集合的入口；

在新契约相关系统资料中，QlikSense 被归类为“通过 QlikSense 提供数据”的一种帐票/数据提供方式。文档说明它可以从 DB、CSV 等来源获取数据，并按日次等周期生成帐票或数据集市，供业务部门使用。[4]
