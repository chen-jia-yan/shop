# 1. Excel 的切分實現
## 1.1 誰把整張 sheet 作為一個 segment?
`kb_poc/parsing/excel_parser.py:45-49, 74-76, 181-198` — `parse_excel_file()` 對每個 worksheet 生成一個 `ParsedSegment`：
```python
# :45-49
def parse_excel_file(...) -> ParsedDocument:
    """按 worksheet 解析 Excel，每个 worksheet 产出一个 segment。"""

# :74-76
for worksheet in workbook.worksheets:
    locator = worksheet.title
```
一個 sheet = 一個 segment，`locator = worksheet.title`（如 "Sheet1"）。

## 1.2 誰把 segment 細切成 cell-level chunk?
`kb_poc/ingestion/ingestor.py:230-242` — `_chunk_document()` 對 `content_type != "ppt"/"diagram"/"flowchart"` 的 segment 調用 `_split_text()`：
```python
# :230-242
if content_type in {"ppt", "diagram", "flowchart"}:
    parts = [raw_text] if raw_text else []
else:
    parts = _split_text(segment.text, chunk_size=chunk_size, overlap=overlap)
```
`_split_text()` (:285-315) 按行累積切分，到 `chunk_size` 時截斷，末尾 `overlap` 行帶入下一塊。粒度是「按行 → 按字數」，不是按 cell。

每個單元格在 `_parse_worksheet_cells()` (:257-298) 中已生成對應 `StructuredBlock`（cell block + row block），帶精確 `cell_range`（如 "Sheet1!A3"），但這些 block 在上層 segment 構建時僅用於生成 text 文本行，block 級別的 `cell_range` 在拼接後丟失了。最終 chunk 的 `cell_range` 來自 segment 級別（ingestor.py:258），而 Excel segment 的 `cell_range` 是 None（excel_parser.py 未設 `cell_range=...`）。

## 1.3 表頭有沒有被識別或單獨保存?
沒有。
- `_parse_worksheet_cells()` (:257-298) 從 row=1 開始 iterate，所有行無差別處理
- 合併單元格：整個 excel_parser.py 中無 `merged_cell` / `merge_cells` 相關邏輯
- `table_headers` 來自 `semantic_extraction`（excel_parser.py:176），但 `_parse_worksheet_cells` 產生的 block 從不設 `table_cells`，所以 Excel parser 的 `table_headers` 總是空列表

## 2.2 字段確認
| 字段 | 值 | 說明 |
| ---- | ---- | ---- |
| chunk_id | sha1 前12位 hex | ingestor.py:244 — `sha1(f"{source_file}:{segment.locator}:{part}")[:12]` |
| source_file | 文件名 | 有值，filterable |
| page_or_sheet | Sheet1 / slide-N | 有值，filterable |
| cell_range | 空 | Excel chunk 沒有 cell_range。segment 級別未設（excel_parser.py），ingestor.py:258 複製 segment.cell_range → None |
| part | 無獨立字段 | 不存為 metadata 字段。chunk 順序靠 jsonl 行序 → Azure 索引中的 chunk_id 字母序（sha1 含 part 文本前綴，部分可排序） |

## 2.3 同一張 sheet 的 chunk 能否按順序拼回原表？
不能精確還原。
- 排序：chunk 在 jsonl 中按寫入順序排列，`chunk_id` 含 `sha1(source_file:locator:part)`，但 part 是文本片段而非行號，無法用以還原目標行號
- `cell_range` 為空，無法定位每個 chunk 對應到表格的哪些行列
- 目前只能靠 `page_or_sheet` 過濾到整張 sheet，但 sheet 內無法細分定位

# 4. 檢索鏈路
## 4.1 Agent 調用「檢索知識庫」的入口函數
調用鏈：
```
AgentOrchestrator.run_chat_turn()
→ agent.runtime.run_tool("search_kb", arguments)    # orchestrator.py:284
→ ToolDispatcher.dispatch("search_kb", payload)      # tool_registry.py:167
→ RetrievalSkillRuntime.search_kb()                 # skills/kb_retrieval/runtime.py:81
→ answerer.retriever.search(query, top_k, ...)      # runtime.py:113
→ HybridRetriever.search()                          # retrieval/retriever.py:73
```

## 4.2 top-K 在哪行返回 / context 在哪行組裝?
top-K：三層預設
1. 環境變量 `KB_TOP_K` → `config.py:166`（預設 5）
2. Skill 入口 `top_k: int = 5`（`kb_retrieval/runtime.py:85`）
3. `RetrievalConfig.top_k = 5`（`retriever.py:37`）

context 組裝：`search_kb()` 返回 results（content + metadata）後，由 LLM 自行組裝 context。`prompt_builder.py:25-35` 將檢索策略注入 system prompt，但實際組裝來自 LLM 的 tool call 應。

context 長度上限：`retriever.py` 中無硬性截斷。`_split_text()` 的 `chunk_size` 由 `_chunk_profile()` 決定（不同 `content_type` 不同值），但檢索返回的 top_k 條結果的總長度沒有統一上限。需注意：embedding 層單條上限 8192 token（`clamp_embedding_text()`）。

## 4.3 LLM 鏈路和 Agent 鏈路是不是同一個檢索函數?
是，完全共用。
- `retriever.py:473`：`BM25Retriever = HybridRetriever` — 只有一個檢索類
- Agent 路徑：`RetrievalSkillRuntime.search_kb()` → `answerer.retriever.search()`（`kb_retrieval/runtime.py:113`）
- LLM 直連（LocalAnswerer）：`Answerer.search()` → `retriever.search()`（`qa/answerer.py:51-56`）
- 兩者最終都調 `HybridRetriever.search()`（`retriever.py:73-79`）

## 5.2 關鍵觀察
- PPT 不細切（`ingestor.py:234-236`）：`content_type in {"ppt", "diagram", "flowchart"}` → 整頁作為一個 chunk，不調 `_split_text()`
- OCR 文字含空間佈局：圖像文字以區塊形式嵌入（OCR 區塊 + 閱讀順序 + 空間重建），保留了位置信息
- `flowchart_nodes` / `flowchart_edges` 為空：PPT 的 segment 未設置 `flowchart`（僅 `segment.flowchart` 結構來自特定解析器），所以 metadata 中這些字段為空列表
- 內容靠 `page_or_sheet: slide-1` 定位到頁級，頁內無法細分定位

# 總結：要實現「回填所在表格區域」的關鍵缺口
1. `cell_range` 缺失 — Excel chunk 沒有 `cell_range`，無法定位到具體行列
2. 表頭未識別 — 沒有 header 標記，無法區分表頭行與數據行
3. chunk 內無行號排序字段 — 無法按原始表格順序拼接回完整表
4. 合併單元格無處理 — 跨列跨行合併數據可能丟失或重複
