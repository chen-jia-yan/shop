【第二步要做的】
一、application/library_eval.py：EvalService
构造参数：settings、eval_repo、prompt_library、model_gateway、qa_port: QaAnswerPort | None、now_ms: Callable[[], int]（默认取当前毫秒时间戳，测试时可以替换）

1. 评估集
   - import_gold_set(req) -> GoldSetData：seq 从 1 开始按导入顺序编号；question_count = 题目数
   - list_gold_sets(req)、list_questions(req)：评估集不存在时报"评估集不存在"
2. 发起评估 start_run(req) -> EvalRunStartData，按顺序校验：
   a. qa_port 为 None → "问答服务未配置"
   b. settings.library_eval_judge_model 为空 → "判官模型未配置"
   c. 评估集不存在 → "评估集不存在"
   d. 评估集没有题目 → "评估集没有题目"
   通过后：
   - top_k = req.top_k，为 None 时用 settings.library_eval_default_top_k
   - 写入 run：status=queued、total=题目数、done=0、failed_count=0、parse_error_count=0、judge_model、judge_version=JUDGE_VERSION、cancel_requested=0
   - 同一事务里为每道题写一条 item：status=pending，并复制题目的 question、ideal_answer、expected_source（快照，以后评估集变了也不影响这次结果）
   - 用 asyncio.create_task 在后台执行 execute_run(run_id)；任务对象存进 self._tasks（一个 set），完成后用 add_done_callback 移除（防止被垃圾回收）
   - 返回 run_id 和 status="queued"
3. 执行 execute_run(run_id)（后台任务调用的就是它；测试直接 await 它）
   a. run 改为 running，写 started_time、heartbeat_time
   b. 另起一个心跳任务：每 30 秒调用一次 touch_heartbeat，直到 execute_run 结束（在 finally 里取消）
   c. 取出全部 pending 的 item 放进队列；启动 min(library_eval_max_concurrency, 题目数) 个 worker 并发处理
   d. 每个 worker 循环：
      - 先从数据库重新读取 run，cancel_requested 为真就退出，不再领新题
      - 从队列领一道题；队列空了就退出
      - 处理这道题（见 e）
   e. 处理一道题：
      - 记录开始时间
      - qa = await asyncio.wait_for(qa_port.answer(question=..., mode=run.answer_mode, top_k=run.top_k), timeout=library_eval_item_timeout_sec)
      - 从题目对应的评估集题目里取 key_points
      - judge_result, usage = await judge_answer(...)，判官看到的证据必须就是 qa.evidence，不能另外检索
      - category = classify(...)
      - complete_item：answer、evidence（qa.evidence 序列化）、scores（parse_error 时为 None）、category、parse_error、judge_raw、latency_ms、token_usage、status=done
      - increment_progress(done_delta=1, parse_error_delta=1 或 0, heartbeat_time=now)
      - 出现任何 Exception（包括超时）：fail_item(error=f"{异常类名}: {异常信息}"，最多 2000 字)，increment_progress(done_delta=1, failed_delta=1)，然后继续下一题
      - asyncio.CancelledError 不能被捕获吞掉，必须继续往外抛
   f. 全部 worker 结束后，重新读取 run：
      - cancel_requested 为真 → status=cancelled（没处理的题保持 pending）
      - failed_count == total → status=failed，error="全部题目执行失败"
      - 其他 → status=succeeded
      - summary = compute_summary(该任务全部 item)，写 finished_time
   g. 在 a–f 之外出现意外异常 → status=failed，error 记录异常（最多 2000 字），finished_time
   h. 收到 asyncio.CancelledError（服务关闭）→ status=interrupted，error="服务关闭"，finished_time，然后重新抛出
4. 取消 cancel_run(req) -> EvalRunData
   - 不存在 → "评估任务不存在"
   - status 是 succeeded / failed / cancelled / interrupted → "评估任务已结束，无法取消"
   - 否则 request_cancel，返回最新的 run
5. 查询：get_run、list_runs、list_items、get_item、get_analysis（由该任务全部 item 调用 build_analysis 现算）；找不到时分别报"评估任务不存在""评估题目不存在"
6. 中断恢复 recover_stale_runs()：older_than_ms = now - library_eval_heartbeat_timeout_sec × 1000；
   find_stale_runs 找到的每个任务改为 interrupted，error="服务重启或实例中断"，写 finished_time
7. 关闭 shutdown()：取消 self._tasks 里的全部任务，并用 asyncio.gather(..., return_exceptions=True) 等它们结束
