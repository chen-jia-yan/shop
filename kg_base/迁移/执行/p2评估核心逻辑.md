3. core/library_eval/judge.py
   - JUDGE_VERSION = "v2.1"
   - 证据格式化：
     · 原文证据，每条一段：第一行 "[序号] 来源：{source_file} / {page_or_sheet} / chunk_id={chunk_id}"，第二行起是 content
     · 推断证据，每条一段：第一行 "[序号] 类型：图谱事实"（kind 为 kg_fact）或 "[序号] 类型：推断"（kind 为 derived），第二行起是 content
     · 序号从 1 开始，原文证据和推断证据各自编号；段与段之间空一行
     · 字段为空时显示"（未知）"；单条 content 超过 4000 字时截断，末尾加"……（已截断）"
     · 没有原文证据时填"（无）"；没有推断证据时也填"（无）"。不能填空字符串（旧代码把推断证据写死成空字符串，这是这次要修的 bug）
   - key_points 有值时，逐条编号填入（"1. xxx" 每行一条）；为 None 或空列表时，填旧代码在这种情况下填的内容
   - build_judge_messages(prompt_library, *, question, ideal_answer, answer, evidence, key_points) -> list[dict[str, str]]
     消息的角色和顺序与旧代码一致
   - parse_judge_output(text) -> JudgeResult
     JudgeResult：scores: dict[str, DimScore] | None、parse_error: bool、raw: str；DimScore：score: int、reason: str
     · 兼容：纯 JSON；被 ```json ... ``` 包裹；JSON 前后有其他文字。取第一个完整的 JSON 对象（逐字符配对大括号，并正确跳过字符串里的括号；不能用贪婪正则）
     · 用第 4c 步的键名读取四个维度，转换成总纲 K 节的统一名称
     · 分数必须是 1–5 的整数：整数 4 可以；字符串 "4" 可以转换；4.5、0、6、"四"、null 都算失败。reason 必须是字符串
     · 任何一项不满足：parse_error=True，scores=None，raw 保留原文。绝不抛异常
   - async def judge_answer(gateway, prompt_library, *, model, question, ideal_answer, qa: QaResult, key_points) -> tuple[JudgeResult, dict | None]
     依次调用 build_judge_messages → complete_text(temperature=0.0) → parse_judge_output，返回 (判官结果, usage)
