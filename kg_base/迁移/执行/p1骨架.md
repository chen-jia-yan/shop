   a. persistence/library_draft_repo.py
      - add(draft) -> 返回新建的记录
      - get(draft_id) -> 记录或 None（已软删除的视为不存在）
      - list_page(租户字段, file_id, status, page, page_size) -> (列表, total)，按 create_time 倒序
      - update_chunks(draft_id, chunks, base_status="draft", update_time)
      - transition_status(draft_id, from_statuses: list[str], to_status: str, **其他要更新的列) -> bool
        必须是一条带条件的 UPDATE（WHERE id = :id AND status IN (:from_statuses) AND deleted = 0），返回是否真的更新了 1 行。用于防止重复提交
      - soft_delete(draft_id, delete_time)
   b. persistence/library_eval_repo.py
      - 评估集：add_gold_set(gold_set, questions)（同一个事务里写入评估集和全部题目）、get_gold_set、list_gold_sets、
        list_questions(set_id, page, page_size)（按 seq 排序）、list_all_questions(set_id)（不分页，按 seq 排序）
      - 评估任务：add_run(run, items)（同一个事务里写入任务和全部题目 item，item.status=pending）、get_run、
        list_runs(租户字段, status, page, page_size)（按 create_time 倒序）、
        update_run(run_id, **要更新的列)、request_cancel(run_id)、touch_heartbeat(run_id, heartbeat_time)、
        increment_progress(run_id, *, done_delta, failed_delta, parse_error_delta, heartbeat_time)
        —— 必须是一条 UPDATE ... SET done = done + :done_delta, failed_count = failed_count + :failed_delta ... 的原子更新，不能先读再写
      - 评估题目：get_item、list_items(run_id, category, page, page_size)（按 seq 排序）、list_items_for_run(run_id)（不分页）、
        list_pending_items(run_id)（status=pending，按 seq 排序）、complete_item(item_id, **结果列)、fail_item(item_id, error)
      - 恢复：find_stale_runs(older_than_ms) -> 列表：status 为 queued 或 running，并且 heartbeat_time（为空时用 create_time）早于 older_than_ms
