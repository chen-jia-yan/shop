## 4. 大模型调用
### 4.1 裁判（Judge）调用
- 位置: `kb_poc/skills/rag_eval/runtime.py`
- 主裁判方法: `_judge()`（第613行）→ 实际调用 `_judge_v2()`（第697行）
- v2判prompt: 模块级常量 `JUDGE_V2_SYSTEM_PROMPT`（第37-39行） + `JUDGE_V2_USER_PROMPT_TEMPLATE`（第41-80行）
  - 4个维度: 忠实度、答案相关性、完整性、正确性 (1-5分)
  - `completeness` 额外输出 `key_points` 逐条判定
  - 注意: 评估prompt中的日文字段名含「忠实度」等日文表述
- v1判prompt (保留但不调用): `JUDGE_V1_SYSTEM_PROMPT`（第29-35行）
- LLM客户端: `OpenAICompatibleClient`（第139行 `from ...llm.openai_compatible_client import OpenAICompatibleClient`）
- 模型名: `model or self.settings.copilot_model`（第144行）—— 即 `.env` 中 `COPILOT_MODEL=gpt-5.4`
- 调用参数: `temperature=0.0`（第683行），无tools

### 4.2 根因分析（analyze_results）调用
- 位置: `runtime.py` `analyze_results()` 方法（第1095行）
- Prompt: `_ANALYZE_SYSTEM_PROMPT`（第1055行） + `_ANALYZE_FEW_SHOT`（第1063行）
- 模型: 同裁判，`OpenAICompatibleClient`
- 输出: 写 `eval_analysis.json`

### 4.3 答案生成调用
- 默认: `LocalAnswerer`（`kb_poc/local_answer/answerer.py`，第303-310行）——本地小模型/简单回答
- 临时开关: `use_advanced_qa=True` 时走 `AgentOrchestrator`（`kb_poc/agent/orchestrator.py`，第297-301行）
- 注意: 生成调用的模型由 `Answerer / LocalAnswerer / AgentOrchestrator` 内部决定，不是 `rag_eval` 直接配置

### 6.2 切片可视化特有配置
- 默认切片参数（`service.py` `_default_profiles()` 第445-458行，写死在代码中，非环境变量）：
  - default : chunk_size=520, overlap=80
  - ppt : chunk_size=900, overlap=60
  - ocr : chunk_size=260, overlap=30
  - pdf : chunk_size=420, overlap=60
- 质量阈值（`service.py` `_judge_quality()` 第415-429行，写死）：`<20 token → bad，>350 token → bad，>120 token 且未闭合 → warn`

### 6.3 RAG评估特有配置
- defaults（`manifest.json` 第25-28行）：`limit: null`（跑全部）、`top_k: 5`
- `run_rag_eval` 参数（运行时传入）：
  - dataset_path : 评估集路径
  - limit : 限制条数
  - top_k : 检索返回数（默认10，第115行）
  - output_path : 报告输出路径
  - model : 模型名（默认 `self.settings.copilot_model`）
  - use_advanced_qa : 临时开关（默认False，第117行）
- 整表重组上限（写死）：`_MAX_TABLE_CONTEXT_CHARS = 20000`（第313行）
- `allows_mutation: false`（manifest.json第23行）：标记为只读skill
- `requires_model: true`（manifest.json第24行）：需要LLM调用

## 9. 迁移时必须和同事约定的数据接口
### 9.1 切片工作台依赖的外部数据
1. 切片批次文件（`file-*.jsonl`）：
   - 格式：每行一个 Documentchunk JSON，字段含 `chunk_id`, `content`, `metadata.source_file`, `metadata.chunk_id`, `metadata.page_or_sheet`, `metadata.title_path`, `metadata.block_type`, `metadata.artifact_path`, `metadata.doc_type`
   - 迁移后需确认：是直接复制jsonl文件，还是通过API按需查询
2. 源文档目录：
   - chunk_studio首次访问文件时会跑完整解析+OCR去生成快照
   - 迁移后需确认：目标环境是否有PaddleOCR？是否需要预生成快照？
3. 解析器模块（`kb_poc.parsing.*`）：
   - `parse_pptx_file / parse_excel_file / parse_markdown_file`
   - `build_configured_ppt_ocr`
   - 迁移后需确认：这些解析器是否一同迁移？还是切片工作台改为只读预生成的快照？
4. 重建模块（`kb_poc.reconstruction`）：
   - `reconstruct_document_segments / build_reconstructed_chunks`
   - 用于文本复原和参数覆盖预览
5. 配置类（`KBSettings`）：
   - 需要约定迁移后的配置字段映射（至少需要 `project_root`, `source_dir`, `ocr_*`, `copilot_provider_*`）

### 9.2 RAG评估依赖的外部服务
1. 检索服务（`Answerer / Answerer.search()`）：
   - 需要连接到 Azure AI Search 索引
   - 迁移后需确认：目标环境的索引名、端点、密钥
2. LLM服务（`OpenAICompatibleClient`）：
   - 裁判打分 + 答案生成 + 根因分析都需要
   - 需要确认：目标环境的 `base_url`, `api_key`, `model`
3. 评估集格式约定：
   - JSONL每行：`{"question": "...", "expected_answer": "...", "expected_source": "...", "expected_file": "..."}`
   - `expected_answer` 兼容旧字段名 `ideal_answer`
4. 评估报告注册表（`evals/_eval_registry.json`）：
   - 格式：`{"reports": [...], "updated": "..."}`
