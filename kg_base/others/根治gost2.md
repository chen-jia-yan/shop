1. 第四刀(启动清扫)加一条”响铃”:清扫如果真杀到了东西,要打一条明显的日志(杀了哪个 PID、命令行是什么)。原因:第 1–3 刀修好后,正常跑本就不该再产生新孤儿;所以清扫平时应该”扫了个空”。哪天它真杀到了,就是个信号——说明还有漏的泄漏点,而不是让这个兜底默默把 bug 盖住。这条正好符合你”别越修越乱、别让创可贴遮住真问题”的顾虑。

2. 确认 set_executable 作用在进程池真正用的那个 context 上:它已经注意到”别放太晚”。再让它确认一句:如果 ‎`ProcessPoolExecutor` 是用默认 context 创建的,‎`set_executable` 就生效;如果代码里显式传了别的 ‎`mp_context`,得把设置加到那个 context 上,否则白设。这是唯一一个”看着对、其实可能没生效”的坑。

3. 锁的”PID 还活着才算有效”判断保留(它已经写了)——好。这样上次异常退出没清锁,下次也能正常起,不会把自己锁死。
