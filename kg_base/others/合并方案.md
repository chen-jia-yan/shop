我打算动这几个文件：`kb_admin\state_store.py`、`kb_admin\worker.py`、`kb_admin\process_one_file.py`、`kb_admin\ingestion.py`，大概还要看一眼 `kb_admin\services.py` 里有没有依赖旧状态名的显示/重试分支，但只会在确实被旧状态耦合时才动。

1. **kb_admin\state_store.py**
    - 要改状态机定义、`claim_pending(...)`、`mark(...)`、卡住任务回滚逻辑和启动时的数据迁移逻辑，把 `text_done / ocr_pending / ocr_processing` 全部收口成 `pending / processing / completed / failed / dead`，并把历史中间态统一重置为 `pending` 且清零 `attempts/crash_count`；
    - 风险是这里最容易把“失败重试 / 崩溃恢复”改坏，所以我会只删两阶段分支，不碰 `dead` 判定规则。

2. **kb_admin\worker.py**
    - 要改 `process_one(...)`、`_submit_rows(...)`、`_run_heavy_subprocess(...)`、主循环 `run(...)`，去掉 `phase / next_phase / _phase_for_stage(...)`，让每个文件始终一次 `include_ocr=True`，处理完后只入库一次并直接 `mark(..., "completed")`；
    - 风险是这里最容易影响重文件子进程隔离和进程池超时恢复，所以我不会动 `sys.executable`、超时、pool 重建、heavy subprocess 结构。

3. **kb_admin\process_one_file.py**
    - 要改命令行参数和返回值，去掉 `--phase` 以及 `next_phase` 相关分支，固定单趟 `include_ocr=True`；
    - 风险较小，主要是要和 `worker.py` 保持入参与 JSON 返回格式一致。

4. **kb_admin\ingestion.py**
    - 要改 `write_chunk_batches(...)` / `build_chunks_for_stage(...)` 的阶段返回约定，去掉“下一阶段是 ocr”的语义，让它只负责一次性产出完整 chunk 并写临时文件；
    - 风险是要确保 embedding 批量和 `source_kind` 标记仍正常。

> 我怀疑 `kb_admin\services.py` 里如果有把 `text_done / ocr_pending / ocr_processing` 当作任务状态展示或重试条件的逻辑，也要一起清掉，否则 UI/管理层会看到脏状态；这是我的猜测，需要打开文件确认后再决定是否改。
