# 2. 写入前会不会删除切片；按什么删；同文件名新版本会不会留下旧切片
## 结论
- 会删旧切片。
- 删除依据是 `document_id`，不是文件名，也不是 `source_file`。
- 但这里有个关键边界：SDK 默认 `document_id` 是文件内容 hash，不是“文件路径/文件名稳定 ID”。
- 所以：
  - 同内容重传：`document_id` 不变，会先删旧再写新，不会残留旧切片。
  - 同文件名、内容变了：默认 `document_id` 也会变，删除只删“新 document_id 对应的旧 chunk”，而旧版本的 document_id 不会被这次自动命中，所以旧版本切片会留在索引里，除非调用方自己把稳定 ID 通过 `idempotency_key` 传进来，或额外显式删除 `document_id`。

# 4. delete(document_id) 会不会同时清理 Neo4j 中这个文档的数据

## 6. TapIngestClient 有没有 async 版本；内部是否有阻塞网络调用
### 结论
- 没有 async 版本。当前公开方法 validate/process/process_files/ingest 全是同步 def。
- 内部有阻塞式网络调用：
  - embedding 用的是同步 OpenAI 客户端；
