任务目标:重写 rag-eval 的评分,让它反映项目真实目标——端到端答案质量 + 文档/段落级检索召回 + 严格忠实度,不再用碎片级命中当头条。顺带量出"toehold 率"(有没有捞到对的那份/那页),作为将来判断是否需要重跑的证据。

背景:现在的评分用"碎片级命中"量一个被定位切碎的库,天然不公平,把答得好的系统打成 1-2 分。测试阶段不需要迁就历史基线,直接把尺子做对。

范围(只允许动):
- rag-eval 的评估运行时(判分 _judge / 生成 _generate_answer / 维度定义)
- 不动生产的检索/生成/索引

明确不做(红线):
- 不碰生产检索、生成、索引、embedding;
- 这是只改"评估"这一侧;
- 不破坏 gold set 现有格式(要加字段只能新增)。

具体改动:
1. 检索召回改为"文档/段落级":命中结果里有没有来自正确来源(expected_source)的 chunk,算 toehold 命中率。保留它当诊断,专门用来发现"真漏召回"。
2. 答案质量当头条:忠实度/groundedness(答案是否只依据检索内容、有没有编)、答案相关性、完整性(对 ideal_answer)、正确性(对 ideal_answer)。
3. 裁判提示词:把检索到的(碎片)上下文 + 问题 + ideal_answer 一起给裁判,明确要求它"先在脑中复原碎片的意思,再判答案是否被支持"——利用模型自身的复原能力,不另造产物。
4. 忠实度/有没有乱答要严,确保真漏、真编仍被抓出来。
5.(可选)每题判 2-3 次取平均、固定裁判模型与温度,降低打分抖动。

必须保持不变:生产链路一律不动;gold set 原有字段不变。

验收标准:
- 评估报告给出:①文档/段落级召回(toehold 率)②端到端答案质量头条 ③严格忠实度仍能标出乱答;
- 同一份 gold set 上,分数比之前更贴近"答案其实不错"的真相,且真漏仍会暴露。

验证方式:静态检查;我自己先跑小样本(省 token、防 429);用任务①的开关做 off vs on 对比。

风险与回退:只改评估侧;改回评估文件即回退,生产不受影响。
