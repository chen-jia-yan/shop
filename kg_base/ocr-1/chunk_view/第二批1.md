任务目标:两处加固——缓存按内容失效、artifact 读取收窄目录。只加健壮性/安全性,不改功能和接口。

范围(只允许动):
- chunk_studio/segment_cache.py
- chunk_studio/service.py(仅 get_artifact_detail 相关处)

明确不做(红线):
- 不碰切片/解析/OCR/索引核心逻辑;
- 不改任何接口的路径、参数名、返回字段结构(前端在用);
- 不顺手重构无关代码。

具体改动:
1. segment_cache 缓存失效(解决"源文件改了、预览还看旧内容"):
   - 保存快照时,额外在快照 JSON 里记录:源文件的 mtime 和 size,外加一个 schema_version 字段。
   - load_document_snapshot 读取时:对比当前源文件的 mtime+size 和 schema_version;任意一个对不上,就当缓存未命中、返回 None(触发重新解析)。
   - 说明:旧缓存没有这些字段,会被当未命中、重解析一次(含 OCR),这是正常的一次性成本。
   - 不要用"读全文件算 hash"的方式(大文件慢);用 mtime+size 即可。

2. get_artifact_detail 收窄根目录(当前允许读 project_root 下任意文件,风险偏大):
   - 先只读确认:前端传来的 artifact path 是相对于哪个目录的(artifact_dir 还是 project_root)?
   - 在不破坏前端正常读取的前提下,把 safe_under 的校验根从 project_root 收窄到 artifact 目录(context.artifact_dir);若前端确实要跨目录,改成一个明确的白名单目录,别放开到整个 project_root。
   - ⚠️ 如果这一步会影响前端正常功能,先停下来说明,别硬改。

必须保持不变:正常 artifact 读取、正常缓存命中逻辑、所有返回结构。

验收标准:
- 改动某个源文件后重开 preview,看到的是新内容(发生了重解析),不是旧快照;
- 传一个 artifact 目录以外的路径会被拒,正常 artifact 仍能读到。

验证方式:py_compile / import 静态检查 + 单接口小测,别真跑整个 worker。

风险与回退:缓存改动最坏是多解析一次;artifact 收窄若误伤前端,回退到原校验根并告诉我。
