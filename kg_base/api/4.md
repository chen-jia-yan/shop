出问题怎么办

① 提 PR

在 Azure DevOps 从 ‎⁠feature/tap-10366⁠ 提到 develop。描述里写清做了什么、怎么验证、要注意什么（比如图谱写入开关在 dit 上要关）

 

② CI 检查

PR 页面会显示流水线结果，通常会跑代码检查（ruff）、类型检查（mypy）、测试（pytest）、构建镜像。全部绿了才算过

点红色的那一步看日志。最常见的是测试失败或缺依赖（比如 SDK 没装进镜像），把日志最后几十行发我

③ 代码审核

等组长或同事审核。有评论就按评论修改，在同一个分支提交、推送，PR 会自动更新

 

④ 合并

审核通过后点 Complete。合并方式（Squash 还是 Merge）按团队习惯来，问组长

有冲突时，在本地把 develop 合进你的分支解决，再推送

⑤ CD 部署

合并后自动打包镜像、部署到 dit，不用手动操作。在 Pipelines 里看这次部署有没有成功、用的是哪个提交

部署失败看日志；部署成功但服务起不来，多半是配置缺失，看后端日志

⑥ 冒烟检查

部署完先花 5 分钟确认服务活着：打开 dit 后端的 ‎⁠/docs⁠，或在 TAP 页面按 F12 看你的接口有没有返回 200

404 说明路由没挂上或部署的还是旧版本；500 去看后端日志
