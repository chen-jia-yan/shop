# 知识图谱页面 · 前端对接说明

> 接口前缀：`/tap/ai/library/kg`　｜　全部 `POST`（节点详情为 `GET`）　｜　请求体 JSON
> 接口文档：后端启动后打开 `http://<后端地址>/docs`，在 `library-kg` 分组下

---

## 1. 通用约定

| 项目 | 约定 |
| --- | --- |
| 选择图谱 | 每个请求体照常带上平台的租户字段 `saas_id`、`workspace_id`、`project_id`、`user_id`（和其他 TAP 接口一样）。后端按 `saas_id` 自动找到对应的图谱：`hk` → hk 图谱，`jp` → `jp-poc` 图谱。**不需要传 `scope`** |
| 指定图谱（可选） | 如果要绕过 `saas_id` 直接指定图谱，传 `scope`（值来自 `scopes/list`）。两个都传时以 `scope` 为准 |
| 参数错误 | HTTP **422**，返回体是 `{"detail": [...]}`。这是前端传参有问题，请检查参数 |
| 业务错误 | HTTP **200**，返回体 `{"code": "CCB001", "message": "节点不存在"}`。把 `message` 显示给用户 |
| 分页 | 请求 `page`（从 1 开始）、`page_size`；返回 `items / total / page / page_size` |
| 节点显示 | 名称用 `label`，类型用 `type_zh`；筛选时传英文 `type` |
| 边显示 | 文字用 `label`。`type` 为 `RELATED_TO` 的边建议画成虚线或灰色（弱关系） |
| 已弃用字段 | `name`（改用 `label`）、`direction`、`entities/list` 的 `types`（改用 `entity_types`）。仍然返回或可用，新代码请不要再用 |

### 节点对象

```json
{"id": "System:SFDC", "label": "SFDC", "name": "SFDC", "type": "System", "type_zh": "系统", "degree": 12}
```

`id` 原样保存，调用其他接口时原样传回。`id` 中可能含有 `:`、`/`、中文。

### 边对象

```json
{"id": "5:abc:123", "source": "System:SFDC", "target": "Data:顧客情報", "type": "USES", "type_zh": "使用", "label": "使用"}
```

## 2. 页面区域与接口

| 页面区域 | 接口 | 何时调用 |
| --- | --- | --- |
| 首页选择知识库（hk / jp） | 不用调图谱接口 | 选中的租户作为 `saas_id` 带在之后每个请求里 |
| 顶部「后端文档数」 | `scopes/list` 的 `document_count` | 同上 |
| 顶部「已加载节点 / 关系」 | **不用调接口** | 前端统计当前画布上的节点数和边数 |
| 顶部搜索框 | `nodes/search` | 用户输入关键词时（建议防抖 300ms） |
| 左侧类型图例 / 过滤 | `stats` | 页面打开、切换图谱时 |
| 左侧实体列表 | `entities/list` | 打开页面、勾选类型、输入筛选关键词、选择文档时 |
| 左侧文档列表 | `files/list` | 页面打开、搜索文档时 |
| 中间画布 | `graph/overview` | 页面打开、勾选类型、选择文档时 |
| 右侧节点详情 | `nodes/{node_id}`（GET） | 点击节点 |
| 右侧「展开邻居」/「相邻节点」 | `nodes/expand` | 点击节点或展开按钮 |
| 右侧「来源切片」 | `nodes/chunks/list` | 点击节点 |

## 3. 交互流程（需要组合调用的场景）

### 3.1 打开页面

```
首页已选知识库 → saas_id（例如 hk）
  ├─ stats(saas_id)               → 左侧类型勾选项和数量
  ├─ files/list(saas_id)          → 左侧文档列表
  ├─ entities/list(saas_id)       → 左侧实体列表
  └─ graph/overview(saas_id)      → 画布
```

画布返回空、且 `scopes/list` 中该租户对应图谱 `has_graph=false` 时（目前 hk 就是这样）：画布显示「暂无实体关系，可在文档列表中查看」，不调 `graph/overview`。

### 3.2 切换图谱

清空画布、详情面板、勾选状态，然后用新的 `saas_id` 重做 3.1。

### 3.3 点击一个节点

**同时**发三个请求：

```
nodes/{node_id}                              → 右侧详情：名称、类型、属性
nodes/chunks/list(node_id)                   → 右侧来源切片（按文档分组）
nodes/expand(node_id, depth=1)               → 右侧「相邻节点」列表（结果先缓存，不画到画布上）
```

「相邻节点」= `nodes/expand` 返回的 `nodes` 去掉 `center_id` 本身。

### 3.4 点击「展开邻居」

把 3.3 缓存的 `nodes/expand` 结果**合并**到画布上：

- 按 `id` 去重，已有的节点不重复添加，也不要清空画布
- 边按 `id` 去重
- 没有缓存时（比如直接在画布上右键展开）就现在调一次
- 想展开两层，调 `nodes/expand` 时传 `depth=2`

### 3.5 顶部搜索

```
nodes/search(keyword) → 下拉显示结果
用户选中一个 → nodes/expand(该节点, depth=1) → 把结果合并到画布，并把视角移到该节点、选中它
            → 同时执行 3.3（填右侧详情）
```

### 3.6 左侧勾选类型过滤

```
用户勾选 / 取消勾选 → entity_types = 当前勾选的英文 type 列表
  ├─ graph/overview(entity_types, relation_types, document_id)  → 重画画布
  └─ entities/list(entity_types, document_id)                   → 刷新左侧实体列表
```

- **全部勾选时不传 `entity_types`**，这表示不过滤，比传完整列表更快
- **全部取消时不要调接口**，直接清空画布。传空列表 `[]` 会返回 422
- 关系类型的过滤同理，用 `relation_types`
- 已经展开过的局部子图，勾选后也用 `nodes/expand` 带上同样的过滤条件重新取

### 3.7 点击左侧某个文档

```
graph/overview(document_id=该文档)        → 画布只显示这个文档里的实体和关系
entities/list(document_id=该文档)         → 左侧实体列表只显示这个文档里的实体
```

可以和类型过滤一起用，两个条件同时生效。再点一次或点「全部文档」时去掉 `document_id`。

### 3.8 结果被截断

`graph/overview`、`nodes/expand` 返回 `truncated: true`，表示数据超过了 `limit`，只返回了权重最高的那部分。画布角落要提示：

> 数据较多，仅显示部分。可通过类型过滤或选择文档缩小范围。

## 4. 接口详情

### 4.1 `scopes/list` 图谱列表（可选）

请求：`{}`

```json
{"items": [
  {"saas_id": "jp", "saas_ids": ["jp"], "has_graph": true,
   "entity_count": 1234, "relation_count": 2345, "chunk_count": 16427, "document_count": 40, "last_updated": 1761984000000},
  {"scope": "<hk 索引名>", "saas_ids": ["hk"], "has_graph": false,
   "entity_count": 0, "relation_count": 0, "chunk_count": 90, "document_count": 6, "last_updated": null}
]}
```

这个接口主要给后端排查和管理用：看每个图谱对应哪个租户（`saas_ids`）、有没有实体（`has_graph`）。前端按 `saas_id` 调其他接口时，不必先调它。

### 4.2 `stats` 统计（左侧类型面板）

请求：`{"saas_id": "jp", "workspace_id": "...", "project_id": "...", "user_id": "tapadmin"}`

```json
{
  "entity_types": [
    {"type": "System", "type_zh": "系统", "count": 120},
    {"type": "Process", "type_zh": "流程", "count": 98}
  ],
  "relation_types": [
    {"type": "USES", "type_zh": "使用", "count": 300},
    {"type": "RELATED_TO", "type_zh": "相关", "count": 210}
  ]
}
```

原有字段（比如 `type_counts`）仍然返回。新代码请用这两个列表：已经按数量从多到少排好，带中文名。

### 4.3 `graph/overview` 画布

请求：

```json
{
  "saas_id": "jp", "workspace_id": "...", "project_id": "...", "user_id": "tapadmin",
  "limit": 300,
  "entity_types": ["System", "Process"],
  "relation_types": null,
  "document_id": null
}
```

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `scope` | 是 | |
| `limit` | 否 | 最多返回多少条边 |
| `entity_types` | 否 | 只看这些类型的实体；不传 = 全部；不能传 `[]` |
| `relation_types` | 否 | 只看这些类型的关系；不传 = 全部；不能传 `[]` |
| `document_id` | 否 | 只看这个文档里的实体；值来自 `files/list` |

返回：

```json
{"nodes": [节点对象...], "edges": [边对象...], "truncated": false}
```

没有关系、只有实体时，`nodes` 有数据，`edges` 为空，画成孤立节点即可。

### 4.4 `nodes/expand` 展开邻居

请求：

```json
{
  "saas_id": "jp", "workspace_id": "...", "project_id": "...", "user_id": "tapadmin",
  "node_id": "System:SFDC",
  "depth": 1,
  "limit": 200,
  "entity_types": null,
  "relation_types": ["USES", "REQUIRES"]
}
```

返回：

```json
{"center_id": "System:SFDC", "nodes": [节点对象...含中心节点], "edges": [边对象...], "truncated": false}
```

中心节点总会返回，即使它的类型不在 `entity_types` 里。

### 4.5 `nodes/search` 顶部搜索

请求：`{"saas_id": "jp", "keyword": "理赔", "entity_types": null}`

返回：节点对象列表（原有的返回结构不变，每个节点按第 1 节的格式带上 `label`、`type_zh`）。

### 4.6 `entities/list` 左侧实体列表

请求：

```json
{"saas_id": "jp", "keyword": "契約", "entity_types": ["Process"], "document_id": null, "page": 1, "page_size": 20}
```

返回：`{"items": [节点对象...], "total": 56, "page": 1, "page_size": 20}`

`keyword` 是名称包含匹配，不区分大小写和全半角。

### 4.7 `nodes/{node_id}` 节点详情（GET）

`GET /tap/ai/library/kg/nodes/System:SFDC?saas_id=jp`

`node_id` 里有特殊字符时要做 URL 编码（`encodeURIComponent`）。查询参数传 `saas_id`（或 `scope`）。

返回：节点对象 + `properties`（其他属性，已去掉向量等内部字段）。节点不存在时返回 `CCB001 节点不存在`。

### 4.8 `nodes/chunks/list` 来源切片（按文档分组）

**两种模式：**

| 模式 | 什么时候用 | 请求 | 分页单位 |
| --- | --- | --- | --- |
| 文档分组（`by_document`） | 点击节点后，右侧首次显示 | 不传 `document_id` | 文档 |
| 文档内（`in_document`） | 某个文档点「查看全部 N 条」 | 传 `document_id` | 切片 |

**文档分组模式**

请求：

```json
{"saas_id": "jp", "node_id": "entity::123", "page": 1, "page_size": 20, "chunks_per_doc": 3}
```

返回：

```json
{
  "mode": "by_document",
  "items": [
    {
      "document_id": "doc::ab12...",
      "source_file": "#09_代理店手数料システム.pptx",
      "chunk_total": 5,
      "has_more": true,
      "chunks": [
        {"chunk_id": "cb11afe7eb1d", "page_or_sheet": "slide-3", "preview": "1-2. 代理店手数料の概要……", "has_content": true},
        {"chunk_id": "7b578ac45407", "page_or_sheet": "slide-7", "preview": "……", "has_content": true},
        {"chunk_id": "1305a76fed20", "page_or_sheet": "slide-11", "preview": "", "has_content": false}
      ]
    },
    {
      "document_id": "doc::cd34...",
      "source_file": "#06_新契約システム概要.pptx",
      "chunk_total": 2,
      "has_more": false,
      "chunks": [...]
    }
  ],
  "total": 2,
  "chunk_total": 7,
  "page": 1,
  "page_size": 20
}
```

**排序规则（后端已排好，前端按顺序显示即可）：**
- 文档：提到该节点的切片越多越靠前
- 切片：按页码的自然顺序排列（slide-2 排在 slide-11 前面）

**文档内模式**（点「查看全部 5 条」）

请求：

```json
{"saas_id": "jp", "node_id": "entity::123", "document_id": "doc::ab12...", "page": 1, "page_size": 20}
```

返回结构相同，`mode` 为 `in_document`，`items` 里只有这一个文档，`chunks` 是这一页的切片，`total` 是该文档的切片总数。

**推荐显示方式：**

```
来源切片（共 7 条，来自 2 个文档）          ← chunk_total、total
▼ #09_代理店手数料システム.pptx（5）        ← source_file、chunk_total，可折叠
    slide-3   1-2. 代理店手数料の概要……      ← page_or_sheet、preview
    slide-7   ……
    slide-11  暂无内容                      ← has_content=false 时显示
    查看全部 5 条 ›                         ← has_more=true 时显示，点击走文档内模式
▶ #06_新契約システム概要.pptx（2）
```

- `preview` 最多 200 个字，鼠标悬停或点击可以展开显示完整的 `preview`
- `document_id` 为空字符串的分组，`source_file` 为「未知文档」
- 文档数大于 `page_size` 时，底部显示「加载更多文档」，`page` 加 1 后追加到列表

### 4.9 `files/list` 文档列表

请求：`{"saas_id": "jp", "keyword": "契約", "page": 1, "page_size": 20}`

`keyword` 可选，按文件名包含匹配。返回的文档编号字段就是其他接口里 `document_id` 要传的值。

## 5. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 返回 422 | 参数格式不对，比如 `saas_id` 和 `scope` 都没传、传了 `[]`、类型名带空格、`page_size` 为 0 | 按 `detail` 里的提示修正参数 |
| 返回 CCB001「节点不存在」 | `node_id` 不是从接口返回的值复制来的，或者切换了图谱但还用着旧节点 | 切换图谱时清空状态 |
| 返回 CCB001「图谱不存在」或「该租户未配置知识图谱」 | `scope` 不在 `scopes/list` 里，或该 `saas_id` 没有配置图谱 | 联系后端确认配置 |
| hk 画布是空的 | hk 目前只有文档和切片，还没有实体关系（`has_graph=false`） | 正常，显示提示语 |
| 切片显示「暂无内容」 | 该切片暂时没有正文摘要 | 正常，后端正在补全 jp-poc 的数据 |
| 画布只有部分数据 | `truncated=true` | 显示截断提示 |

## 6. 不在本期范围

- 增量 / 变更提醒：不做，顶部「变更 / 同步增量」请隐藏
- 新增节点、新增关系、重命名、删除、导入、重置：不做，按钮已隐藏
- 导出：前端把当前画布导出成图片或 JSON 即可，不需要后端
- 切片「相似度」：没有这个数据，请改为显示页码（`page_or_sheet`）
