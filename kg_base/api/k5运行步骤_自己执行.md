【由你自己运行，不交给 Copilot】K5 改版的正式运行步骤

1. 配置（在后端 .env 中，你自己编辑，不要发给任何人）：
   jp-poc 和 hk 在同一个 Azure 服务、共用查询密钥 → 什么都不用加，脚本会自动用知识库已有的配置
   不在同一个服务，或者想单独用 jp-poc 的查询密钥 → 加三行：
     TAP_AI_KG_POC_SEARCH_ENDPOINT=https://<jp-poc 所在服务>.search.windows.net
     TAP_AI_KG_POC_SEARCH_KEY=<jp-poc 的查询密钥，不要用管理密钥>
     TAP_AI_KG_POC_INDEX=jp-poc

2. 记录现状（Neo4j 网页控制台）：
   MATCH (n) WHERE n.scope IS NOT NULL
   RETURN n.scope AS scope, labels(n) AS 节点类型, count(*) AS 数量 ORDER BY scope, 数量 DESC;

3. 预演（不写任何数据）：
   Set-Location C:\Users\234393\Desktop\tap-ai-backend
   & .\.venv\Scripts\python.exe scripts\kg_remap_poc_chunks.py
   把输出发我：六种分类各多少、matched 占比、几个例子

4. 我确认数字合理后，正式写入：
   & .\.venv\Scripts\python.exe scripts\kg_remap_poc_chunks.py --write
   脚本最后会自动核对 hk 等其他 scope 的数字有没有变化

5. 确认结果（Neo4j 网页控制台）：
   MATCH (c:Chunk {scope: 'jp-poc'})
   RETURN c.remap_status AS 状态, count(*) AS 数量, count(c.preview) AS 有摘要;

   MATCH (d:Document {scope: 'jp-poc'})
   RETURN d.filename, d.source_file LIMIT 10;

   再跑一次第 2 步，hk 的各行数字必须和第 2 步完全一样

6. 在 swagger 里对同一个实体调 nodes/chunks/list，切片应该带上了正文，文件名不再是乱码
