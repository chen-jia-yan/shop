3. 怎么在 dit 环境联调

dit 是自动部署出来的环境，不能在上面直接改代码。联调的做法是「在 dit 上发现问题 → 本地复现、修改 → 提交 PR → 流水线重新部署 → 回到 dit 验证」。

第一步：在页面上看前端发了什么、后端回了什么（最常用）

1. 在 TAP 页面按 F12，打开开发者工具，切到 Network（网络） 标签。

2. 在过滤框输入 ‎⁠tap/ai⁠，只看你的接口。

3. 在页面上操作，比如打开图谱、点一个节点。

4. 点击列表里的某条请求：

 - Headers（标头）：请求地址、状态码，比如 200、422。

 - Payload（载荷）：前端发的请求体，刚才的入参问题就是在这里看出来的。

 - Response（响应）：后端返回的数据。

5. 有问题时，右键这条请求 → Copy → Copy as cURL，就能拿到完整的请求。

一个安全提醒： 请求头里有登录凭证（‎⁠Authorization⁠ 或 Cookie）。截图或转发请求的时候，先把这些删掉。

第三步：确认 dit 上跑的是哪个版本

到 Azure DevOps 的 Pipelines，找最近一次运行，看它构建的是哪个分支、哪个提交。你修了问题但 dit 上还没变，多半是还没重新部署，或者流水线失败了。

第四步：修改并重新部署

本地改 → 测试 → 提交 → 推送并更新 PR → 等流水线跑完自动部署 → 在 dit 页面上用 F12 再验证一次。

要问组长或 DevOps 的三件事

1. dit 后端的日志在哪里看？（是 Azure 门户、Kibana 还是别的。）报 500 或数据不对的时候，日志是最快找到原因的地方。

2. dit 后端的 swagger（‎⁠/docs⁠）能不能直接打开？地址是什么？

3. dit 的配置在哪里改？（是不是 ‎⁠devsecops/⁠ 下的部署文件。）有两件事要确认：

 - ‎⁠TAP_AI_KB_INDEXES⁠ 里有没有 hk。

 - Neo4j 地址配好没有。

 - 图谱写入开关 ‎⁠TAP_AI_LIBRARY_KB_GRAPH_ENABLED⁠ 在 dit 上建议先设成 ‎⁠false⁠，因为写图逻辑还没完整验证。

4. 顺序建议

1. 先让 Copilot 做第 1 段（包含 S0）。这个直接决定前端能不能调通，优先级最高。

2. 做完提交、推送，流水线部署到 dit 后，在 TAP 页面上用 F12 验证：前端用 ‎⁠saas_id⁠ 调用，应该返回 200。
