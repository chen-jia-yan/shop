几个关键设计，你和前端都需要知道：

1. 兼容旧字段，不破坏前端已接好的部分 ￼

2. 类型过滤怎么传 ￼

画布接口（‎`graph/overview`、‎`nodes/expand`）和两个列表接口（‎`entities/list`、‎`nodes/search`），都用同样的参数名和规则：



|参数              |不传 |传值                               |不允许         |

|----------------|---|---------------------------------|------------|

|`entity_types`  |不过滤|只看这些实体类型，如 `["System","Process"]`|`[]`（返回 422）|

|`relation_types`|不过滤|只看这些关系类型                         |`[]`        |

|`doc_id`        |不过滤|只看这个文档里的实体                       |空字符串        |

- 多个条件同时传： 取交集。

- 前端全选： 不传这个参数。

- 前端全部取消勾选： 不调接口，直接清空画布。

- 左侧勾选框的数据来源： ‎`stats` 新增的 ‎`entity_types` 和 ‎`relation_types` 两个列表，带中文名和数量，已经排好序。

- 类型名的校验方式： 只校验格式（字母和下划线，最多 40 个字符），不检查这个类型是否存在。库里实际出现的类型可能比 SDK 定义的多，不存在的类型只是查不到数据，不会报错。

3. 切片列表怎么分组 ￼



|模式  |请求         |返回                         |用在哪         |

|----|-----------|---------------------------|------------|

|文档分组|不传 `doc_id`|每页 20 个文档，每个文档带前 3 条切片和切片总数|点击节点后，右侧首次显示|

|文档内 |传 `doc_id` |只返回这个文档的切片，按切片分页           |点「查看全部 N 条」 |

怎么实现：

1. 先在 Neo4j 里按文档统计「提到这个节点的切片数」，按数量从多到少排序，再按文档分页。

2. 取出这一页文档里的切片。

3. 在 Python 里按页码的自然顺序排序（slide-2 排在 slide-11 前面），每个文档取前 3 条。

这样分页的单位是文档，同一个文档不会被拆到两页。

每条切片带什么：

- ‎`preview`：正文前 200 个字。

- ‎`has_content`：有没有正文。没有正文时 ‎`preview` 为空字符串，前端显示「暂无内容」，不再拿切片编号充数。

4. 补全切片正文（K5 改版） ￼

1. 从 Azure 读取： 只读读出 jp-poc 索引的全部切片，对每条正文算 ‎`sha256` 前 12 位，和 Neo4j 里的切片编号对上。正文前后有空格时也会再试一次，还有多条对上时，用「文件名 + 页码」区分。

2. 对上的切片写回四样东西：

 - 切片编号改成 Azure 的主键，旧编号保存在 ‎`poc_chunk_id`。这样满足全系统的约定「图里的切片编号 = Azure 切片主键」，同事的问答以后对 jp-poc 也能直接取到原文。

 - 补上正文摘要。

 - 换成正确的文件名。

 - 补上页码。

3. 对不上的切片： 只修文件名乱码，并标记状态（多条匹配、没匹配、编号冲突），编号不变。

4. 兼容同一个服务和不同服务： 脚本有自己的三个配置项（‎`TAP_AI_KG_POC_*`），配了就用。没配的话，自动用知识库现有的 Azure 配置。

5. 安全措施：

 - Azure 只读，源码里禁止出现写入方法，测试会检查。

 - Neo4j 只改 jp-poc 的切片和文档节点，不碰实体和关系。

 - 不改 ‎`document_id`，否则切片和文档之间的关系会断开。

 - 写入前后自动核对其他 scope 的数字，hk 有任何变化就报错退出。

 - 可以重复运行，已经对齐过的切片会跳过。
