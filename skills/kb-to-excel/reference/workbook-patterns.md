# 保险业务常见工作簿模式

每种模式给出：一行是什么 → 字段要点 → 视图 / 提醒 / 仪表盘 → 注意事项。按需求删减改造。
共同点：**原始数据表永远是第一层**，视图、仪表盘、提醒都建在它上面。

## 1. 投诉 / 工单台账（对内，持续更新）——示范：`complaints_tracker.json`
**一行**：一件投诉（主键：工单号）。
**字段**：受理日期、渠道、客户（脱敏）、产品、类别、**问题描述原文**、承办部门、承办人（录入）、状态（录入）、结案日期（录入）；公式：处理时限、处理天数、时效；智能：摘要、建议类别（对照人工类别）；链接：工单来源。
**视图**：待办（未结案，按时限排序）、时效预警（超时 + 临近）、状态看板。
**提醒**：超时、临近时限、未分派、监管转办加急、已结案缺结案日期、智能类别与人工不一致。
**仪表盘**：受理 / 未结 / 结案率 / 超时 / 平均天数 / 监管未结；受理与结案月度趋势；部门 × 类别热力；部门进度；异常清单。
**注意**：客户信息脱敏；时限天数放参数；原文不改写，摘要另起一列。

## 2. 整改 / 项目跟踪（对内，持续更新）——示范：`compliance_tracker.json`
**一行**：一项整改事项；问题另建一张“问题清单”数据表，用编号关联。
**字段**：事项、对应问题、责任部门、责任人（录入）、计划开始 / 完成、状态、进度（录入）；公式：剩余天数、预警；问题表用 INDEX/MATCH 取整改状态。
**视图**：未完成（按计划完成日排序）、状态看板。需要时间轴时在 sheets 里加 gantt。
**提醒**：逾期、临近、缺责任人、已完成但进度不足、高风险问题未改完。
**仪表盘**：完成率（圆环）、平均进度、逾期、高风险未改完；部门进度；预警分布；异常清单。
**注意**：整改措施写具体动作；依据查不到写【请确认】。

## 3. 经营看板（对内，管理层）——示范：`branch_dashboard.json`
**一行**：一个机构 / 一条产品线 / 一个季度，分别建三张数据表。
**字段**：原始指标（保费、去年同期、目标、人力、继续率）原样录入；同比、达成率、人均产能为公式。
**视图**：通常不需要；`meta.dashboard_first: true` 让仪表盘排第一。
**提醒**：未达成、继续率低于预警线、负增长。
**仪表盘**：指标卡 + 公式洞察 + 分组达成表 + 引用数据表的图表（对比、排名、规模 + 增速、构成）；口径说明放 notes。
**注意**：比率类汇总用总额相除；“下降为好”的指标（赔付率、费用率、投诉率）着色方向相反。

## 4. 产品 / 方案对比 + 试算（对外为主）——示范：`product_compare.json`
**一行**：不是记录型数据，用 sheets：对比矩阵（matrix）+ 试算（calculator，含费率查找表）。
**注意**：费率必须来自知识库费率表；写明“试算结果仅供参考，以保险合同为准”；推荐项写适用人群，不写“最好”。对外文件加 `--external` 质检。

## 5. 材料 / 检查清单——示范：`claims_checklist.json`
**一行**：一项材料或检查点，用 checklist；区分“必备”和“如适用”，顶部自动显示还差几项。
需要按人 / 按件跟踪（例如 100 件理赔各自的材料齐全情况）时，改用 data：一行一件，每项材料一个 bool 字段，提醒“缺必备材料”。

## 6. 参数 / 政策汇总台账（对内）
**一行**：一条规则（例如一个产品的一项投保规则、一个地区的一项报销标准）。
**字段**：对象、规则项、规定内容（**原文**）、数值（可计算时单独一列）、生效日期、来源文档、条款位置。
**视图**：按对象筛选的列表；需要横向比较时另加 matrix。
**提醒**：缺来源、生效日期早于最新版本、同一对象同一规则项出现两条（冲突待确认）。
**注意**：新旧规定冲突时两条都保留，在备注写明以哪条为准，不要只留一条。

## 7. 费用 / 预算测算（对内）
**一行**：一项费用（主键：费用编号）。字段：类别、单价（录入）、数量（录入）、标准单价；公式：金额、超标准。
**提醒**：超标准、缺审批人。**仪表盘**：按类别汇总、预算使用率圆环。
单个方案的现场测算用 calculator。

## 8. 名单 / 通讯录（对内）
**一行**：一个人（主键：工号或编号）。色系用 soft。
**视图**：按机构 / 角色的列表。**提醒**：缺对接人、信息过期（更新日期早于参数设定的天数）。
**注意**：只用有权限查看的信息；手机号等个人信息确有需要才放入，对外文件一律不放。

## 9. 培训 / 考试台账（对内）
**一行**：一人一次培训或考试。公式：是否通过 `=IF({@成绩}>={param.pass},"通过","未通过")`。
**仪表盘**：按机构的参训率、通过率（总人数相除）、未通过名单。通过线查不到时写【请确认】。

## 10. 已有表格的分析与回写
**场景**：用户给了一个现成的 Excel（如每周导出的工单表），要求“分析一下”“把结论填回去”。
**流程**：`read_xlsx.py read` 原样读出 → 基于全部记录分析 → 需要报告时交给 Word / PPT → `read_xlsx.py write` 按主键回写白名单列（例如“智能摘要”“建议类别”“分析结论”），另存新文件。
**升级**：把读出的数据作为 data，补字段类型、公式、视图、提醒和仪表盘后重新渲染；用 `review_xlsx.py --content` 确认数据一条没少。
