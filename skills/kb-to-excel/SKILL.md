# 知识生成 Excel

表格的重心在数据。目标是交付一个**原始数据一条不少、在原始数据上做汇总归纳、打开就能用**的工作簿：

```
数据层  原始记录 ── 完整保留，不合并、不汇总、不改写；每行带来源
  │  只引用，不复制
视图层  筛选 / 排序 / 看板 ── 数据一改自动更新，点主键跳回原始行
  │
分析层  仪表盘（进度 · 趋势 · 异常）· 提醒规则（表里标色）· 智能列（紫色表头，待确认）
```

**硬规则：汇总只能新增，不能替代原始数据。** 原始数据表的行数、字段数必须与检索结果一致，渲染和质检都会核对。

```
① 读懂需求 → 需求卡片
② 设计字段 → 字段清单（先给用户看）
③ 按字段检索 → 原始记录 + 出处
④ 设计视图与分析 → 视图、提醒规则、仪表盘
⑤ 组装内容 JSON → 渲染 .xlsx
⑥ 质检交付
（另：已有工作簿 → 读取 → 分析 → 报告 → 回写）
```

## ① 读懂需求 → 需求卡片

规则见 `kb-to-word/reference/requirement-analysis.md`。Excel 额外判断三件事：

| 项 | 判断 | 影响 |
|---|---|---|
| **一行是什么** | 一件投诉、一个机构、一项整改、一款产品…… | 决定主键和行数，是整个工作簿的地基 |
| **要不要持续更新** | 一次性汇总，还是每周有人更新状态 | 持续更新 → 录入格、下拉、提醒规则、看板 |
| **要看什么结论** | 进度？趋势？异常？对比？ | 决定视图和仪表盘放什么 |

```
📋 需求卡片
一行 = 一件客户投诉（主键：工单号）｜读者：客服与理赔负责人｜对内｜每周更新
要看：未结案进度、超时预警、各部门情况｜色系：蓝色系
```

## ② 设计字段 → 字段清单

字段是一切的基础（视图、公式、提醒、仪表盘都依赖它）。**先列字段清单给用户确认，再检索。**能从需求推断的直接写，拿不准的标出来问。

| 列 | 说明 |
|---|---|
| 字段名 | 与知识库原文用词一致，不自己改名；同一含义只用一个字段 |
| 类型 | text 文本 / longtext 长文本 / number 数字 / money 金额 / percent 百分比 / date 日期 / select 单选 / multi 多选 / person 人员 / link 链接 / formula 公式 / ai 智能生成 / bool 是否 |
| 必填 | 必填为空时自动标黄 |
| 可选值 | 单选字段的取值（生成下拉，集中放在“参数”表） |
| 来源 | 来自哪个系统 / 文档；人工登记的写“人工登记” |

原则：
- **检索到的字段全部保留**，不因为“列太多”删列；阅读负担用冻结、隐藏辅助列、视图来解决。
- **原文类内容单独成列、完整写入**（问题描述、条款原文、处理意见），不要只放摘要。需要摘要时另加一个 `ai` 字段。
- 能算出来的（时限、天数、达成率、状态判断）用 `formula` 字段，不手填。
- 阈值（时限天数、预警线）放 `params`，公式里用 `{param.键}` 引用，改一处全表生效。

## ③ 按字段检索 → 原始记录

检索方法与证据台账同 `kb-to-word/reference/retrieval.md`：

1. **先确认记录清单**（一共有哪些工单 / 机构 / 事项），记下条数 → 写进 `expect_rows`。
2. **再按字段补全**，每个字段检索一次覆盖所有记录。
3. 查不到的格子填 `【待补充：XX】`（自动高亮），不推测。
4. **原样写入**：数字、日期、原文照抄；单位和口径不一致时在字段 `desc` 里写明，不要私自换算。

## ④ 设计视图与分析

格式见 `reference/sheet-types.md`，常见组合见 `reference/workbook-patterns.md`。

- **视图**（`views`）：回答“我现在要处理哪些”。`list` 列表（条件 + 排序），`board` 看板（按状态分列）。视图只引用数据表。
- **提醒规则**（`rules`）：回答“哪些有问题”。条件命中时，数据表的“提醒标记”列写出规则名，指定字段标红 / 黄 / 紫；规则可在“提醒规则”表逐条停用。只在表里标记，不发消息。
- **仪表盘**（`dashboard`）：回答“整体怎么样”。指标卡（可带圆环）、智能洞察（每句话由公式拼成，数据变了句子跟着变）、趋势组合图、交叉热力、分组进度、分布、异常清单、引用数据表的原生图表。
- **智能列**（`ai` 字段）：摘要、分类、信息提取。写入的是值，表头标注依据字段和生成日期；可写 `check` 与人工字段对照，不一致自动标紫。**原文列不动。**

公式写法（`reference/design-standards.md`）：
- 本行字段 `{@字段}`，其他表的整列 `{表.字段}`（渲染为结构化引用，表格新增行自动覆盖），参数 `{param.键}`。
- 所有除法包 `IFERROR`；比率类汇总用“总分子 ÷ 总分母”，不对百分比求和或简单平均。
- 公式由需求描述生成时，在字段 `desc` 里写一句话说明含义（会出现在表头批注和“字段说明”里）。

## ⑤ 渲染

```bash
pip install -U openpyxl
python scripts/render_xlsx.py content.json out/文件名.xlsx                 # 默认蓝色系
python scripts/render_xlsx.py content.json out/文件名.xlsx --style soft    # 淡色系；orange 为橙色系
```

- 退出码 2：内容校验不通过，**不会生成文件**。包括：行里有字段定义之外的键（会丢数据）、值多于字段、主键为空或重复、`expect_rows` 与行数不符、工作表名非法、视图引用不存在的字段。按提示改 JSON。
- 退出码 3：文件已生成，但有公式引用或图表无法解析，按提示修正后重跑。
- 输出会列出每张数据表的“记录数 × 原始字段数”，与需求卡片核对。

自动生成的工作表：**使用说明**（第一张：分层说明、工作表目录可点击跳转、单元格颜色图例）、**字段说明**（类型、必填、可选值 / 公式、来源、填写率）、**提醒规则**、**参数**。

## ⑥ 质检交付

```bash
python scripts/review_xlsx.py out/文件名.xlsx --content content.json [--external] [--final] [--recalc]
```

1. **脚本检查**：原始数据完整性（行数、字段、原文是否被改写）、视图和仪表盘里有没有手填数字、智能列是否标注、未解析引用、不存在的工作表、无 IFERROR 的除法、占位符、合规用语（`--external`）、对外试算的免责提示；装了 LibreOffice 加 `--recalc` 查 `#REF!` `#DIV/0!`。
2. **自评**：按 `reference/quality-rubric.md` 打分，任何一项低于 4 分修改后重新渲染，最多 2 轮。
3. **交付说明**（在对话中）：
   - 每张数据表的记录数 × 字段数，与检索结果一致
   - 视图、仪表盘、提醒规则各看什么；哪些格子可以改（淡黄录入格）、改了会联动哪里
   - 智能列的依据，提醒“紫色表头的智能列待人工确认”
   - 【待补充】【请确认】的数量和位置
   - 对外文件：正式使用前按公司流程审核；试算结果以投保系统为准

## 已有工作簿：读取 → 分析 → 报告 → 回写

```bash
python scripts/read_xlsx.py read  已有.xlsx -o work/data.json        # 原样读出每张表（值 + 公式列）
python scripts/read_xlsx.py write 已有.xlsx work/updates.json -o out/已回写.xlsx
```

1. **读取**：优先读 Excel 表格对象，没有时自动找表头；输出的字段类型是推断，使用前核对。
2. **分析**：基于读出的全部记录计算，不抽样；结论里写明依据的记录数和筛选条件。
3. **报告**：需要文档或汇报时，交给 kb-to-word / kb-to-ppt，数据引用读出的原始值。
4. **回写**：只回写白名单里的列（智能列、分析结论、状态建议），按主键定位；主键找不到、目标是公式的一律跳过并列出；**另存为新文件，原文件不改。**
5. 想把旧表升级成新版（加视图、仪表盘、提醒）：用读出的 `data` 作底稿，补全字段类型和公式后重新渲染，并用 `--content` 质检确认数据一条没少。

## 不要做的事

- 不要把检索结果先总结成要点再进表；不要合并单元格；不要为了“简洁”删字段。
- 不要在视图、仪表盘里手填数字；不要对百分比列直接求和。
- 不要做 Word / PPT 式的封面、色块和海报排版。
- 不要编造费率、价格、联系方式；示例里的数据只在 `examples/` 中使用。
- 智能列不要覆盖原文列；回写不要覆盖原文件。
- 对外文件不要出现收益承诺、与存款类比、绝对化用语。
