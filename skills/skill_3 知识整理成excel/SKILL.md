# 知识整理成 Excel

把"要翻好几篇文档才能拼出来"的信息，整理成一张一眼能看懂的表。

## 流程

### 1. 确定表格结构

表格 = **对象（行）× 维度（列）**。开始检索前先确定：

| 项 | 例子 | 用户没说时 |
|---|---|---|
| 对象（每一行是什么） | 各个产品版本、各城市、各类假期 | 必须明确；不清楚就问 |
| 维度（每一列是什么） | 价格、用户数上限、适用人员、时限 | 根据对象类型提出建议列，请用户确认或直接开始 |
| 范围 | 全部产品 / 只看某条产品线 | 全部 |

用户只给了对象没给维度时，先检索一次了解有哪些信息，再提出建议的列（不超过 8 列），和用户确认一次后开始。

### 2. 逐格检索

- 先检索"对象清单"，确认一共有哪些对象，不要漏
- 再按**维度**检索（一个维度一次，能覆盖所有对象），比按对象逐个检索更省次数
- 单元格找不到就填 `【待补充】`，**不要用常识或推测填**
- 同一格多篇文档说法不一致时，用更新时间新的，并在备注里注明

检索方法同 kb-to-word 的 `reference/retrieval.md`（Retrieval 链路为主，qa_advance 核实具体数值）。

### 3. 整理成 JSON

格式见下方"内容格式"，保存为 `/tmp/kb_table.json`。

- 数字类的列（价格、数量、天数）设 `type: number`，单元格只填数字，单位写进列名（"价格（元/年）"）
- 一个单元格只放一个值；有条件的写成"600（一线城市）"这种短格式，长说明放进 `notes`
- 行数多（超过 30 行）或有明显分组时，加一列"分类"并按它排序

### 4. 生成 .xlsx

```bash
python scripts/build_xlsx.py /tmp/kb_table.json /tmp/outputs/<文件名>.xlsx
```

生成的表格：标题行、带底色的表头、边框、自动换行、按内容调整列宽、冻结表头、启用筛选；`【待补充】` 的单元格会标黄。

依赖：`openpyxl`（`pip install openpyxl`）。

### 5. 自检

```bash
python scripts/check_xlsx.py /tmp/outputs/<文件名>.xlsx
```

输出每个工作表的行列数、空单元格、`【待补充】` 数量。有空单元格时检查是漏填还是确实不适用（不适用的填"—"）。

### 6. 交付

告诉用户：
- 文件已生成，附下载
- 表格结构：多少行（对象）、哪些列（维度）
- 有多少 `【待补充】`，分别是哪些对象的哪些维度
- 有冲突的单元格采用了哪份文档的说法

## 内容格式

```json
{
  "title": "产品版本对比",
  "subtitle": "数据来源：TAP 知识库，整理日期 2026-11-16",
  "sheets": [
    {
      "name": "版本对比",
      "columns": [
        {"name": "版本", "type": "text"},
        {"name": "价格（元/用户/年）", "type": "number"},
        {"name": "适用对象", "type": "text", "width": 30}
      ],
      "rows": [
        ["标准版", 1200, "中小团队"],
        ["企业版", "【待补充】", "大型企业"]
      ],
      "notes": ["企业版价格按需报价，知识库中无统一标准"]
    }
  ]
}
```

- `type`：`text` / `number` / `percent`（填 0.15 显示为 15%）/ `date`（填 "2026-11-16"）
- `width`：可选，列宽（字符数），不填则自动
- 可以有多个工作表；每个 `name` 不超过 31 个字符

## 规则

- 不编造数值：没检索到就填 `【待补充】`。
- 价格、折扣等内部信息，在 `subtitle` 或 `notes` 里注明"内部资料，对外以正式报价单为准"。
- 文件名用中文主题加日期，比如 `产品版本对比_20261116.xlsx`。
