# 知识生成 Word 评测用例

上线前和每次修改后跑一遍。把 `<...>` 换成你们知识库里真实存在的主题。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | 根据知识库帮我写一份 <产品> 的服务方案 | 触发 kb-to-word |
| A2 | 出一份 Word 版的 <制度> 说明 | 触发 |
| A3 | <制度> 的审批时限是多少？ | 不触发，交给 qa_advance |
| A4 | 把 <项目> 做成汇报 PPT | 不触发（kb-to-ppt） |
| A5 | 帮我检查这份合同 | 不触发（compliance-check） |

## B. 需求确认

| # | 用户输入 | 期望 |
|---|---|---|
| B1 | 帮我写个方案 | 主题不明确，要追问主题；问题不超过 3 个 |
| B2 | 给 <客户> 写一份 <产品> 服务方案，3 页左右 | 信息足够，不追问，直接开始 |

## C. 内容质量

| # | 用户输入 | 期望 |
|---|---|---|
| C1 | 写一份 <知识库里有完整资料的主题> 说明文档 | 结构符合 doc-types.md 的"说明文档"；没有空章节；业务信息都能在检索结果里找到 |
| C2 | 写一份 <知识库里只有部分资料的主题> 方案 | 缺失部分标注【待补充】，交付时列出缺什么；**不编造** |
| C3 | 写一份 <知识库里完全没有的主题> 方案 | 停下来告诉用户没检索到，请用户提供关键词或资料，不生成空壳文档 |
| C4 | 写一份 <有新旧两版规定的主题> 说明 | 采用新版，交付时说明存在冲突 |
| C5 | 给客户写 <产品> 介绍 | 不出现内部系统名、内部术语 |

## D. 文件生成

| # | 检查项 | 期望 |
|---|---|---|
| D1 | 不带模板生成 | 能用 Word 正常打开；中文显示正常（不出现方框或乱码） |
| D2 | 带公司模板生成 | 页眉页脚和 Logo 保留；标题使用模板样式 |
| D3 | 内容带表格 | 表头加粗、有底色；列数和内容对齐 |
| D4 | `toc: true` | Word 里更新域后显示目录 |
| D5 | 运行 check_docx.py | 输出结构信息；有【待补充】时提示 |
