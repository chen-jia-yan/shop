# 检索方法

TAP 提供两种检索方式：Retrieval 链路和 qa_advance skill。

> ⚠️ 待你们补充：下面"调用方式"里的接口名、参数、返回字段是占位，请按 TAP 的实际接口替换。

## 选用哪种

| 场景 | 用哪个 | 原因 |
|---|---|---|
| 按章节拉取原始知识片段，用来组织成文档 | **Retrieval 链路** | 需要原文片段和多条结果，便于重新组织 |
| 某个具体问题需要一个准确的答案（如"XX 的审批时限是多少"） | **qa_advance** | 已经做好了答案生成 |
| 检索结果互相矛盾，需要确认现行规定 | **qa_advance** | 让它给出确定答案 |

生成文档时以 Retrieval 为主，qa_advance 用于补充和核实。

## 调用方式（占位，待替换）

```
Retrieval:
  调用: <TAP_RETRIEVAL_API>
  参数: query=<检索词>, top_k=<条数，建议 8-10>, filters=<可选：分类/时间>
  返回: [{id, title, content, updated_at, ...}]

qa_advance:
  调用: 按 qa_advance skill 的方式调用
  输入: 具体问题
```

## 检索策略

1. **先定大纲，再按章节检索。** 每个章节单独检索 1-3 次，检索词用章节里的具体概念，不要用整个文档主题。
   - ❌ "XX 服务方案"
   - ✅ "XX 服务 收费标准"、"XX 服务 实施流程"、"XX 服务 售后政策"
2. **一次检索结果不够时，换角度再检索**：同义词、上位概念、相关流程名。最多换 3 次，还找不到就标记 `【待补充】`。
3. **注意时效。** 同一主题有多条结果时，优先采用 `updated_at` 较新的；新旧内容有冲突的，记下来，交付时告诉用户。
4. **控制用量。** 只保留和当前章节直接相关的片段，不要把所有检索结果都塞进上下文。

## 什么情况下停下来问用户

- 主题在知识库里完全检索不到（可能是叫法不同，请用户提供关键词或相关文档名）
- 检索结果涉及多个不同的业务线或产品，无法判断用户指的是哪一个
