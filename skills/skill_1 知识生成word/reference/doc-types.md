# 常见文档类型与推荐结构

按用户要的文档类型选结构。结构是起点，可以根据检索到的内容增删章节，但不要为了凑结构写空章节。

## 方案（给客户或内部决策）

1. 背景与目标：要解决什么问题、达到什么效果
2. 方案概述：一段话说清楚整体思路
3. 具体内容：分模块展开，每个模块写"做什么、怎么做、谁负责"
4. 实施计划：阶段、时间、里程碑（建议用表格）
5. 资源与费用（如适用）
6. 风险与应对（建议用表格：风险 / 影响 / 应对措施）
7. 附录：相关政策、参数

读者是客户时：去掉内部术语和内部系统名，突出客户收益。

## 说明文档（产品、服务、系统、政策说明）

1. 概述：是什么、适用于谁
2. 主要内容：功能、条款或规则，按重要程度排序
3. 使用方法或办理流程（用编号列表）
4. 常见问题（问答形式）
5. 联系方式或支持渠道

## 报告（工作汇报、分析报告）

1. 摘要：3-5 句话讲结论，领导只看这一段也能明白
2. 现状与数据
3. 问题与分析
4. 建议与下一步
5. 附录：数据明细

## 培训材料

1. 培训目标：学完能做什么
2. 知识要点：按学习顺序排列，每个要点配一个实际例子
3. 操作步骤（编号列表，必要时配注意事项）
4. 常见错误与注意事项
5. 自测题（3-5 道，附答案）

## 制度/流程文件

1. 目的与适用范围
2. 术语定义
3. 职责分工（表格：角色 / 职责）
4. 流程步骤（编号列表，写清楚每一步的负责人和时限）
5. 相关表单与附件
6. 生效日期与版本记录

## 不在以上类型时

按"读者最想先知道什么"排列章节：结论或要点放前面，背景和细节放后面。
