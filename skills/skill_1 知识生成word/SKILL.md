# 知识生成 Word

把知识库里的内容组织成一份可以直接交付的 Word 文档。内容必须来自知识库，不能凭空编写业务信息。

## 流程

### 1. 明确需求

开始检索前，确认以下信息。用户已经说清楚的不要再问；缺的一次问完，最多问 3 个问题。

| 信息 | 用途 | 用户没说时的默认值 |
|---|---|---|
| 文档类型 | 决定结构，见 `reference/doc-types.md` | 按用户描述判断，判断不了再问 |
| 读者 | 决定措辞和详略（客户/内部同事/领导） | 内部同事 |
| 主题范围 | 决定检索什么 | 必须明确，不能默认 |
| 篇幅 | 控制内容量 | 3-5 页 |
| 模板 | 决定样式 | `templates/` 下的默认模板；没有就用脚本内置样式 |

### 2. 检索知识

按 `reference/retrieval.md` 的方法检索。要点：

- 先列出文档大纲，再**按章节分别检索**，不要只用一个大问题检索一次。
- 每个章节记录用到了哪些知识条目（来源追溯由平台处理，这里只需保证内容来自检索结果）。
- 检索不到的章节，**不要编造**，在文档里写 `【待补充：<缺什么>】`，并在最后告诉用户。

### 3. 生成文档内容

把内容整理成 JSON 文件（格式见下方"内容格式"），保存为 `/tmp/kb_doc.json`。

写作要求：
- 面向读者写，不要照搬知识条目原文的结构和口吻。
- 多篇知识有冲突时，以更新时间较新的为准，并在交付时告诉用户冲突在哪里。
- 能用表格说清楚的（参数、对比、步骤和负责人），用表格。
- 不写空话套话，每段都要有具体信息。

### 4. 生成 .docx

```bash
python scripts/build_docx.py /tmp/kb_doc.json /tmp/outputs/<文件名>.docx --template templates/<模板>.docx
```

- 不传 `--template` 时使用内置样式（宋体/微软雅黑，A4）。
- 依赖：`python-docx`。如果报 `ModuleNotFoundError`，执行 `pip install python-docx`。

### 5. 自检

```bash
python scripts/check_docx.py /tmp/outputs/<文件名>.docx
```

脚本会输出：标题结构、字数、表格数、`【待补充】` 占位数量、空章节。
如果发现空章节或格式问题，修改 JSON 后重新生成。

### 6. 交付

告诉用户：
- 文件已生成，附下载
- 文档结构（一行列出章节）
- 有哪些 `【待补充】`，分别缺什么
- 知识之间如果有冲突，说明采用了哪一份

最后可以推荐下一步，比如"需要做成汇报 PPT 吗？"（kb-to-ppt 上线后）。

## 内容格式

```json
{
  "title": "XX 服务方案",
  "subtitle": "面向 XX 客户",
  "meta": {"编制部门": "XX 部", "日期": "2026-11-16", "版本": "V1.0"},
  "toc": true,
  "blocks": [
    {"type": "heading", "text": "一、项目背景", "level": 1},
    {"type": "paragraph", "text": "正文，支持 **加粗**。"},
    {"type": "bullets", "items": ["要点一", "要点二"]},
    {"type": "numbered", "items": ["第一步", "第二步"]},
    {"type": "table", "header": ["项目", "说明"], "rows": [["A", "B"]]},
    {"type": "note", "text": "提示或注意事项"},
    {"type": "page_break"}
  ]
}
```

- `heading.level`：1-3
- `toc`：是否在开头插入目录域（用户在 Word 里按 F9 更新后显示页码）
- `meta`：可选，显示在标题下方

## 规则

- 不编造业务内容：没检索到就写 `【待补充】`。
- 不要把检索的原始结果整段粘贴进文档，要重新组织。
- 文件名用中文主题加日期，比如 `XX服务方案_20261116.docx`。
