# 在 TAP 中取版本、查影响范围

> 下面的表名、字段名、接口参数是**占位写法**，以 TAP 实际库表和接口文档为准。上线前请平台同事把真实名称补进本文件。

## 1. 取得新旧两个版本（MySQL 文档元数据）

需要的字段：文档 ID、文档名称、版本号、状态（草稿 / 待审核 / 已生效 / 已废止）、生效日期、发布日期、负责人 / 归属部门、文件存储地址。

```sql
-- 占位示例：按文档名找出最近两个已生效版本
SELECT <doc_id>, <version>, <status>, <effective_date>, <owner_dept>, <file_url>
FROM   <文档版本表>
WHERE  <doc_name> = '<文档名称>' AND <status> IN ('<已生效>', '<待审核>')
ORDER  BY <effective_date> DESC
LIMIT  2;
```

判断规则：

- **新版**：用户指定的版本；没指定时取“待审核”或最新“已生效”。
- **旧版**：新版之前最近一个“已生效”版本。不要拿草稿当旧版。
- 两个版本的 `effective_date`、`version`、`owner_dept` 分别填入 `diff_docs.py` 的 `--effective-date`、`--old-label/--new-label`，归属部门写进 notes.json 的 `department`。
- 新版走 TAP 审核流程时，本报告可作为审核附件；**本 skill 不直接改知识库内容**，所有更新按处置计划由责任部门走正常审核。

## 2. 查影响范围：三种来源，按可得程度使用

| 来源 | 适合 | 怎么用 |
|---|---|---|
| 知识库批量导出 | 有导出权限、范围明确（如“某产品全部知识”） | 导成 jsonl（每行 doc_id / title / type / owner / url / updated / text），直接 `--corpus` |
| TAP Retrieval | 没有导出、或全库范围 | 用 refs.json 的 `queries` 逐条检索，结果存 JSON 后 `--corpus` |
| qa_advance | 重大 / 较大变更的兜底确认 | 把变更前的口径当问题问（如“xx 产品等待期多少天？”），看答案是否还是旧值 |

### 2.1 用 Retrieval 补查

`find_refs.py` 会为每条实质变更生成两类检索语句：

- **stale**（找含旧值的内容）：`<范围词> <上下文词> <旧值>`，如“xx 产品 等待期 90 天”；以及被删除的原文短语。
- **related**（找相关内容）：`<范围词> <术语1> <术语2> <术语3>`。

建议参数（以实际接口为准）：每条取前 10–20 条，召回模式用混合检索（关键词 + 向量），**过滤掉被修订文档本身的所有版本**，只保留已生效内容。

把每次检索的返回合并成一个 JSON（数组，或 `{"results": [...]}`），每条至少包含：

```json
{"doc_id": "...", "title": "...", "type": "FAQ", "owner": "客户服务部", "url": "...", "updated": "2025-08-01",
 "snippet": "命中的片段或全文"}
```

字段名不同也可以：`content` / `snippet` / `answer` / `body` 都会当作正文，`question` 会并入标题。

### 2.2 用 qa_advance 兜底

对每条重大 / 较大变更，至少问一个问题，问法是**站在客户或一线人员角度、问变更前的口径**：

| 变更 | 问题 |
|---|---|
| 等待期 90 天 → 30 天 | “xx 产品的等待期是多少天？” |
| 删除某项责任免除 | “xx 产品在什么情况下不赔？” |
| 理赔时限调整 | “xx 产品理赔多久能到账？” |

答案里仍是旧口径的，把答案引用的来源文档加入语料；答案正确但引用了旧文档的，同样加入。qa_advance 的返回存 JSON（含 `question`、`answer`、来源列表）后 `--corpus`。

## 3. 匹配判定与误报排除

| 结果 | 判定 | 常见误报 | 怎么排除 |
|---|---|---|---|
| 疑似过时 | 同一句同时有上下文词和旧值、且没有新值；或含被删除的原文短语 | 另一款产品的同名参数；历史说明（“原等待期为 90 天”） | 加 `--scope-term` 限定产品；在 notes.json 中写说明，或在导出里剔除 |
| 相关 | 同一句出现相关术语 | 泛泛提到术语的通用说明 | 影响度里相关内容封顶 20 分，不会主导级别 |

**没查不等于没影响**：语料不完整时，报告会写明“影响范围仅按变更类别推断”，并附检索语句清单。
