# 变更识别口径

本文说明脚本怎样把两个版本拆成“变更”，以及你在复核时要注意的边界情况。参数都在 `tap-config/impact.json` 与 `rules.json`（`impact` 部分）。

## 1. 块：比对的最小单位

| 块类型 | 来源 | 说明 |
|---|---|---|
| heading | 标题样式、`#` 标题、或匹配 `heading_patterns` 的段落（“第三章”“一、”“（二）”“2.1”…） | 用来维护章节路径，标题文字本身改了也算一处变更 |
| para | 普通段落、列表项 | 以“第 x 条”开头的段落会记下条款号（`anchor_pattern`），配对时同条款号加分 |
| table | 表格的每一行 | 首行视为表头，后续行按“表头：值”拼成文本，便于看出哪一列变了 |

每个块带：章节路径（如“第二章 保险责任 / 第五条”）、顺序号、原文、规范化文本（全角半角统一、去多余空白）。

## 2. 对齐与变更类型

| 类型 | 判定 | 报告里怎么写 |
|---|---|---|
| 修改 modified | 同一区间内相似度 ≥ `match_threshold`（0.45）且块类型一致 | 有数值变化写“{上下文}由 A 调整为 B”；否则写“将‘x’改为‘y’”“删去‘x’”“增加‘y’” |
| 新增 added | 新版中没有可配对的块 | “新增：……” |
| 删除 removed | 旧版中没有可配对的块 | “删除：……” |
| 移动 moved | 跨区间配上、相似度 ≥ `move_threshold`（0.95）且去标点后完全相同 | “由 A 位置移至 B 位置”，重要度设上限 |
| 移动并修改 moved_modified | 跨区间配上但内容有差异 | 先写位置变化，再写内容变化 |

**措辞调整（minor）**：只改了标点空格，或相似度 ≥ `similarity_minor`（0.92）且没有任何实质信号。措辞调整不进入正文分析，列在附录一，级别固定为轻微。

## 3. 信号

| 信号 | 识别方式 | 典型例子 | 复核要点 |
|---|---|---|---|
| 数值 number | 抽出“数字 + 单位”（单位表 `number_units`，长的优先），中文数字转阿拉伯数字，日期先屏蔽；按“上下文词 + 单位”配对新旧值 | 等待期 90 天 → 30 天；给付比例 80% → 100% | 一段里有多个数值时，确认配对没有串（如“30 天”和“180 天”） |
| 数值大幅变动 | 变动幅度 ≥ `number_big_ratio`（50%） | 免赔额 1 万 → 5 千 | — |
| 日期 date | YYYY-MM-DD、YYYY年M月D日 等 | 施行日期调整 | 区分“生效日期”与“举例日期” |
| 义务表述 obligation | 强词（必须、应当、不得…）与弱词（可以、有权、原则上…）的增减 | “应当在 10 日内”→“可以在 10 日内”为放宽 | 判断对客户是利是弊，写进变化说明 |
| 否定词 negation | 只看**被改动的字词**里有没有“不、未、非、无” | “不承担”→“承担” | 最容易误报：句式调整也会带出否定词，必须读原文 |
| 适用范围 scope | 改动处出现“仅、限于、不包括、以上、以内、最高…” | “60 周岁以下”→“65 周岁以下” | 范围扩大还是收窄 |
| 术语 terms | 命中类别关键词（`categories[].keywords`），优先看改动处，其次看整段 | “责任免除”“现金价值” | 决定变更类别 |

## 4. 类别

12 个类别（保险责任、责任免除、重要期间、保费与费率、投保规则、核保规则、理赔规则与时效、退保与现金价值、监管与合规、销售与宣传、流程与时效、组织与职责），都没命中时归“其他”。

- 一处变更可以属于多个类别，**主类别取权重最高的**，处置事项与受影响对象取最主要的 `action_categories_max`（2）个类别。
- 认错类别时（例如“理赔材料里提到保险金”被认成保险责任），在 notes.json 里用 `category` 改正。
- 新业务线（如健康管理服务、养老社区权益）可以在配置里加类别，不需要改脚本。

## 5. 已知局限：脚本会打复核提示

下面这些盲区，脚本会在对应变更上打复核提示（`review_flags`）或在比对结果里给出警告（`meta.warnings`）。读原文确认后，把结论写进判断的 `diff_review`。怎么处理见 `methods.md` 第 4 节。阈值在 `rules.json` 的 `impact.review_flags`。

| 盲区 | 脚本怎么提示 |
|---|---|
| 跨段落拆分 / 合并：一段拆成两段，会被识别为“修改 + 新增” | `split_merge`：新增 / 删除的内容大部分包含在相邻的修改条里 |
| 语义等价改写：“不予赔付”→“不承担给付责任”，可能被误报为否定词变化 | `paraphrase`：整体相似度高、但有否定或义务信号 |
| 表格列结构变化：增删列会让整张表每行都变 | `table_shape`：同一表格的表头（列）变了 |
| 图片、公式、附件、扫描页没有参与比对 | 文档级警告：“含 n 处非文字内容”“第 n 页没有文字” |

反方向也要看：**被判为措辞调整的，有没有其实是实质变更的**，比如“或”改“且”、“日”改“工作日”。脚本对这类变化只能部分识别，要靠读原文。
