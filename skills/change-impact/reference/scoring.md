# 评分与定级口径

所有数字都在配置里（`tap-config/impact.json` 的 `signals`、`impact_points`、`floors`，`rules.json` 的 `impact.weights`、`impact.levels`），这里写的是出厂值。报告会把每条变更的加分项逐条写出来，读者能看懂“为什么是这个级别”。

## 1. 重要度（0–100）：这处改动本身有多要紧

| 项 | 分 | 说明 |
|---|---|---|
| 类别权重 | 6–32 | 责任免除 32、保险责任 30、监管与合规 28、重要期间 26、保费与费率 26、退保与现金价值 24、理赔 22、投保规则 20、核保规则 20、销售与宣传 16、流程与时效 14、组织与职责 8、其他 6 |
| 数值变化 | +20 | |
| 数值变动幅度 ≥ 50% | +10 | |
| 否定词变化 | +20 | |
| 义务表述变化 | +15 | |
| 删除含关键术语的内容 | +15 | |
| 适用范围措辞变化 | +12 | |
| 新增含关键术语的条款 | +10 | |
| 日期变化 | +10 | |
| 措辞调整 / 仅移动位置 | 上限 15 | |

## 2. 影响度（0–100）：改动会波及多大范围

| 项 | 分 | 说明 |
|---|---|---|
| 知识库中含旧值的内容 | 每篇 +12，最多 48 | 这些内容不改就会对外给出错误口径 |
| 需复核的相关内容 | 每篇 +4，最多 20 | |
| 对客 | +15 | 类别标记为 customer（客户权益、对客材料） |
| 涉及系统参数 | +10 | 类别标记为 system，且改动含数值、日期或义务表述 |
| 距生效日 ≤ 30 天 | +15 | 已经生效的同样加分，并提示“需立即处置” |
| 距生效日 ≤ 90 天 | +8 | |

**没有提供语料时影响度会偏低**，报告会提示“影响范围仅按类别推断”。这时不要下“影响很小”的结论，先补查。

## 3. 综合分与级别

综合分 = 重要度 × 0.55 + 影响度 × 0.45

| 级别 | 综合分 | 处置要求（`level_sla`） |
|---|---|---|
| P0 重大 | ≥ 65 | 立即启动，生效日前全部完成；需管理层知悉 |
| P1 较大 | ≥ 48 | 3 个工作日内启动，生效日前完成 |
| P2 一般 | ≥ 28 | 生效日前完成更新 |
| P3 轻微 | 其余 | 随下次例行修订一并处理 |

## 4. 级别下限（高风险情形不会被分数“稀释”）

| 情形 | 涉及类别 | 至少 |
|---|---|---|
| 否定词变化 | 保险责任、责任免除 | 较大 |
| 删除含关键术语的内容 | 责任免除、保险责任 | 较大 |
| 数值变化 | 保险责任、重要期间、保费与费率、退保与现金价值 | 较大 |
| 义务表述变化 | 责任免除、监管与合规 | 较大 |
| 数值变化 | 理赔、投保规则、核保规则 | 一般 |
| 适用范围变化 | 保险责任、责任免除 | 一般 |

## 5. 校准参考（出厂参数下的典型结果）

| 例子 | 重要度 | 影响度 | 综合分 | 级别 |
|---|---|---|---|---|
| 等待期 90 天 → 30 天，3 篇内容含旧值，距生效 20 天 | 56 | 76 | 65 | 重大 |
| 同上，但未提供语料、未给生效日 | 56 | 25 | 42 | 较大（下限） |
| 责任免除删除一项（“不承担”整句删去），2 篇含旧值 | 47 | 39 | 43 | 较大（下限） |
| 理赔核定时限 5 个工作日 → 3 个工作日 | 42 | 25 | 34 | 一般 |
| 审批职责由 A 部门调整为 B 部门 | 8 | 0 | 4 | 轻微（建议人工看是否需升级） |

## 6. 人工调整

- 自动级别只是初筛。重大 / 较大必须由分析人读原文确认；轻微里如果有“只改一个字但改变责任范围”的（如“或”→“且”），要手工升级。
- 在 notes.json 里写 `overrides`，改级别或忽略**必须写 reason**；报告保留“人工调整：原因（自动评级为 x）”。
- 某个产品线口径确实不同（如团险更看重投保规则），用 `--config` 叠加专门配置，不要直接改出厂配置，并在数据来源里注明。
