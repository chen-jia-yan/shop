# 提交方式配置

> ⚠️ 待核实：TAP 是否有写入接口。已确认：**写入内容必须先审核，审核通过后才生效。**

```
SUBMIT_MODE = file
```

可选值：`api` / `file`。核实之前保持 `file`，skill 可以正常使用。

---

## 方式 A：通过接口提交（`api`）

### 核实清单

- [ ] TAP 是否有"提交待审核内容"的接口（不是直接发布的接口）
- [ ] 接口需要哪些字段：标题、正文格式（Markdown/HTML）、分类、标签、提交人……
- [ ] 提交人身份怎么传：用当前登录用户，还是服务账号
- [ ] 返回什么：提交编号、审核状态、查看链接
- [ ] 审核人是谁：按分类自动分配，还是固定的管理员
- [ ] 审核结果是否会通知提交人

### 调用方式（占位，待替换）

```
调用: <TAP_SUBMIT_API>
参数:
  title       = <json.title>
  content     = <生成的 .md 文件内容>
  category    = <json.category>
  tags        = ["会议纪要", <项目名>]
  meta        = <生成的 .json 文件内容>（如果接口支持结构化字段）
  status      = pending_review     # 必须是待审核，不能直接发布
返回:
  submission_id, status, review_url
```

### 要求
- **只能提交为待审核状态**。如果接口有"直接发布"的选项，不要使用。
- 提交失败时，自动改为 `file` 方式，把文件给用户，不要让用户的内容丢失。

## 方式 B：生成文件，用户自行上传（`file`）

生成的两份文件交给用户，并附上上传说明：

> 纪要已整理好，文件在下方。请到 TAP 的 <提交入口名称，待补充> 上传 `.md` 文件，分类选择"<category>"。提交后会进入审核，审核通过后在知识库中可见。

> ⚠️ 待补充：TAP 上传入口的名称或链接。
