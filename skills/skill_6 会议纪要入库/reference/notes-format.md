# 纪要提取规则与格式

## 三类内容怎么判断

### 已决定（decisions）
满足任意一条：
- 负责这件事或有决定权的人明确表示同意："可以""就这么办""定了"
- 会上明确宣布结论："那就定在 12 月上线"
- 对于小范围会议没有明确决策人时，**负责执行的人**都明确同意

每条要写：
- `content`：决定了什么（一句话，具体）
- `basis`：依据——谁提出、谁同意、理由是什么

例：
> 原文："李四：我建议先做账单页面，大部分投诉都跟它有关。张三：同意，先做这个。"
> → 已决定：先做账单页面。依据：李四提出（投诉大多与账单相关），张三同意。

### 待定（open_items）
- 有人提出、但没人明确同意（**没有反对 ≠ 同意**）
- 明确说"下次再讨论""会后再确认"
- 提出了问题、没有得到回答

每条写：`content`（什么还没定）、`note`（卡在哪里、下一步谁跟进，原文有才写）

### 待办（action_items）
- 原文中有明确要做的事
- `owner`：原文明确说了谁来做才填，否则留空
- `due`：原文明确说了时间才填，"尽快""下周"这类原样保留，不要自己换算成日期
- 不要从"讨论过 XX"推出"某人要做 XX"

## 不入库的内容
- 寒暄、闲聊、技术故障（"听得到吗"）
- 讨论过程中被否定的方案，除非否定的原因有参考价值（写进对应决定的 `basis`）
- 敏感信息：个人薪资、绩效评价、身份证号、手机号、具体合同金额等——默认去掉，向用户确认后才保留

## 草稿 JSON 格式

```json
{
  "title": "XX 项目第三阶段评审会",
  "date": "2026-11-18",
  "category": "项目/XX 项目",
  "attendees": ["张三", "李四", "王五"],
  "summary": "2-3 句话的会议概要",
  "decisions": [
    {"content": "第四阶段 12 月 15 日启动", "basis": "张三提出，项目负责人王五同意，原因是第三阶段遗留问题需两周处理"}
  ],
  "open_items": [
    {"content": "第四阶段是否增加移动端", "note": "需要先确认预算，李四会后跟进"}
  ],
  "action_items": [
    {"task": "整理第三阶段遗留问题清单", "owner": "李四", "due": "11 月 22 日"},
    {"task": "确认移动端预算", "owner": "", "due": ""}
  ],
  "uncertain_terms": ["“启明系统”（转写识别，待确认）"],
  "source": "Teams 会议转写"
}
```

必填：`title`、`date`、`category`、`summary`；`decisions` / `open_items` / `action_items` 至少有一项不为空。
