# 会议纪要入库

把会议里定下来的事沉淀进知识库。**提交后进入审核，审核通过才对其他人可见**，所以要在提交前让用户确认内容准确。

## 流程

### 1. 拿到会议内容

用户可以提供：
- 粘贴的会议纪要、Teams 转写文本、聊天记录
- 上传的文件（Word/PDF/txt）。Word/PDF 先提取文字。

同时确认（用户没说的从内容里推断，推断不出再问，一次问完）：
- 会议主题、日期
- 归属：属于哪个项目/部门/知识分类（决定提交到哪里）

### 2. 提取内容

按 `reference/notes-format.md` 的规则提取。核心是**区分三类**：

| 类型 | 判断标准 |
|---|---|
| **已决定** | 有决定权的人明确同意，或会上明确说"就这么定" |
| **待定** | 有人提出、但没有明确同意，或明确说"下次再定" |
| **待办** | 有明确的要做的事；负责人和截止时间**只在原文提到时才填** |

没有说清楚的，宁可放进"待定"，也不要升级成"已决定"。

### 3. 生成草稿，请用户确认

把草稿整理成 JSON（格式见 `reference/notes-format.md`），保存为 `/tmp/notes_draft.json`，然后运行检查：

```bash
python scripts/build_submission.py /tmp/notes_draft.json --check
```

脚本会列出：缺负责人或截止时间的待办、没有依据的决定、可能的敏感信息。

把草稿以易读的形式展示给用户，**同时列出脚本发现的问题**，请用户：
- 确认"已决定"的内容是否准确
- 补充缺失的负责人、截止时间（也可以选择保持空白）
- 确认是否有不该入库的内容

**用户没有明确确认前，不要提交。**

### 4. 提交审核

用户确认后，按 `reference/submission.md` 里的 **`SUBMIT_MODE`** 提交：

```bash
python scripts/build_submission.py /tmp/notes_draft.json --out /tmp/outputs/
```

脚本生成两份文件：
- `<主题>_<日期>.md`：给审核人和读者看的纪要正文
- `<主题>_<日期>.json`：给系统用的结构化数据

- `api`：调用 TAP 写入接口，把内容提交到审核队列，记下返回的提交编号。
- `file`：把两份文件给用户，告诉用户在哪里上传提交（见 submission.md）。

### 5. 告诉用户结果

- 提交成功（或文件已生成）
- 当前状态：**待审核**，审核通过后才会在知识库中可见
- 提交编号（api 模式）或上传方法（file 模式）
- 待办清单再列一次，方便用户直接转发给相关负责人

## 规则

- 不编造：负责人、截止时间、决定内容都只来自原文。
- 转写文本里的人名、项目名可能识别错误，拿不准的标注 `（待确认）`，并在第 3 步提醒用户。
- 敏感信息（个人薪资、绩效评价、身份证号、手机号、合同金额等）默认不写入，在第 3 步向用户确认。
- 闲聊、与结论无关的讨论过程不入库，只保留结论和必要的理由。
- 用户只要摘要、不要入库时，做完第 3 步就停止。
