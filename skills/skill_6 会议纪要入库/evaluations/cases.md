# 会议纪要入库评测用例

上线前和每次修改后跑一遍。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | （粘贴会议纪要）帮我整理入库 | 触发 |
| A2 | （上传 Teams 转写文件）提取一下待办 | 触发 |
| A3 | 明天要开会，帮我准备一下 | 不触发（meeting-prep） |
| A4 | （上传产品手册）帮我入库 | 不触发（doc-ingest） |
| A5 | （粘贴纪要）帮我总结一下就行 | 触发，但只做到第 3 步，不提交 |

## B. 提取准确性（用 `examples/transcript.txt`）

| # | 检查项 | 期望 |
|---|---|---|
| B1 | "12 月 15 日启动" | 归为**已决定**，依据写明张三提出、王五同意 |
| B2 | "要不要做移动端" | 归为**待定**（王五明确说先不定） |
| B3 | "测试环境换新服务器" | 归为**待定**（提出后无人回应，没有反对 ≠ 同意） |
| B4 | "遗留问题清单" | 待办，负责人李四，截止"11 月 22 日前" |
| B5 | "确认移动端预算" | 待办，负责人和截止时间**留空**（原文没说） |
| B6 | "启明系统" | 标注为待确认名称 |
| B7 | "大家好""今天就到这里" | 不入库 |

## C. 确认与提交

| # | 场景 | 期望 |
|---|---|---|
| C1 | 草稿生成后 | 先展示给用户确认，列出缺负责人/截止时间的待办；**未确认不提交** |
| C2 | 用户说"可以，提交吧" | 生成 .md 和 .json；`SUBMIT_MODE=file` 时给出文件和上传说明 |
| C3 | `SUBMIT_MODE=api` | 提交状态为待审核（pending_review），返回提交编号；不使用直接发布 |
| C4 | `SUBMIT_MODE=api`，接口失败 | 改为生成文件交给用户，内容不丢失 |
| C5 | 交付消息 | 说明"待审核，通过后才可见"；再列一次待办清单 |

## D. 脚本

| # | 命令 | 期望 |
|---|---|---|
| D1 | `build_submission.py examples/draft.json --check` | 无阻断问题；警告：待办 2 缺负责人和截止时间；"启明系统"待确认 |
| D2 | `build_submission.py examples/draft.json --out out/` | 生成 `示例项目第三阶段评审会_2026-11-18.md` 和 `.json`，json 中 `review_status` 为 `pending_review` |
| D3 | 删掉草稿里的 `category` 后运行 | 报阻断问题，退出码 1，不生成文件 |
| D4 | 在 summary 里加一个手机号后运行 | 警告"可能含敏感信息（手机号）" |
