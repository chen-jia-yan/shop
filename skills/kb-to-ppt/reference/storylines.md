# 8 种保险业务汇报的叙事结构

每种结构给出：适合场合 → 页面顺序（括号内为推荐版式）→ 讲述要点。页数为 15 分钟左右的参考。

## 1. 经营分析汇报 `analysis`（管理层，10-14 页）
封面 → 目录 → **执行摘要**（exec_summary，自动汇总）→ 核心结论（kpis + 趋势 / 基准 + takeaway）→ 章节：经营概览（chart + insight、donut + insight）
→ 章节：区域与渠道（chart + target + alert、waterfall 差异归因、tilemap 区域分布、table）→ 风险评估（matrix）→ 章节：下一步举措（process、roadmap）
→ **需要决策的事项**（summary）→ 结束
**要点**：第一页内容页就给结论；关键页标 key 进执行摘要；有目标的图画目标线并点明问题项；数据尽量 data_from 引用经营看板；结尾必须是请管理层决策的具体事项（decisions）。

## 2. 工作汇报 `work_report`（上级/部门，8-12 页）
封面 → 本期结论（statement 或 kpis）→ 完成情况（bars / gauge）→ 亮点（icon_grid）
→ 问题与原因（compare 或 matrix）→ 下期计划（timeline）→ 需要的支持（summary）→ 结束
**要点**：用“结论 → 依据 → 下一步”组织；问题要配原因和对策，不只罗列。

## 3. 方案汇报 `proposal`（评审/客户，10-15 页）
封面 → 背景与问题（statement、big_number）→ 目标（kpis）→ 方案总览（layers 或 hierarchy）
→ 方案细节（process、icon_grid）→ 方案对比（compare）→ 实施计划（timeline）→ 资源与风险（table、matrix）
→ 待决策事项（summary）→ 结束
**要点**：先讲“为什么要做”，再讲“怎么做”；方案对比要给推荐和理由。

## 4. 培训课件 `training`（代理人/新人，15-20 页）
封面 → 目录 → 学习目标（bullets）→ 章节：知识讲解（statement、pyramid、venn、icon_grid）
→ 章节：怎么用（coverage 保障责任、compare、radar 版本对比、case 客户案例、funnel）→ 章节：注意事项（qa 问答话术、bullets 合规底线）
→ 课后任务（summary）→ 结束
**要点**：每章先给一句话的核心观点（statement）；多用对比和案例（案例标示例）；话术页列出规范回答和避免说法；最后布置可检查的任务。

## 5. 产品介绍 `product`（销售/客户，8-12 页）
封面 → 一句话介绍（statement）→ 产品亮点（icon_grid）→ 保障责任（coverage）
→ 适合谁（columns 或 case）→ 版本对比（radar + 对比表）→ 投保与理赔（process 或 journey）→ 重要提示（disclaimer，对外自动插入）
→ 结束（含咨询方式）
**要点**：对外版本必须有犹豫期、等待期、责任免除和“以保险合同条款为准”；不出现收益承诺和绝对化用语。

## 6. 项目进展 `project`（项目组/管理层，8-12 页）
封面 → 总体进度（gauge + insight）→ 路线图（roadmap，now 标当前）→ 各模块进度（bars）
→ 风险与问题（matrix）→ 下阶段计划（process）→ 需要协调的事项（summary）→ 结束
**要点**：进度用数字说话；风险写应对措施和责任人。

## 7. 客户说明会 / 启动会 `customer` / `kickoff`（6-10 页，暖阳渐变主题）
封面 → 欢迎与目的（statement）→ 我们能为您做什么（icon_grid）→ 服务流程（cycle 或 process）
→ 关键数字（big_number）→ 常见问题（bullets）→ 结束（联系方式）
**要点**：语气亲和，少用术语；每页字更少、图更大。

---

## 写标题的方法

| 话题式（不要） | 结论式（要） |
|---|---|
| 三季度经营情况 | 三季度<核心指标><数值>，<超额/未>完成季度目标 |
| 区域分析 | <某区域>是唯一未完成目标的区域 |
| 产品亮点 | 六个亮点，每个都能对应客户的一个顾虑 |
| 实施计划 | 三项专项按月推进，12 月中旬全部落地 |

检验方法：把所有标题连起来读一遍，应该能听懂整个汇报。

## 8. 服务改进 / 理赔服务 `service` / `claims`（管理层或服务团队，8-12 页，康护青绿主题）
封面 → 执行摘要 → 服务指标（kpis + 基准条）→ 客户旅程与痛点（journey）→ 问题分布（tilemap 或 chart + alert）
→ 原因（matrix）→ 改进路线（roadmap）→ 需要协调的事项（summary）→ 结束
**要点**：痛点用投诉台账或服务数据佐证（data_from）；每个痛点对应一项改进动作和责任人。
