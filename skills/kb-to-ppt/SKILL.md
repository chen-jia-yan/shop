# 知识生成 PPT

目标是交付一份**拿去就能讲**的演示文稿：故事线清楚，每页一个结论，图示代替大段文字，
品牌视觉、留白充足，动画克制流畅，每页都有可以照着讲的备注。

```
① 读懂需求 → 需求卡片（听众、场合、时长、希望听众做什么、主题）
② 搭故事线 → 页面大纲（每页一句结论 + 选定版式），先给用户确认
③ 按页检索 → 证据台账（每个数字都有出处；能从 Excel 工作簿取数的直接引用）
④ 组装内容 JSON
⑤ 渲染 → .pptx + 构建报告（标题体检、时长、问题清单）
⑥ 质检交付
```

---

## ① 读懂需求 → 需求卡片

| 项 | 判断 | 影响 |
|---|---|---|
| 听众 | 管理层 / 同事 / 代理人 / 客户 | 结论先行程度、术语、对内对外 |
| 场合与时长 | 15 分钟汇报 ≈ 8-12 页；30 分钟培训 ≈ 15-20 页 | 页数；写进 `meta.duration_min`，超时会提示 |
| 目的 | 听完要决策、要执行、要理解，还是要购买 | 结尾页的写法；要决策的写 `decisions` |
| 对内 / 对外 | 对外：`meta.external: true` | 自动插入“重要提示”页、合规用语检查、示例水印 |
| 主题 | 7 套任选，见 `reference/design-system.md`；不指定时按汇报类型默认 | `meta.theme` |

```
📋 需求卡片
听众：管理层｜场合：季度经营会，约 20 分钟｜目的：批准三项专项｜对内
页数：约 14 页｜主题：信赖科技蓝｜重点：华东、价值率、继续率｜需要执行摘要
```

主题由用户决定：问一句“用哪套主题？”并列出 7 套名称和适用场合；用户没有偏好时按 `deck_type` 默认。

## ② 搭故事线 → 页面大纲（最重要的一步）

从 `reference/storylines.md` 选叙事结构，再写大纲。**先写出每页的标题，再决定版式**：

- **标题是一句结论**：“华东是唯一未完成目标的区域”，不是“区域情况”。只读所有标题就能听懂整个故事。
  数据页的标题要带数字；标题不超过 28 字，细节放副标题（渲染时会做标题体检）。
- **一页只讲一件事**；需要两件事就拆两页。
- **每页选一个最能证明这句结论的版式**（`reference/elements.md` 有对照表）。不确定时 `layout` 写 `auto`。
- 最重要的 3-6 页标 `key: true`：执行摘要和精简版都优先用它们；有问题的页标 `alert: true`（摘要里标红）。
- 管理层汇报加 `meta.exec_summary`：渲染时自动把各页结论汇总成一页，带页码跳转和“需要决策”。
- 用章节页（section）分 3-5 章；2 章以上自动生成目录页（显示每章页数和讲述时长）。
- 结尾用 summary 列出行动项（谁、做什么、什么时候）和需要决策的事项，再接 end。

**大纲先在对话里给用户确认**（标题列表 + 每页版式 + 预计时长），用户说“直接做”则跳过确认。

## ③ 按页检索 → 证据台账

方法同 `kb-to-word/reference/retrieval.md`：逐页检索，数字、时限、比例必须有出处；
查不到写【待补充：XX】（渲染后高亮）；资料冲突取最新，关键数据写【请确认】。

**数据在 Excel 里的，直接引用**：内容页写 `data_from`，图表、进度条、方块地图、瀑布图、表格的数据从工作簿读取，
口径与表格一致，并自动写“数据来源”脚注（格式见 elements.md）。

## ④ 组装内容 JSON

格式见 `reference/elements.md`。写作要点：

- **字少图多**：每页正文一般不超过 120 字；要点不超过 6 条，超过 8 条会被自动拆页。
- **强调要克制**：标题里用 `**…**` 标出最关键的几个字（显示为强调色）；一页强调不超过 2 处。
- **数字自动高亮**：说明文字里的数字和单位会自动加粗并用强调色。
- **图表要“会说话”**：有目标的写 `target`（画目标线），有问题项的写 `alert: "auto"`（自动找出低于目标的最低项并换色），
  `callout: "auto"` 自动生成标注框（如“华东 89.7%，差 10.3pct”）。
- **图标**：每个条目可指定 `icon`（41 个）；不指定时按文字关键词自动匹配，同一页内不重复。
- **右侧“关键发现”栏**（`insight`）写 2-3 条解读；**底部“结论条”**（`takeaway`）写这一页最想让听众记住的一句话。
- **数据来源**：页面级 `source` 显示在左下角；**示例数据**：`meta.sample: true` 时案例、保障责任、雷达页自动加“示例样本”标记，单页可用 `sample` 覆盖。
- **每页写 notes**（演讲备注）：口语化，60-150 字；讲述时长按备注字数估算（约 220 字 / 分钟）。
- **对外材料**：不承诺收益、不与存款类比、不用绝对化用语；`meta.external: true` 时在结束页前自动插入“重要提示”页，
  条目按 `meta.product_kind`（protection / annuity / universal / participating）取自 `tap-config/compliance.json`。

## ⑤ 渲染

```bash
pip install -U python-pptx openpyxl
python scripts/render_pptx.py deck.json out/汇报.pptx                  # 用 meta.theme 或按 deck_type 自动选
python scripts/render_pptx.py deck.json out/汇报.pptx --theme teal     # 换主题，内容不变
python scripts/render_pptx.py deck.json out/汇报_精简版.pptx --brief   # 管理层精简版
python scripts/render_pptx.py deck.json out/汇报.pptx --no-animation   # 不要动画（如要转 PDF 打印）
```

渲染时会自动：读取 Excel 数据、插入目录和执行摘要、拆分过长的要点 / 问答页、对外版本插入重要提示、选择 auto 版式、
按框大小缩小字号、生成章节进度条和页码、写入入场动画和切换效果。
同时生成 `<文件名>_构建报告.md`：每页版式、标题、讲述时长、动画步骤，以及**标题体检**（像话题、没有数字、过长、
没点明图表标出的异常项）、文字放不下、版式重复、强调过多、缺备注、超出会议时长等问题。

退出码 2：内容校验不通过，例如版式缺字段、雷达图数据个数不符、区域没有预设位置、Excel 中找不到字段、
公式列没有计算结果（需先在 Excel 中打开保存一次）。

## ⑥ 质检交付

```bash
python scripts/review_pptx.py out/汇报.pptx [--external] [--final]
```

1. **构建报告和质检报告中的问题都要处理**：标题像话题就改成结论；文字放不下就精简或拆页；连续 3 页同一版式就换一种；缺备注就补。
2. **七维自评**（`reference/quality-rubric.md`），低于 4 分的项修改后重新渲染，最多 2 轮。
3. **交付说明**：页数和结构（章节标题列表）、主题、预计时长、主要依据的知识库文档和 Excel 文件、
   【待补充】所在页码、演示建议（哪几页是重点）；对外材料提醒走合规审核。需要时同时交付精简版。

## 不要做的事

- 不要把文档内容整段搬上 PPT；不要一页放三个以上的观点。
- 不要整页铺满主色：封面、章节页以留白为主，主色只用于强调。
- 不要为了“丰富”每页都换花样，版式服务于结论；同一章节内可以重复使用合适的版式，但不要连续 3 页相同。
- 不要编造数字、案例、联系方式；案例和演示数据要标“示例”。
- 不要关掉演讲备注——讲的人往往不是做 PPT 的人。
