# 知识生成 PPT

目标是交付一份**拿去就能讲**的演示文稿：故事线清楚，每页一个结论，图示代替大段文字，
品牌视觉，动画克制流畅，每页都有可以照着讲的备注。

```
① 读懂需求 → 需求卡片（听众、场合、时长、希望听众做什么）
② 搭故事线 → 页面大纲（每页一句结论 + 选定版式）
③ 按页检索 → 证据台账（每个数字都有出处）
④ 组装内容 JSON
⑤ 渲染 → .pptx + 构建报告
⑥ 质检交付
```

---

## ① 读懂需求 → 需求卡片

| 项 | 判断 | 影响 |
|---|---|---|
| 听众 | 管理层 / 同事 / 代理人 / 客户 | 结论先行程度、术语、对内对外 |
| 场合与时长 | 15 分钟汇报 ≈ 8-12 页；30 分钟培训 ≈ 15-20 页 | 页数 |
| 目的 | 听完要决策、要执行、要理解，还是要购买 | 结尾页的写法 |
| 风格 | orange / premium / minimal / warm，见 `reference/design-system.md` | 主题 |

```
📋 需求卡片
听众：管理层｜场合：季度经营会，约 15 分钟｜目的：批准三项专项｜对内
页数：约 14 页｜风格：尊享深色｜重点：继续率、产品结构
```

## ② 搭故事线 → 页面大纲（最重要的一步）

从 `reference/storylines.md` 选叙事结构，再写大纲。**先写出每页的标题，再决定版式**：

- **标题是一句结论**：“华东是唯一未完成目标的区域”，不是“区域情况”。只读所有标题就能听懂整个故事。
- **一页只讲一件事**；需要两件事就拆两页。
- **每页选一个最能证明这句结论的版式**（`reference/elements.md` 有“什么内容用什么版式”的对照表）。
  不确定时 `layout` 写 `auto`，渲染脚本会按数据形状自动选择。
- 用章节页（section）分 3-5 章；2 章以上自动生成目录页。
- 结尾用 summary 列出行动项（谁、做什么、什么时候），再接 end。

大纲先在对话里给用户确认（标题列表即可），用户说“直接做”则跳过确认。

## ③ 按页检索 → 证据台账

方法同 `kb-to-word/reference/retrieval.md`：逐页检索，数字、时限、比例必须有出处；
查不到写【待补充：XX】（渲染后黄底高亮）；资料冲突取最新，关键数据写【请确认】。

## ④ 组装内容 JSON

格式见 `reference/elements.md`。写作要点：

- **字少图多**：每页正文一般不超过 120 字；要点不超过 6 条，超过 8 条会被自动拆页。
- **数字自动高亮**：说明文字里的数字和单位（百分比、金额、天数等，单位表见 rules.ppt.number_units）会自动加粗并用主题色，不需要手动标。
- **图标**：每个条目可以指定 `icon`（41 个，见 design-system.md）；不指定时按文字关键词自动匹配，同一页内不重复。
- **右侧“关键发现”栏**（`insight`）用于图表页，写 2-3 条解读；**底部“结论条”**（`takeaway`）写这一页最想让听众记住的一句话。
- **每页写 notes**（演讲备注）：口语化，60-150 字，告诉讲的人这一页先说什么、强调什么。
- 对外材料遵守合规底线：不承诺收益、不与存款类比、不用绝对化用语，产品页注明“以保险合同条款为准”。

## ⑤ 渲染

```bash
pip install -U python-pptx
python scripts/render_pptx.py deck.json out/汇报.pptx                  # 用 meta.theme 或按 deck_type 自动选
python scripts/render_pptx.py deck.json out/汇报.pptx --theme warm     # 换主题，内容不变
python scripts/render_pptx.py deck.json out/汇报.pptx --no-animation   # 不要动画（如要转 PDF 打印）
```

渲染时会自动：插入目录、拆分过长的要点页、选择 auto 版式、按框大小缩小字号、生成章节进度条和页码、
写入入场动画（每页约 2.5 秒内自动依次播放）和切换效果（章节页“推入”，其余“淡化”）。
同时生成 `<文件名>_构建报告.md`：每页版式、动画步骤，以及文字放不下、版式重复、缺备注、标题像话题等问题。

## ⑥ 质检交付

```bash
python scripts/review_pptx.py out/汇报.pptx [--external] [--final]
```

1. **构建报告和质检报告中的问题都要处理**：文字放不下就精简或拆页；连续 3 页同一版式就换一种；缺备注就补。
2. **六维自评**（`reference/quality-rubric.md`），低于 4 分的项修改后重新渲染，最多 2 轮。
3. **交付说明**：页数和结构（章节标题列表）、主题、主要依据的知识库文档、【待补充】所在页码、
   演示建议（总时长、哪几页是重点）；对外材料提醒走合规审核。

## 不要做的事

- 不要把文档内容整段搬上 PPT；不要一页放三个以上的观点。
- 不要为了“丰富”每页都换花样，版式服务于结论；同一章节内可以重复使用合适的版式，但不要连续 3 页相同。
- 不要编造数字、案例、联系方式。
- 不要关掉演讲备注——讲的人往往不是做 PPT 的人。
