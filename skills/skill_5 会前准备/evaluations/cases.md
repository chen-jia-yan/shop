# 会前准备评测用例

上线前和每次修改后跑一遍。把 `<...>` 换成你们知识库里真实存在的客户、项目。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | 明天下午和 <客户> 开会，帮我准备一下 | 触发 meeting-prep |
| A2 | （粘贴一封会议邀请） | 触发 |
| A3 | （上传 .ics 文件） | 触发 |
| A4 | （粘贴会议纪要）帮我整理一下 | 不触发（meeting-notes-to-kb） |
| A5 | 帮我约一个明天下午的会 | 不触发，说明不支持预约会议 |

## B. 会议信息获取

| # | 场景 | 期望 |
|---|---|---|
| B1 | `MEETING_SOURCE=paste`，用户只说"明天开会帮我准备" | 请用户粘贴邀请，或提供主题和参会方；不假装查了日历 |
| B2 | 运行 `parse_invite.py examples/invite.ics` | 正确解析主题、时间、组织者、2 位必需参会人、1 位可选参会人、地点；议程里的折行被正确拼接（"价格与付款方式"） |
| B3 | 运行 `parse_invite.py examples/pasted.txt` | 正确解析主题、开始/结束时间、参会人列表；议程进入 body |
| B4 | 粘贴的邀请缺参会人 | `missing` 中包含 attendees，skill 追问参会方 |
| B5 | `MEETING_SOURCE=graph`，日历里同一天有 2 个相关会议 | 列出两个会议让用户选 |
| B6 | `MEETING_SOURCE=auto`，Graph 调用失败 | 改为请用户粘贴，不报错中断 |

## C. 简报质量

| # | 场景 | 期望 |
|---|---|---|
| C1 | 客户会议，参会人有外部邮箱 | 识别为客户会议，有"客户情况"部分 |
| C2 | 议程有 3 项 | 3 项分别检索，简报里逐项有对应信息 |
| C3 | 知识库没有该客户资料 | "资料缺口"里写明，**不编造**合作历史 |
| C4 | 任意会议 | 第一部分是"最需要知道的 3 件事"；每条都有具体内容；总长度在一页以内 |
| C5 | 邀请正文里有会议链接和密码 | 简报里不出现链接和密码 |
| C6 | 用户要 Word 版 | 调用 kb-to-word 的 build_docx.py 生成 .docx |
