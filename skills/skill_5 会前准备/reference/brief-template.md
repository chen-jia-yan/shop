# 会前简报模板

所有类型都用同一个骨架，按会议类型调整"重点"部分。整份控制在一页以内。

## 通用骨架

```markdown
# 会前简报：<会议主题>
<日期 时间> ｜ <地点或线上> ｜ 组织者：<姓名>
参会方：<单位/部门，列出主要人员>

## 最需要知道的 3 件事
1. <最关键的信息，带具体数字或结论>
2. ...
3. ...

## 背景
<2-4 句：这件事的来龙去脉、目前进展到哪一步>

## <按会议类型的重点部分，见下方>

## 可能被问到的问题
| 问题 | 答案要点 |
|---|---|
| ... | ... |

## 相关资料
- <知识库文档标题>：<一句话说明它讲了什么>

## 资料缺口
- <知识库中没找到的内容，建议会前向谁确认>
```

"资料缺口"没有内容时，整节删掉。

## 各类型的重点部分

### 客户会议
标题：`## 客户情况`
- 合作历史：合作了什么、什么时候、规模
- 当前状态：进行中的项目、合同、待处理的问题
- 客户关注点：以往沟通中提过的诉求或意见
- 我方可以提供的：相关产品、政策、方案（适用于这个客户的）
- 注意事项：价格、承诺边界等不能随口答应的内容

### 项目会议
标题：`## 项目现状`
- 当前阶段和进度
- 上次会议的结论和待办（如果知识库里有纪要）
- 本次议程各项的相关信息，逐项列出
- 风险和阻塞

### 决策会议
标题：`## 待决策事项`
每个待决策事项写：
- 要决定什么
- 可选方案及各自的依据（来自知识库）
- 相关的制度或规定限制
- 历史上类似的决策是怎么定的（如有）

### 内部沟通
标题：`## 议题要点`
- 按议程逐项列出相关信息
- 没有议程时，按主题列出 3-5 个相关知识点

## 写作检查

- [ ] 第一屏就能看到"最需要知道的 3 件事"
- [ ] 没有一句空话，每条都有具体内容
- [ ] 可能被问到的问题都附了答案要点
- [ ] 没有复述会议链接、密码
- [ ] 总长度在一页以内
