# 主题简报评测用例

上线前和每次修改后跑一遍。把 `<...>` 换成你们知识库里真实存在的主题，每类主题至少测 1 个。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | 给我讲讲 <系统名> | 触发 |
| A2 | 我要接手 <项目名>，需要知道什么？ | 触发，读者按新手处理 |
| A3 | <制度名> 的报销时限是多少？ | 不触发（qa_advance） |
| A4 | 帮我写一份 <产品> 的说明文档，Word 格式 | 不触发（kb-to-word） |
| A5 | 给我讲讲财务 | 触发，但先追问具体哪一块 |

## B. 结构与检索

| # | 场景 | 期望 |
|---|---|---|
| B1 | 系统类主题 | 有"怎么用"部分，覆盖开通、常用操作、支持渠道 |
| B2 | 制度类主题 | 有"怎么办"部分，流程用编号列表，写清谁/在哪/时限 |
| B3 | 产品类主题 | 价格部分注明"内部信息，对外以报价单为准" |
| B4 | 项目类主题 | 关键决定和待定事项分开，待定的没有写成已定 |
| B5 | 概念类主题 | 给出公司内部定义，与通用含义不同时说明区别 |
| B6 | 任意主题 | 按方面分别检索，不是只用主题名检索一次 |

## C. 内容质量

| # | 场景 | 期望 |
|---|---|---|
| C1 | 任意主题 | 第一部分就是核心要点，3-5 条，每条都有具体信息 |
| C2 | 任意主题 | 总长度在一页以内（600-1000 字） |
| C3 | 某个方面知识库里没有 | 写"知识库中暂未找到 XX 的说明"，不编造 |
| C4 | 两篇文档说法不一致 | 用新的，并注明旧说法和调整时间 |
| C5 | 读者是新手 vs 熟悉 | 新手版先讲是什么、少术语；熟悉版省略基础，突出细节和例外 |
| C6 | "继续了解" | 示例问题可以直接复制去问 qa_advance |
| C7 | 主题完全检索不到 | 停下来请用户提供别的叫法，不生成空壳简报 |
| C8 | 用户要 Word 版 | 交给 kb-to-word 生成 |
