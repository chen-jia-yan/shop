# 各类主题的简报结构

每类列出：**要检索的方面**（第 3 步用）和**展开部分怎么写**（第 4 步用）。方面检索不到就跳过并注明。

---

## 系统/工具

**要检索的方面**
1. 是什么、用来做什么、谁需要用
2. 怎么开通/申请权限、入口在哪
3. 主要功能和常用操作
4. 常见问题和故障处理
5. 使用规范和限制（安全要求、禁止行为）
6. 出问题找谁（支持渠道）

**展开部分**：标题 `## 怎么用`
- 开通：一两句话说清步骤和入口
- 常用操作：3-5 个，每个一行
- 限制和规范：有就写
- 支持渠道：找谁、怎么找

---

## 制度/流程

**要检索的方面**
1. 目的和适用范围（适用于谁、什么情况）
2. 核心规则（标准、额度、时限）
3. 办理流程（步骤、每步谁负责、在哪办）
4. 需要的材料或表单
5. 例外情况和特殊规定
6. 违反规定的后果（如有）

**展开部分**：标题 `## 怎么办`
- 用编号列表写流程，每步写清楚"谁、在哪、做什么、时限"
- 规则较多时用表格（项目 / 标准 / 说明）
- 例外情况单独列出

---

## 产品/服务

**要检索的方面**
1. 是什么、解决什么问题、面向哪些客户
2. 版本/套餐和主要区别
3. 核心功能或服务内容
4. 价格和商务政策（注意：对内简报可以写，提醒不能直接对外）
5. 与同类产品的区别（知识库里有才写）
6. 常见客户问题和标准回答

**展开部分**：标题 `## 产品详情`
- 版本区别优先用表格
- 价格部分注明"内部信息，对外请以报价单为准"

---

## 项目

**要检索的方面**
1. 背景和目标
2. 范围和主要交付物
3. 当前阶段和进度
4. 团队和分工（负责人、对接人）
5. 关键决定（会议纪要里的"已决定"）
6. 当前风险和待定事项

**展开部分**：标题 `## 项目现状`
- 时间线：已完成的阶段 → 当前阶段 → 后续计划
- 团队：角色 / 姓名 / 负责什么
- 关键决定和待定事项分开写，**待定的不能写成已定**

---

## 概念/术语

**要检索的方面**
1. 定义（公司内部的用法，不是通用定义）
2. 在哪些业务、流程、文档中使用
3. 相关或容易混淆的概念
4. 具体例子

**展开部分**：标题 `## 详细说明`
- 先给公司内部的定义；如果和通用含义不同，明确说出区别
- 用一个具体例子说明
- 容易混淆的概念用对比的方式写

---

## 判断不了类型时

按"读者最想先知道什么"组织：是什么 → 怎么用/怎么办 → 注意什么 → 找谁。
