# 主题简报

`qa_advance` 回答一个问题；主题简报回答"关于这件事，我需要知道什么"。

## 流程

### 1. 确认主题和读者

- **主题**：要具体到一个对象。"财务" 太宽，先问："想了解财务的哪一块？比如报销、预算、付款审批？"；"差旅报销" 足够具体，直接开始。
- **读者熟悉程度**：从用户的说法判断，判断不了按"新手"处理，不要追问。
  - 新手（"我刚接触""完全不了解""要接手"）：先讲是什么、为什么，少用术语
  - 熟悉（"我知道大概，想看全貌""想系统梳理一下"）：省略基础解释，突出规则细节、例外和易错点

### 2. 判断主题类型，拆出要检索的方面

按 `reference/brief-structures.md` 判断主题属于哪一类，每一类都列出了要覆盖的方面。

| 类型 | 例子 |
|---|---|
| 系统/工具 | VPN、报销系统、CRM |
| 制度/流程 | 差旅报销、年假、采购审批 |
| 产品/服务 | 某个产品线、某项服务 |
| 项目 | 某个在建项目 |
| 概念/术语 | 公司内部的专有名词、业务概念 |

### 3. 按方面逐个检索

按 `reference/retrieval-plan.md` 执行。要点：
- **每个方面单独检索**，不要只用主题名检索一次
- 记下每条信息来自哪篇文档、更新时间（来源追溯由平台处理，这里用于判断新旧和冲突）
- 多篇文档说法不一致时，以更新时间较新的为准，并在简报中注明

### 4. 写简报

结构固定为四部分，控制在**一页以内（600-1000 字）**：

```markdown
# <主题>

**一句话**：<它是什么、用来做什么>

## 核心要点
<3-5 条，读者只看这一部分也能掌握大概。每条都要具体：数字、时限、负责人、入口>

## <按主题类型的展开部分，见 brief-structures.md>

## 常见问题与易错点
<2-4 条，优先写知识库里明确提到的注意事项、例外情况>

## 继续了解
- 想了解 <某个细节>，可以直接问我："<示例问题>"
- 相关文档：<文档标题>（<一句话说明>）
```

写作要求：
- 先结论后细节，第一屏就是核心要点。
- 不照搬原文结构，按读者理解的顺序重新组织。
- 每句话都要有信息量，不写"XX 非常重要""需要引起重视"这类空话。
- 知识库没有覆盖的方面，在对应位置写一句"知识库中暂未找到 XX 的说明"，**不编造，也不用常识补**。

### 5. 交付

- 默认在对话里给出简报。
- 用户需要 Word 版时，交给 kb-to-word 生成。
- "继续了解"里的示例问题要能直接复制去问 `qa_advance`。

## 规则

- 简报只基于知识库内容。
- 一个方面检索不到就跳过并注明，不要为了结构完整而硬写。
- 主题涉及多个相互独立的对象时（比如"公司的各种假期"），按对象分节，每节压缩，总长度仍控制在一页半以内；超过时只写概览，并列出可以分别深入的子主题。
