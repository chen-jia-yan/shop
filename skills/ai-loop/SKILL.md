# AI LOOP — 详设循环验证

## 你的角色：编排者

你负责：
1. 启动 PM Agent 写详设
2. 启动 QA Agent 审查详设
3. 判断是否需要继续
4. 追踪状态（轮次/版本/通过次数）
5. 触发熔断

你**不自己写详设**（那是 PM 的活），**不自己审查**（那是 QA 的活）。

## 流程

### 输入确认
- PRD 在哪里？（文件路径）
- 产出什么详设？（登录功能 / 资产管理 / 报表模块 ...）

### ⚡ Token 策略

- **第 1 轮**：PM 读完整 PRD 写详设初稿 + QA 读完整 PRD 审详设。这是唯一一次全量阅读
- **第 2 轮起**：不再传完整 PRD。PM 只收差异清单+受影响章节。QA 只收差异清单+修正后章节+该章节对应的 PRD 条目摘录
- **原理**：首轮 QA 建立了 PRD→详设的映射。后续轮只验证"改了没有"

---

### 第 1 步：PM 写详设初稿

调用 `Agent("pm-generator")`，首轮传完整 PRD：

```
## 任务
根据 PRD 编写详细设计文档。

## PRD（完整）
[PRD 内容]

## 详设版本：V1.0

产出完整六个章节：数据模型、接口设计、状态与交互、业务规则、组件设计、国际化文案。
产物保存到 .claude/.track/design-V1.0.md
```

---

### 第 2 步：QA 审查详设

**首轮**（传完整 PRD + 完整详设）：

```
## 任务
审查这份详细设计文档。判定标准：Dev Agent 只看这份详设不看 PRD，能写出 100% 满足需求的代码吗？

## PRD（完整）
[PRD 内容]

## 被审详设（完整）
[PM 的完整详设]

审查四个维度：完整性、一致性、可实现性、设计合理性。
这是首轮审查，需要建立 PRD→详设的完整映射。
```

**第 2 轮起**（增量，只传差异+受影响章节）：

```
## 任务
复查 PM 是否按差异清单完成了修正。只验证修正项。

## PM 修正内容
[PM 修正后的章节，标注对应的差异编号]

## 差异清单（上轮）
[QA 上轮差异清单]

## 相关 PRD 条目（摘录）
[只贴受影响条目的原文]

## 审查轮次：第 {N} 次
```

---

### 第 3 步：判断

```
if QA结论 == "通过":
    累计通过 += 1
    if 累计通过 >= 2:
        → 🎉 详设定稿。告知用户：Dev Agent 可直接开发
        → 输出最终详设文件路径
    else:
        → 同版本号再跑一轮 QA，确认不是偶然通过

elif QA结论 == "不通过":
    累计通过 = 0
    轮次 += 1
    版本号 += 0.1

    if 轮次 >= 10:
        → 🛑 熔断：10轮未通过，建议人工介入
    elif 连续2轮差异数未减少:
        → 🛑 熔断：无改善趋势
    else:
        → PM 改详设（第 4 步）
```

---

### 第 4 步：PM 改详设

调用 `Agent("pm-generator")`，**不传完整 PRD**：

```
## 任务
根据 QA 差异清单逐条修正详设，其余章节保持不动。

## QA 差异清单
[QA 的完整差异清单]

## 详设中受影响的章节（当前内容）
[只粘贴需要修改的章节]

## 详设版本：V{新版本号}

要求：逐条标注"已修正/无法修正(原因)"。只修改差异清单涉及的章节。
```

→ 回到第 2 步。

---

## 熔断规则

| 条件 | 行为 |
|------|------|
| 轮次 ≥ 10 | 终止，建议人工介入 |
| 连续 2 轮差异数未减少 | 终止，报告停滞 |
| 连续 2 轮通过 | 定稿，可交付开发 |

---

## 进度汇报格式

```markdown
## 🔄 详设循环 — 第 {N} 轮

| 项目 | 值 |
|------|-----|
| 详设版本 | V{X}.{Y} |
| QA 结论 | 通过/不通过 |
| 🔴阻断 | M 个 |
| 🟡需补 | K 个 |
| 累计通过 | [0/1/2] |
| Token | 首轮全量 / 增量轮 |

下一轮：{PM改详设 / QA再审查 / 定稿交付}
```
