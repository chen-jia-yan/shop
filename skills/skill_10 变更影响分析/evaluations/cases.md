# 变更影响分析评测用例

上线前和每次修改后跑一遍。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | （上传两版制度）对比一下改了什么，影响哪些地方 | 触发 |
| A2 | 新版报销规定出来了，知识库哪些内容要跟着改？（上传新版） | 触发；询问旧版，或从知识库找到旧版 |
| A3 | （上传一份合同）帮我检查一下 | 不触发（compliance-check） |
| A4 | 报销时限是怎么一步步改过来的？ | 不触发（decision-trace） |

## B. 脚本（用 `examples/old.txt` 和 `examples/new.txt`）

运行：
```bash
python scripts/compare_docs.py examples/old.txt examples/new.txt
python scripts/compare_docs.py examples/old.txt examples/new.txt --show-minor
```

| # | 检查项 | 期望 |
|---|---|---|
| B1 | 第一条（适用范围增加了劳务派遣人员） | 识别出改动，章节为"第一条"；句子相似度高，脚本可能标为"措辞调整"，**核实时必须判断为实质变更**（适用人群变了） |
| B2 | 第二条 | 实质变更，`number_changes` 为 `30天 → 15个工作日` |
| B3 | 第三条（只把全角冒号改成半角） | 默认不出现，`minor_hidden` 为 1；加 `--show-minor` 后显示为"格式标点" |
| B4 | 第四条（部门经理 → 部门负责人） | 脚本可能标为"措辞调整"；**第 3 步核实时必须判断为实质变更**（审批人变了） |
| B5 | 第五条 | 没有改动，不出现 |
| B6 | 第六条 | "新增" |
| B7 | 标题行（2025 版 → 2026 版） | 不作为改动输出 |
| B8 | 两个完全无关的文件 | 输出相似度很低的警告 |
| B9 | 用 .docx 文件对比 | 能读取正文和表格；条款号作为章节名 |

## C. 影响检索与报告

| # | 场景 | 期望 |
|---|---|---|
| C1 | 变更点"报销时限" | 用"30 天内提交"等旧说法检索；还在写 30 天的文档列入"需要同步更新"，附原文摘录 |
| C2 | 只提到"报销时限"但没写具体天数的文档 | 列入"可能受影响"，不列入"需要同步更新" |
| C3 | 问答测试 | 问"差旅报销要在多少天内提交？"，回答 30 天的列入"问答需更新" |
| C4 | 会议纪要里提到 30 天 | 历史记录，不列入"需要同步更新" |
| C5 | 被修改文件的旧版本身 | 不列入影响清单 |
| C6 | 适用范围变化（新增劳务派遣人员） | "影响谁"写明新增的人群，建议通知 |
| C7 | 新版没写过渡安排 | 建议明确新旧规定的过渡安排 |
| C8 | 任意场景 | 不修改知识库内容；末尾提示检索范围受用户权限限制 |
| C9 | 影响清单超过 10 条 | 提供生成 Excel 的选项 |
