# 规范检查评测用例

上线前和每次修改后跑一遍。每类文档至少准备 2 份真实样本：1 份基本合规的，1 份有明确问题的（可以在合规样本上人为改出问题，这样"标准答案"是已知的）。

## A. 触发判断

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | （上传合同）帮我看看这份合同有没有问题 | 触发 |
| A2 | （上传方案）是否符合公司规范？ | 触发 |
| A3 | （上传两版制度）有什么区别 | 不触发（change-impact） |
| A4 | 帮我写一份服务方案 | 不触发（kb-to-word） |
| A5 | 合同的付款比例有什么规定？ | 不触发（qa_advance） |

## B. 类型识别与规范检索

| # | 场景 | 期望 |
|---|---|---|
| B1 | 上传服务合同 | 识别为合同；检索服务合同模板、合同管理制度、授权规定 |
| B2 | 上传客户方案 | 识别为方案；检索方案模板、对外材料规范、定价政策 |
| B3 | 上传制度草稿 | 识别为制度文件；检索编写规范和**现行同类制度** |
| B4 | 用户说"对照 XX 模板" | 以用户指定的模板为准 |
| B5 | 知识库里没有某类规范 | 报告中列为"未检查的项"，**不用常识判定为不合规** |

## C. 检查质量（用人为改出问题的样本）

| # | 埋入的问题 | 期望 |
|---|---|---|
| C1 | 合同删掉了模板里的保密条款 | 检出，"必须修改"，依据指向模板条款 |
| C2 | 合同付款比例超出制度规定 | 检出，"必须修改"，依据写到具体条款 |
| C3 | 合同金额超出签约权限 | 检出，"提示"（需用户确认审批） |
| C4 | 对外方案里写了内部系统名 | 检出 |
| C5 | 方案中的产品参数是旧版 | 检出，并指出现行参数 |
| C6 | 新制度和现行制度对同一事项规定矛盾 | 检出，并指出矛盾的现行制度 |
| C7 | 基本合规的样本 | 不出现"必须修改"；不为了凑数列一堆无依据的问题 |
| C8 | 任意样本 | 每条"必须修改"都有具体依据（规范名 + 条款） |

## D. 脚本与输出

| # | 场景 | 期望 |
|---|---|---|
| D1 | `extract_docx.py` 处理含表格的文档 | 表格里的段落也被提取，`in_table` 为 true |
| D2 | `annotate_docx.py`，python-docx ≥ 1.2 | Word 打开后右侧批注栏显示批注，作者为"规范检查" |
| D3 | `annotate_docx.py`，python-docx < 1.2 | 段落后出现红色【检查意见】，输出提示升级 |
| D4 | issues 中 para 编号错误、但 quote 正确 | 通过 quote 定位到正确段落 |
| D5 | issues 中 para 为 0（缺失类问题） | 批注挂在文档开头 |
| D6 | 输出路径与原文件相同 | 报错，不覆盖原文件 |
| D7 | 上传 PDF | 只输出问题清单，并提示提供 Word 版可批注 |
| D8 | 合同类交付 | 结尾提示"正式签署前请按公司流程走法务审核" |
