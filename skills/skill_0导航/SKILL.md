# Skill 导航

帮用户找到合适的 skill，并教会他怎么说。所有 skill 的信息只来自 `catalog.md`，不要凭记忆或猜测介绍 skill。

## 第一步：读取目录

每次触发都先读 `catalog.md`。它是唯一的信息来源，会持续增量更新。

- 只推荐 `状态: 已上线` 的 skill。
- `状态: 开发中` 的 skill 可以告诉用户"即将上线"，但不能让用户去调用。
- `状态: 已下线` 的 skill 不要提及。
- 目录里没有的 skill，一律当作不存在。

## 第二步：判断用户属于哪种情况

### A. 用户想看全部功能（"你能做什么""有哪些 skill"）

按 catalog 里的 `分类` 分组展示，每组列出已上线 skill，每个一行：

```
**名称**：一句话功效
  试试说："示例说法1"
```

最后加一句："告诉我你现在想做的事，我帮你挑最合适的。"
如果已上线 skill 超过 15 个，先只列分类名和每类数量，让用户选分类再展开。

### B. 用户描述了一个任务（"我要给客户写个方案""明天开会要准备什么"）

1. 拿用户的描述去比对每个 skill 的 `什么时候用` 和 `示例说法`，同时排除命中 `不适用` 的。
2. 推荐最匹配的 1 个；如果确实有 2-3 个都合适（比如可以串起来用），按使用顺序列出。
3. 每个推荐包含：
   - 为什么适合（结合用户的原话，一句话）
   - 需要准备什么（来自 `需要准备`）
   - 会得到什么（来自 `产出`）
   - 一句根据用户实际任务改写好的示例说法，用户可以直接复制
4. 如果用户的信息已经足够，直接问"要我现在就用 XX 帮你做吗？"

### C. 用户问某个具体 skill 怎么用（"会前准备怎么用"）

展示该 skill 的完整卡片：功效、什么时候用、不适用、需要准备、产出、全部示例说法。

### D. 没有匹配的 skill

- 如果是知识问答，交给 `qa_advance`。
- 如果命中的是 `开发中` 的 skill，说明"这个功能正在开发中"，并给出当前能用的替代方案（如有）。
- 都不匹配时，如实说"目前还没有专门处理这个的 skill"，并在回答末尾附上：
  `[未匹配需求] <用一句话概括用户想做的事>`
  这一行用于后台统计，帮助决定下一个要做的 skill。

## 规则

- 推荐要少而准。宁可推荐 1 个确定合适的，不要列 5 个让用户自己挑。
- 示例说法必须是用户能直接发出去的完整句子，并尽量带上用户自己任务里的内容。
- 不要解释 skill 的技术原理，只讲用户能做什么、怎么说。
- 如果推荐的 skill 有 `前置条件`（如需要先上传文件、需要权限），提前说明。

## 维护说明（给管理员）

- 新增、修改、下线 skill：只改 `catalog.md`，本文件不用动。
- 新增条目的格式见 `reference/catalog-entry-template.md`。
- 写 skill 的 description 时，参照 `reference/description-guide.md`。
- 每次改完 catalog，跑一遍 `evaluations/cases.md` 里的用例。
