# Skill 导航评测用例

每次修改 `catalog.md` 或 `SKILL.md` 后跑一遍。
"期望"一栏基于当前 catalog：当某个 skill 从"开发中"变成"已上线"后，记得更新对应用例的期望。

## A. 查看全部功能

| # | 用户输入 | 期望 |
|---|---|---|
| A1 | 你能帮我做什么？ | 按分类列出所有"已上线" skill，每个带一句功效和一句示例；不把"开发中"的当成可用 |
| A2 | 有哪些 skill？ | 同 A1 |
| A3 | 管理员能用哪些功能？ | 只展示"知识库管理（管理员）"分类 |

## B. 根据任务推荐

| # | 用户输入 | 期望 |
|---|---|---|
| B1 | 明天要和客户开续约会，我该准备什么？ | 识别为会前准备；当前 meeting-prep 是"开发中"，说明即将上线，不让用户调用；如有替代方案给出替代方案 |
| B2 | 公司报销流程怎么走？ | 识别为知识问答，交给 qa_advance，不推荐其他 skill |
| B3 | 帮我把这个会议纪要整理一下存起来 | 匹配 meeting-notes-to-kb，不匹配 meeting-prep |
| B4 | 新旧两版制度有什么区别？ | 匹配 change-impact，不匹配 compliance-check |
| B5 | 帮我订一张去上海的机票 | 无匹配；如实说明，并输出 `[未匹配需求]` 行 |

## C. 询问具体 skill

| # | 用户输入 | 期望 |
|---|---|---|
| C1 | qa_advance 怎么用？ | 展示 qa_advance 的完整卡片 |
| C2 | 有没有一个叫"智能排班"的功能？ | catalog 中不存在，如实说没有，不编造 |

## D. 不该触发

| # | 用户输入 | 期望 |
|---|---|---|
| D1 | （粘贴邮件）帮我回复这封邮件 | 用户任务明确，应直接交给对应 skill，不先弹导航（mail-reply 上线后） |
