# Catalog 条目模板

新增 skill 时，复制下面的模板，粘到 `catalog.md` 对应分类下，填好每一项。

```markdown
### <skill-id>（<中文名>）
- 状态: 已上线 | 开发中 | 已下线
- 分类: <分类名，与 catalog 中的分类标题一致；也可以新建分类>
- 功效: <一句话，用户视角，写"能帮你做什么">
- 什么时候用: <用户常见的 2-4 种说法，用引号括起来>
- 不适用: <容易混淆的场景，并写明该用哪个 skill>
- 需要准备: <用户要提供什么：文件、主题、时间范围等>
- 产出: <用户会得到什么：文件类型、内容结构>
- 前置条件: <可选：权限、需要先上传文件等；没有就删掉这一行>
- 示例说法:
  - "<用户能直接复制发出的完整句子>"
  - "<再来一句，覆盖另一种场景>"
```

## 填写要点

- **skill-id** 必须和 skill 实际的 `name` 一致，否则导航推荐了也调用不到。
- **功效** 用用户的话写，不写技术实现。✅"把会议纪要整理成决策和待办" ❌"基于 LLM 的纪要结构化抽取"
- **什么时候用** 写用户真实会说的话。可以去问答日志里找用户的原始说法。
- **不适用** 是减少推荐错误最有效的一项，每个 skill 至少写一条，并指向正确的 skill。
- **示例说法** 至少 2 条，要具体，带上真实业务场景。

## 状态变更

- 开发完成：把 `开发中` 改成 `已上线`
- 暂停或废弃：改成 `已下线`（保留条目，方便以后恢复）
- 每次修改，更新 catalog 顶部的"最后更新"日期
