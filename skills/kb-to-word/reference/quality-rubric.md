# 七维质量评分

渲染并通过脚本质检后，按下表自评。**任何一项低于 4 分就修改后重新渲染**，最多 2 轮。

| 维度 | 5 分 | 3 分 | 1 分 |
|---|---|---|---|
| **需求契合** | 类型、读者、用途、篇幅都和需求卡片一致；用户点名的内容都有 | 基本符合，但篇幅或侧重有偏差 | 写成了另一类文档（如把培训手册写成制度） |
| **内容准确** | 每个数字都能在证据台账找到；冲突已处理；无编造 | 少量表述不够精确 | 有无来源的数字或条款 |
| **内容充实** | 每章有可核对的事实；每段有结论 + 依据 + 做法；有举例；内容体检无提示或已逐条说明 | 个别章节只有原则性表述 | 通篇套话，读者读完不知道该做什么 |
| **结构逻辑** | 结论先行；章节顺序符合读者的使用顺序；无重复 | 结构完整但顺序不顺 | 照搬知识库原文结构 |
| **可读性** | 标题写内容；段落短；术语有解释；读者 30 秒能找到想要的信息 | 有大段文字或个别术语未解释 | 通篇大段文字 |
| **视觉呈现** | 每 1-2 章有图示或图表，元素选择贴合内容；主色只做强调，一页内带底色的元素不超过 3 个；字体方案与文档类型匹配 | 元素偏少或个别元素选得不合适 | 纯文字，或元素堆砌、大面积铺色 |
| **合规** | 质检无“必须修改”；对外文档必备要素齐全；无内部信息外泄 | 有“建议修改”项未处理 | 有“必须修改”项 |

## 自评输出格式（交付说明中简要展示）

```
质量自评：需求 5｜准确 5｜充实 4｜结构 4｜可读 5｜视觉 4｜合规 5
返工：1 轮（第 3 章原为纯文字，已改为流程图 + 清单）
```

## 常见扣分点自查

- [ ] 第一页正文（第一个一级章节）有没有直接给结论？
- [ ] 有没有连续 3 段以上的纯文字？
- [ ] 构建输出的“内容体检”逐条处理了吗？每章有没有至少一个可核对的数字、时限或条款？
- [ ] 有没有“进一步加强、全面提升、及时、相关部门”这类套话？
- [ ] 图表 caption 写的是结论还是话题？
- [ ] 表格是否超过 6 列？
- [ ] 同一概念是否用了不同说法？
- [ ] 【待补充】是否都在交付说明里列出了位置和需要谁补？
- [ ] 对外文档里有没有出现内部系统名、员工姓名、内部价格？
