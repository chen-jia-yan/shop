# 保险行业 10 类文档蓝图

每个蓝图给出：适用场景 → 读者最关心的问题 → 推荐章节（含元素）→ 必备要素 → 常见错误。
**蓝图是起点，不是模板**：按需求卡片删减、合并、调整顺序。章节名称要改写成本次文档的具体内容。

---

## 1. 产品说明书 `product`（对外）

**场景**：给客户或销售人员介绍一款保险产品。
**读者问题**：保什么？不保什么？交多少钱、保多久？怎么买、怎么赔？
**推荐风格**：classic

| 章节 | 回答的问题 | 元素 |
|---|---|---|
| 产品概览 | 这是一款什么产品、适合谁 | lead、kpi（投保年龄/保障期限/交费期间）|
| 保障责任 | 保什么、赔多少 | structure、table（责任/条件/金额）|
| 投保规则 | 谁能买、怎么交费 | table |
| 责任免除 | 哪些情况不赔 | callout(risk)、bullets |
| 重要期间 | 犹豫期、等待期、宽限期 | timeline 或 table |
| 投保与理赔 | 怎么买、怎么赔 | flow |
| 常见问题 | 客户常问的疑问 | faq |
| 术语与提示 | 专业词、风险提示 | glossary、callout(risk) |

**必备**：犹豫期、等待期、责任免除、“具体以保险合同条款为准”、风险提示。
**常见错误**：把条款原文整段复制；用“最全面”“必赔”等用语；漏写等待期内出险的处理。

## 2. 客户方案 / 建议书 `proposal`（对外）

**场景**：针对某位客户或某个家庭的保障规划。
**读者问题**：我现在有哪些保障缺口？推荐什么方案、为什么？要花多少钱？
**推荐风格**：classic（高净值客户用 premium）

| 章节 | 回答的问题 | 元素 |
|---|---|---|
| 方案摘要 | 一句话结论和总保费 | callout(summary)、kpi |
| 家庭保障现状 | 已有什么、缺什么 | table（成员 × 保障类型）|
| 需求分析 | 为什么需要这些保障 | bullets、chart(bar) 保额缺口 |
| 推荐方案 | 选什么、保多少 | compare、table |
| 保费与权益 | 每年交多少、能得到什么 | table、chart |
| 风险提示与说明 | 需要知道的限制 | callout(risk) |

**必备**：风险提示、条款为准声明、犹豫期；涉及分红/万能须写明“不保证”。
**常见错误**：拿收益和存款比；未说明演示利率不代表实际收益。

## 3. 理赔服务指引 `claims`（对外）

**场景**：告诉客户出险后怎么办。
**读者问题**：第一步做什么？要准备哪些材料？多久能赔下来？找谁？
**推荐风格**：minimal（客户自助版用 classic）

| 章节 | 回答的问题 | 元素 |
|---|---|---|
| 出险后第一步 | 现在马上要做什么 | callout(key)、flow |
| 理赔流程 | 整个过程 | flow 或 steps |
| 材料清单 | 带什么 | checklist（按险种分组）|
| 办理时效 | 多久 | timeline |
| 常见拒赔原因 | 怎样避免被拒 | callout(warning)、bullets |
| 常见问题 | | faq |
| 联系方式 | 找谁 | contact |

**必备**：理赔材料、时效、联系方式。
**常见错误**：材料清单不分险种；把内部审核环节写进客户版。

## 4. 核保说明 `underwriting`（对内为主）

**场景**：说明核保规则和结论类型。
**读者问题**：哪些情况要加费/除外/延期/拒保？要客户补什么材料？
**推荐风格**：minimal

章节：核保原则 → 健康告知要点（checklist）→ 结论类型（table：标准体/加费/除外/延期/拒保）→ 常见疾病核保指引（table）→ 补充材料（checklist）→ 案例（callout(info)）。
**必备**：如实告知、健康告知。

## 5. 培训手册 `training`（对内）

**场景**：让新人或转岗人员学会一项知识或技能。
**读者问题**：学完能做什么？要点是什么？怎么检验学会了？
**推荐风格**：classic

章节：学习目标（callout(key)）→ 知识地图（structure 或 flow）→ 分模块讲解（每模块：lead + 要点 + 示例 + 易错点 callout(warning)）→ 案例练习（steps）→ 自测题（numbered + 答案放附录）→ 术语（glossary）。
**必备**：学习目标、自测/练习。
**常见错误**：照搬制度原文；没有案例；只讲“是什么”不讲“怎么做”。

## 6. 管理制度 `policy`（对内）

**场景**：正式的管理办法、操作规程。
**推荐风格**：minimal
章节：总则（目的、依据、适用范围）→ 职责分工（table：部门 × 职责）→ 管理要求（分条）→ 操作流程（flow）→ 监督与考核 → 附则（生效日期、解释权）→ 版本记录（revisions）→ 签批（signoff）。
**必备**：适用范围、职责、生效/施行。
**写法**：用“第 X 条”分条，措辞用“应”“不得”“须”，避免“尽量”“原则上”这类模糊用语。

## 7. 经营分析报告 `analysis`（对内）

**场景**：季度/年度经营回顾、专题分析。
**读者问题**：整体好不好？好在哪、差在哪？原因？接下来怎么办？
**推荐风格**：premium

| 章节 | 元素 |
|---|---|
| 核心结论 | callout(summary)、kpi（4 个关键指标）|
| 业务规模 | chart(combo)、table |
| 结构分析 | chart(donut/stacked) |
| 渠道/机构表现 | chart(highlight)、table（高亮列）|
| 问题与原因 | bullets、matrix |
| 下一步举措 | steps（负责人、时限）|

**必备**：数据口径/资料来源。
**常见错误**：只罗列数字不给判断；同比环比混用；图表标题不写结论。

## 8. 项目方案 `project`（对内）

章节：项目背景与目标（lead、kpi）→ 方案设计（structure/flow）→ 实施计划（timeline）→ 分工（table）→ 资源与预算（table）→ 风险与应对（matrix）→ 待决策事项（callout(key)）。
**必备**：目标、计划/里程碑、风险。

## 9. 客户告知函 `notice`（对外）

**场景**：产品停售、规则调整、服务变更等通知。篇幅短（1-3 页），可不要目录。
章节：告知事项（一句话说清）→ 变更内容（table：变更前/变更后）→ 对您的影响 → 您需要做什么（steps）→ 生效时间 → 联系方式（contact）。
**必备**：生效日期、联系方式。语气礼貌、简明，避免内部术语。

## 10. 合规自查报告 `compliance`（对内）

章节：自查概述（kpi：检查项/问题数/已整改）→ 检查范围与方法 → 发现的问题（table：问题/依据/等级/责任人/期限）→ 风险评估（matrix）→ 整改计划（timeline 或 steps）→ 结论。
**必备**：问题清单、整改责任人。
**写法**：每个问题写明依据的制度条款；整改项写具体动作，不写“加强管理”。
