# 读懂需求：推断规则与提问原则

## 推断优先，提问其次

用户的一句话里通常已经包含了大部分信息。按下表推断，推断不出、且会明显改变结果的才问。

| 线索 | 推断 |
|---|---|
| “给客户”“发给客户”“客户版” | 对外 → 严格合规，去掉内部信息 |
| “给新人”“培训”“带教” | 培训手册，读者基础弱 |
| “给领导”“汇报”“管理层” | 经营分析/项目方案，结论先行，premium 风格 |
| “制度”“办法”“规程” | 管理制度，minimal 风格，分条写 |
| “理赔怎么办”“出险” | 理赔指引 |
| “一页纸”“简单说明” | 篇幅 1-2 页，不要目录 |
| “详细”“完整” | 篇幅 10 页以上 |
| 提到具体季度、年份 | 时间口径 |
| 提到具体客户、家庭成员 | 客户方案 |
| 没说对内对外 | 按文档类型默认（见 blueprints.md 标题） |

## 什么时候该问

只问会**明显改变文档结构或合规要求**的问题，一次最多 3 个，并且给出你的默认选择，让用户可以直接说“按默认”：

- ✅ “这份是发给客户还是内部培训用？（默认按内部培训写）”——对内对外差别很大
- ✅ “要覆盖所有重疾产品，还是只写安康重疾？”——范围差别很大
- ❌ “您希望用什么字体？”——不该问
- ❌ “需要目录吗？”——自己按篇幅决定

用户已经明确说了“你看着办”“直接写”，就不再问，全部按默认推断。

## 需求卡片格式

```
📋 需求卡片
类型：<10 类之一>｜读者：<具体人群>｜用途：<读完要能做什么>
<对内/对外>｜约 <N> 页｜风格：<经典橙白/尊享深色/简约白>｜重点：<用户点名的内容>｜口径：<时点>
```

## 示例

**用户**：“帮我把重疾理赔的流程整理一下，给客户用的”
```
📋 需求卡片
类型：理赔服务指引｜读者：已投保重疾险的客户｜用途：出险后能自己准备材料、提交申请
对外｜约 5 页｜风格：简约白｜重点：材料清单、办理时效｜口径：现行理赔规则
```
不需要提问，直接进入蓝图设计。

**用户**：“写一份三季度的个险经营分析”
```
📋 需求卡片
类型：经营分析报告｜读者：公司管理层｜用途：了解三季度经营情况并决策下一步举措
对内｜约 10 页｜风格：尊享深色｜重点：—｜口径：2026 年三季度
```
可以问一个问题：“需要按分公司拆分对比吗？（默认按渠道和产品线分析，不拆分公司）”

**用户**：“给新人讲讲核保”
→ 类型是**培训手册**（用途是培训），不是核保说明。
