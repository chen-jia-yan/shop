# 评测用例：知识生成 Word

分两部分：**A 脚本用例**（用自带示例验证渲染、版式和质检）、**B 端到端用例**（接上 TAP 后验证 skill 的判断和写作）。

> 示例数据均为虚构。脚本尚需在装有 python-docx 和 matplotlib 的环境中实际运行验证。

## A. 脚本用例

| # | 命令 | 预期 |
|---|---|---|
| A1 | `python scripts/render_docx.py examples/product_manual.json out/product.docx` | 成功；风格 soft 淡雅蓝；字体方案 modern；一级标题 7 个；生成目录；表 2 个（保障责任一览、投保规则要素表）、图 3 个（结构图、时间线、流程图）；【待补充】4 处 |
| A2 | `python scripts/render_docx.py examples/claims_guide.json out/claims.docx` | 成功；风格 soft；无目录（toc=false）；表 1 个、图 2 个；【待补充】3 处 |
| A3 | `python scripts/render_docx.py examples/q3_analysis.json out/q3.docx` | 成功；风格 blue 商务蓝；目录；第一章为执行摘要（核心结论 + 4 条带数字的发现 + 2 项待决策）；表 1 个、图 5 个（组合图、环形图、高亮条形、进度条、四象限）；【请确认】1 处 |
| A4 | `python scripts/render_docx.py examples/service_policy.json out/policy.docx` | 成功；风格 blue；字体方案 formal（标题黑体、正文宋体、西文 Times New Roman）；正文首行缩进 2 字；标题无自动编号；页脚左侧“FWD-OP-2026-012　V3.0” |
| A5 | A1 加 `--style blue`、`--style navy`、`--style classic` 各生成一份 | 内容一致，只有封面、标题样式、表格样式、强调色不同；classic 为原橙色版 |
| A6 | A3 加 `--font-preset formal` | 正文改为宋体；图表仍为黑体系 |
| A7 | A1 加 `--font-cn 思源黑体` | 正文为思源黑体，标题仍按方案（微软雅黑）；命令行指定优先于方案 |
| A8 | 每个渲染命令的输出末尾 | 打印“内容体检”：四份示例预期无提示（如有，逐条核对是规则误报还是内容问题） |
| A9 | `python scripts/review_docx.py out/product.docx --doc-type product` | 通过（退出码 0）；说明中列出【待补充】4 处 |
| A10 | A9 加 `--final` | 不通过（退出码 1），原因是占位符未处理 |
| A11 | `python scripts/review_docx.py out/policy.docx --doc-type policy` | 通过：适用范围、职责、施行三项必备要素齐全 |
| A12 | 在 product_manual.json 某段加入“本产品保本稳赚，比存银行划算”后渲染并质检 | 不通过：收益承诺 2 处（保本、稳赚）、存款类比 1 处 |
| A13 | 删除 product_manual.json 中所有含“等待期”的内容后质检 | 不通过：缺少必备要素“等待期” |
| A14 | 把某个 table 的一行删掉一列后渲染 | 退出码 2，提示“第 N 个元素（表格）第 M 行有 X 列，表头是 Y 列” |
| A15 | 把某个元素的 type 改成 `diagram` | 退出码 2，提示未知类型 |
| A16 | progress 某项 value 写成“较好” | 退出码 2：value 必须是数字 |

**打开 Word 时重点看：**
- [ ] 打开时没有“无法读取的内容”提示
- [ ] 封面单独一页，后面没有多出空白页；淡雅蓝封面左侧两条竖色带贯通整页，商务蓝封面顶部细条 + 浅蓝色块
- [ ] 商务蓝一级标题为“左竖条 + 浅蓝底纹”，文字上下有留白；淡雅蓝为细下划线
- [ ] 表格：淡雅蓝为三线表；商务蓝为浅蓝表头 + 蓝色底线；数字列右对齐；“同比”列正数绿、负数红；制度示例“较上一版”列缩短的时限为绿色
- [ ] 执行摘要：深色标题栏、浅底核心结论、左侧大号数字；“需要决策”为红色方框
- [ ] 进度条：华东条形和数值为红色，100% 处有深色刻度线
- [ ] 正文第一页页脚显示“第 1 页 / 共 N 页”；有文档编号的左侧显示编号和版本
- [ ] 目录更新域后显示页码
- [ ] 图表中文正常显示（不是方块），配色随风格变化，负值为红色
- [ ] 跨页表格每页都有表头

## B. 端到端用例（接上 TAP 后）

| # | 用户输入 | 关键检查点 |
|---|---|---|
| B1 | “把安康重疾整理成一份给客户的产品说明书” | 类型 product、对外、淡雅蓝；包含犹豫期/等待期/责任免除/风险提示；有要素表和投保/理赔举例；无内部信息；数字都有出处 |
| B2 | “给新人讲讲核保，做成培训材料” | 类型判断为 **training**（不是 underwriting）；有学习目标和自测题；每条规则配例子 |
| B3 | “写一份三季度个险经营分析，给领导看” | 风格 blue；第一章是执行摘要 + KPI；每章有数字；图表 caption 写结论 |
| B4 | “出一页纸说明一下理赔要带什么” | 1-2 页；无目录；以清单为主 |
| B5 | “帮我写一份客户方案”（没说客户情况） | 应询问客户家庭情况（最多 3 问并给默认）；不编造客户信息 |
| B6 | 主题在知识库中检索不到 | 告知未找到并建议换说法；不生成空壳文档 |
| B7 | 两份制度对同一时限说法不同（30 天 / 15 天） | 用更新时间新的；文中或交付说明提示冲突 |
| B8 | “客服热线是多少”只能靠推测 | 写【待补充】，绝不编造号码 |
| B9 | “帮我写个制度，越详细越好” | formal 字体；分条写“第 X 条”；有适用范围、职责、生效；附版本记录和签批栏 |
| B10 | 质检出现“必须修改” | 回到撰写阶段修改后重新渲染，不直接交付 |
| B11 | 知识库资料很少，只够写原则 | 不用套话凑篇幅：缩短篇幅、写【待补充】，交付说明里讲清缺什么 |
| B12 | 用户只问“等待期是多少天” | 不触发本 skill（交给 qa_advance） |
| B13 | 用户要“做成 PPT” | 不触发本 skill（交给 kb-to-ppt） |

**评分**：每条按七维评分（reference/quality-rubric.md），各项 ≥4 分为通过。
