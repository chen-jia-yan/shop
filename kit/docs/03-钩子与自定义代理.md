# 03 钩子与自定义代理

## 零、它们是自动触发的吗？
| 东西 | 会不会自动 | 说明 |
|---|---|---|
| 钩子（守卫、改后检查、会话注入） | **一定自动** | Copilot 每次调用工具、每次会话开始都会执行，不依赖模型 |
| 个人规则 | **一定自动** | 每个会话都会读 |
| 技能 | 大多数时候自动 | 模型根据技能的说明判断要不要加载；你输入 `/kit-xxx` 时一定加载 |
| 自定义代理 | 不一定 | 主会话有时会自己委派；你用 `/agent` 选择或 `--agent` 启动时一定生效 |

所以工具包这样安排：
- 个人规则 + 会话注入写明“开发需求默认走 /kit-autopilot”，并且 kit-autopilot 的说明里写着“即使用户没有点名也要使用”，这样**大多数时候你只要说需求**；
- 想百分之百确定，就在会话开始时 `/agent` 选 **kit-orchestrator**（总调度），之后整个会话都按流程走；
- 总调度再把执行、评审委派给其他代理，你不用自己去切换。

## 一、自定义代理（回答你的问题：/agent 和 “set agent - configure custom agents” 怎么用）

### 它是什么
一个代理 = 一个 `.agent.md` 文件：开头写名字、说明、**能用哪些工具**，正文写它的职责和边界。
你上次输入 `/agent` 后它直接开始执行任务，是因为你选中了某个现成代理（或者把后面的文字当成了任务）。现在工具包装好了 7 个自己的代理：

| 代理 | 工具权限 | 用途 |
|---|---|---|
| **kit-orchestrator** | 不限制（靠流程规则和守卫约束） | **总调度：日常只用它** |
| kit-planner | read, grep, glob | 只读规划 |
| kit-implementer | read, grep, glob, edit, execute | 按计划写代码 |
| kit-reviewer | read, grep, glob | 只读评审 |
| kit-verifier | read, grep, glob, execute | 只跑验证，不改代码 |
| kit-debugger | read, grep, glob, edit, execute | 排障 |
| kit-prompt-coach | read, grep, glob, execute | 写提示词 |

总调度不限制工具，是因为它需要“委派子代理”和“向你提问”这两个工具，而这两个工具在不同版本里的名字可能不一样，限制死了反而可能用不了。它不会乱改文件，靠的是三样东西：流程规则（确认前不改）、修改范围（守卫硬拦截越界）、只读的评审代理。
| kit-implementer | read, grep, glob, edit, execute | 按计划写代码 |
| kit-reviewer | read, grep, glob | 只读评审 |
| kit-verifier | read, grep, glob, execute | 只跑验证，不改代码 |
| kit-debugger | read, grep, glob, edit, execute | 排障 |
| kit-prompt-coach | read, grep, glob, execute | 写提示词 |

### 三种用法
1. **会话里选择**：输入 `/agent`，在列表里选 kit-xxx，然后再输入任务（先选，再说任务）。
2. **启动时指定**（1.0.105；bat 版本要看 bat 是否把参数传下去）：`copilot --agent kit-planner`
3. **让主代理自己判断**：直接说“用 kit-reviewer 代理评审这次改动”。

### “configure custom agents” 按钮
它是 Copilot 自带的“新建代理”向导，会问你名字、说明、工具，然后在 `~/.copilot/agents/`（个人）或项目的 `.github/agents/`（项目）下生成一个 `.agent.md`。
**建议不用这个向导，改用脚手架**，因为脚手架生成的格式固定、会自动检查，还能顺手加桌面宠物按钮：
```
python tools\kit_new.py agent kit-sql-reviewer "只读审查 SQL 和迁移脚本。用于新增表或改索引之后。" --tools read,grep,glob --button "SQL 评审"
python tools\install.py
```
同名时，个人/项目里的代理优先于插件里的代理。

### 文件格式（工具包里的写法）
```
---
name: kit-reviewer
description: 一句话说清做什么、什么时候用（模型靠它判断要不要用这个代理）
tools: ["read", "grep", "glob"]
strict-tools-list: true            # 严格按列表，不额外给工具
include-custom-instructions: true  # 同时遵守个人规则
---
正文：职责、边界、交付格式
```
需要给某个代理指定便宜的模型时，在开头加一行 `model: 模型名`（模型名以 `/model` 列表里的为准）。

## 二、钩子（硬拦截）

### 为什么要钩子
规则写在提示词里，模型可能忘、可能“理解错”；钩子是 Copilot 在**每次调用工具之前**执行的程序，它说“不行”，这次调用就不会发生。这是唯一不依赖模型自觉的防线。

### 三个钩子
| 钩子 | 时机 | 做什么 | 超时 |
|---|---|---|---|
| session_start.py | 会话开始 | 注入：当前模式、项目路径、受保护区域、本次修改范围、项目注意事项、有效记忆（总共 ≤1800 字） | 10 秒 |
| guard.py | 每次调用工具前 | 检查并拒绝违规操作（见下表） | 5 秒 |
| post_edit.py | 修改文件后 | 检查刚改的文件：编码、隐形字符、Python 语法；有问题把提示附加给模型 | 10 秒 |

### 守卫拦截规则
| 规则 | 拦截什么 | 放行什么 |
|---|---|---|
| protected-file | 读/改/打印 .env、.env.*、密钥、证书、providers.json | .env.template / .env.sample；`Test-Path .env` |
| git-write | add/commit/push/pull/merge/rebase/reset/checkout/restore/stash/clean/新建分支等 | status/diff/log/show/grep/ls-files/blame、`stash list`、`branch --show-current` |
| shell-write / shell-redirect | `>`、`>>`、Out-File、Set-Content、Add-Content、Tee | `2>&1`、`> $null` |
| package-install | pip/uv add/remove/sync/lock、npm、poetry、conda | — |
| locked-file | 改 pyproject.toml、uv.lock、requirements*.txt、*.lock | 修改范围里勾了“允许修改锁定文件” |
| protected-area | 改项目配置里的受保护区域（同事的问答插件） | `backends/kg_browse.py`；修改范围里明确列出的文件 |
| out-of-scope | 改修改范围以外的文件 | 范围内文件；没设置范围时不限制 |
| ruff-format | ruff format | ruff check |
| dangerous-delete | 递归删除 | — |
| forbidden-marker | 写入 `# type: ignore`、`# noqa`、skip、xfail、`cast(Any,` | 照抄 `# type: ignore[import-untyped]`；markdown 文档里的文字 |
| invisible-char / fullwidth-space | 写入零宽字符、全角空格 | — |
| custom-deny | 配置 `guard.extra_deny_command_patterns`（已加 Neo4j 的 `DETACH DELETE`） | — |

### 安全设计（风险都考虑过）
- **守卫自己出错**：Copilot 对“命令型钩子出错”的处理是**拒绝**（宁可挡住）。为了不因为守卫的 bug 让你什么都做不了，守卫内部捕获所有异常，出错时记日志并放行（`guard.on_error`，默认 allow）；同时 kit_doctor 和 selftest 会提前发现守卫问题。
- **超时**：超时会被当作放行。所以守卫只做纯文本判断，不访问网络、不运行 git，通常几十毫秒完成。
- **紧急关闭**：`python tools\install.py --no-hooks`，或在 kit.config.json 里 `guard.enabled: false`。
- 拦截日志脱敏：日志里的口令、密钥、连接串会被替换掉。

### 测试守卫
```
python hooks\guard.py --selftest        # 27 条内置用例
python tools\run_evals.py --only guard  # 事故用例
```
