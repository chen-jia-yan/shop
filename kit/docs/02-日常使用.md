# 02 日常使用

## 最常用：直接说需求，剩下的交给总调度
在 Copilot 里用大白话说需求就行，例如：
> 知识库重复上传同一个文件时，不要生成第二份数据

接下来会自动发生（你只在三个地方说话）：
```
分析需求、查代码 → （有查不到的才问你，带选项）→ 写出方案
        → 【你回复“确认”】
→ 每一步：锁定修改范围 → 执行（交给执行代理）→ 跑验证 → 评审（交给只读评审代理）
        → 【你决定修哪些】→ 修完再验证、再评审
→ 给出提交命令 → 【你自己提交】→ 下一步 … → 总结 + 建议记住的教训
```
| 你要做的 | 什么时候 |
|---|---|
| 回复“确认”（或者说要改哪里） | 方案出来后。确认前它不会改任何文件 |
| 选修哪些问题 | 每次评审后。每次修复前都会先问你 |
| 执行提交命令 | 每一步验证、评审都过了以后。git 写操作一直由你来做 |

## 怎样让它“自动”走这个流程
有三层保障，越往下越稳：
1. **个人规则**（已安装，每个会话都会读）：写明“开发类需求默认按 /kit-autopilot 流程”。
2. **会话开头注入**（钩子，每次都执行）：再提醒一次流程。
3. **直接选总调度代理**（最稳）：会话开始时输入 `/agent`，选 `kit-orchestrator`。1.0.105 可以直接 `copilot --agent kit-orchestrator` 启动。
平时靠 1、2 就会自动走；如果发现它没按流程（比如没出方案就开始改），说一句“按 /kit-autopilot 流程来”，或者用第 3 种方式。
只是问问题、解释代码、查资料时，它不会走这个流程，直接回答。

## 只有一个窗口也没关系（公司 bat 版本）
1.0.75 只能开一个会话、不方便换模型，所以流程设计成**全程在一个会话里完成**：
- 执行、评审交给**子代理**（总调度用 task 工具委派）。子代理有独立的上下文，主会话不会被大量改代码的过程挤满，也不用开新窗口；
- 一个大任务做到一半上下文变长时，输入 `/compact` 压缩，再继续；
- 如果你的版本不支持委派子代理，总调度会自己按同样的规则执行，流程不变，只是上下文会长一些。

## 桌面宠物
双击 `widget\start_widget.bat`，屏幕右下角会出现一个 Q 版小机器人（设置里可以换成小猫）。它的样子告诉你进行到哪了：
| 它的样子 | 表示 |
|---|---|
| 轻轻浮动、眨眼 | 空闲 |
| 头顶冒“…”，眼睛往上看 | 在分析需求 / 写方案 |
| **蹦蹦跳、天线闪橙光、冒气泡** | **需要你处理**：等你确认方案 / 有问题问你 / 等你决定修哪些 / 等你提交 |
| 专心敲键盘、旁边齿轮转 | 在改代码（肚子上显示第几步） |
| 脚下进度条 | 在跑验证 |
| 戴眼镜、拿放大镜 | 在评审 |
| 星星眼、撒花 | 完成 |
| 冒汗 | 卡住了，需要你看一下 |
| 举红色盾牌 | 守卫刚拦住一次危险操作（气泡里写着拦住了什么） |
| 天线白光一闪 | Copilot 刚调用了一次工具 |
| 打瞌睡 Zzz | 15 分钟没有动静 |

**你不需要操作它**。它只负责“看”：
- 项目自动跟随：在哪个目录打开 Copilot，它就知道是哪个项目，不用选；
- 进度自动跟随：总调度每到一个阶段，它就换个样子；
- 需要你出手时（确认方案、回答问题、选修哪些、提交），它会跳起来、冒气泡、响一声。

想用的时候只有三个动作：
| 动作 | 结果 |
|---|---|
| **单击** | 告诉你现在进行到哪、**你现在该做什么**（例如“去 Copilot 窗口看方案：没问题就回复‘确认’”） |
| **拖动** | 换个位置（会记住） |
| **右键** | 只有 5 项：现在进行到哪了 / 一键验证（当前项目）/ 记住一件事 / 更多工具 / 设置 |

“更多工具”里是手动模式、提示词、检查、记忆等，平时用不到；“设置”里换造型（机器人 / 小猫）、大小、置顶、安静模式，还能“再看一遍使用提示”。
第一次打开时它会用 4 个气泡自我介绍一遍。

宠物不会控制 Copilot，也不需要开第二个窗口；它只读进度和守卫日志。

## 项目怎么选、怎么更新（不用手动选）
| 你在哪里打开 Copilot | 工具包怎么处理 |
|---|---|
| 登记过的项目（tap-ai-backend、fwd-tap-ingest） | 用登记的设置：测试命令、受保护区域（同事的插件）、注意事项、风格包 |
| 没登记的 git 仓库（新项目） | **自动识别**：项目名=文件夹名，按 pyproject / uv.lock / tests 目录推断测试和 lint 命令，直接能用 |
| 不是代码仓库的目录（写文档、查资料、日常问答） | 当作普通助手，不走开发流程，不注入项目信息 |

所以项目**不需要你维护**。只有这些情况才需要登记一下（宠物右键 → 更多工具 → 工具 → 把当前项目登记下来，或命令 `python tools\kit_project.py add`）：
- 要设置“不能改”的目录（像同事的问答插件）；
- 要写项目注意事项（像 jp-poc 只读）；
- 自动识别的测试命令不对。
登记后打开配置文件改对应的项目即可。其他命令：`kit_project.py`（看当前目录被识别成什么）、`kit_project.py list`、`kit_project.py remove 名字`。
总调度在没登记的项目里工作时，如果发现需要这些设置，也会提醒你登记。


## 想单独用某个代理（手动模式）
宠物右键 → 更多工具 → 手动模式，或会话里 `/agent` 选择：
| 代理 | 用途 | 权限 |
|---|---|---|
| kit-orchestrator | 总调度（默认推荐） | 全部，靠流程和守卫约束 |
| kit-planner | 只做规划 | 只读 |
| kit-implementer | 执行一步 | 读、改、执行 |
| kit-reviewer | 评审 | 只读 |
| kit-verifier | 只跑验证 | 读、执行 |
| kit-debugger | 排障 | 读、改、执行 |
| kit-prompt-coach | 写提示词 | 读、执行本地体检工具 |

## 不用宠物也可以（命令行）
```
python tools\prompt_lint.py "需求原话"
python tools\run_checks.py                      （在项目目录里运行，不用写项目名）
python tools\commit_helper.py --message "K2a: 图谱按 saas_id 过滤 scope"
python tools\kit_status.py show
```

## 被守卫拒绝了怎么办
Copilot 会看到一句以 `ai-dev-kit 守卫` 开头的原因，宠物也会举盾牌提醒你：
- `[out-of-scope]` 越界修改 → 如果确实要改，告诉总调度“把 xxx 加进这一步的范围”；
- `[git-write]` → git 写操作你自己执行；
- `[protected-file]` → 需要知道某个配置时，告诉它配置名和是否已设置，不要给值。
所有拦截都记在 `~/.ai-dev-kit/logs/`（敏感内容已脱敏）。

## 每天结束时（可选，2 分钟）
总调度每个任务结束时会建议 1～3 条值得记住的内容，你说“保存第 1、3 条”就行；或者宠物右键 → 记忆 → 记住一件事。每周点一次“核对是否过期”。
