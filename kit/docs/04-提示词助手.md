# 04 提示词助手

你说过“有时候我的指令比较笼统，表达得不够具体”。工具包用三层来解决，从免费到花额度：

## 第 1 层：需求体检（不花额度，1 秒）
双击桌面宠物 → 写下需求 → **体检一下**，或：
```
python tools\prompt_lint.py "帮我优化一下知识库上传"
```
它按 8 个维度打分（满分 100），这 8 个维度是 Anthropic、OpenAI、GitHub 提示词指南共同强调的要素：

| 维度 | 分值 | 问自己 |
|---|---|---|
| 目标 | 20 | 要做成什么？（动作 + 对象） |
| 位置 | 15 | 哪些文件、模块、接口？ |
| 背景 | 10 | 现在什么情况？报错原文？ |
| 约束 | 12 | 哪些不能做？ |
| 完成标准 | 15 | 怎样算完成？（可检查的结果） |
| 验证方式 | 12 | 跑什么命令证明？ |
| 输出要求 | 8 | 做完交回什么？ |
| 示例 | 8 | 有没有参照写法？ |

另外会扣分并指出含糊词（优化一下、看看、处理下……），并提醒“一段话里有几件事，建议拆开”。

## 第 2 层：补全为 R3（不花额度）
宠物右键 → 提示词 → **补全为 R3 提示词**，或加 `--r3`：
```
python tools\prompt_lint.py "……" --r3 --project tap-ai-backend
```
它把你的话放进 R3 结构（通用规则 → 任务 → 背景 → 允许修改的文件 → 要求 → 绝对禁止 → 完成标准 → 验证 → 输出 → 核对表），**缺的部分写成【待补充：……】**，提醒你自己填，不会替你编。项目的受保护区域、验证命令会自动带上。省 token 模式下自动用精简的输出要求。

## 第 3 层：提示词教练（花一点额度，效果最好）
宠物右键 → 提示词 → **提示词教练（AI）**，或在会话里用 kit-prompt-coach 代理 / `/kit-prompt-craft` 技能。它会：
1. 先体检；
2. **自己去代码里查**能查到的（文件在哪、函数叫什么、测试放哪）——不会拿这些来问你；
3. 只问查不到、又会改变做法的问题（最多 5 个，每个带选项和推荐项）；
4. 输出可以直接复制的完整提示词，再体检一次确认 ≥ 80 分。

## 含糊说法速查（完整版在 skills/kit-prompt-craft/references/vague-signals.md）
| 你想说 | 改成 |
|---|---|
| 优化一下上传 | 把 100 个文件批量上传的失败率从 30% 降下来：先按失败原因分类统计 |
| 看看图谱那块 | 只读检查 application/library_kg.py 的 scope 过滤，告诉我是按 entity scope 还是 saas_id 筛选，不要改代码 |
| 完善测试 | 给 delete_file 补三条测试：正常删除、文件不存在、只读索引拒绝 |
| 跟之前一样 | 照 api/conversations.py 的 /add 接口写法 |

## 写完提示词以后
用总调度（默认流程）时，修改范围由它在你确认方案后自动锁定；手动模式下用 `python tools\scope.py from-prompt --project 项目名 提示词文件`，按提示词里【本次允许修改的文件】一段锁定。

## 和自动流程的关系
用总调度（默认流程）时，第 1～3 层是**自动发生**的：它会先体检你的原话、自己查代码、只问查不到的问题，再出方案。所以平时你不需要单独用这一页的工具；只有想先自己把需求理清楚、或者要写给别人看的提示词时才用。
