# 验证改动

## 什么时候用
- 代码改完了，要证明它是对的。
- 想知道上一次执行报告里的“测试通过”是不是真的。

## 绝对禁止
1. 绝对禁止只写“测试通过”而不贴原始输出。
2. 绝对禁止把 0 条测试、收集报错、全部 skipped 当成通过。
3. 绝对禁止为了让验证通过去改测试或加跳过标记。
4. 绝对禁止在验证阶段修改业务代码（发现问题就报告，修复交给下一步）。

## 步骤
1. 运行一键验证（项目名见会话开头的“当前项目”）：
   `{{PYTHON}} {{KIT_ROOT}}/tools/run_checks.py --project <项目名>`
   - 内容没变时会直接返回上次结果（显示“命中缓存”），这是正常的，能省时间和额度。
   - 确实需要重跑时加 `--force`；需要包含较慢的检查（导入隔离、测试收集）时加 `--full`。
   - 只想跑某一项：`--only tests` 或 `--only static`。
2. 读输出：
   - `>` 开头的是失败行，`=` 开头的是测试汇总行，`!` 开头的是识别出的假通过问题。
   - 完整日志路径在最后一行，需要时 view 它。
3. 如果有失败，按失败类型给出下一步建议：
   - 收集阶段报错 → 用 `/kit-debug-bug` 查导入；
   - 断言失败 → 指出期望值和实际值；
   - 编码问题 → 指出文件和行号（多半是 PowerShell 写文件或复制粘贴带进了不可见字符）；
   - 静态检查问题 → 指出对应的事故类别。
4. 全部通过时，确认测试数量和本次改动相关（例如新增了 3 条测试，汇总里的数量应该相应增加）。

## 输出格式
```
【验证命令】……
【结果】通过 / 失败（是否命中缓存）
【测试汇总】collected N，passed N，failed N，skipped N
【问题】（> 和 ! 开头的行原样贴出）
【下一步】……
【核对表】
- [ ] 贴了原始输出
- [ ] 测试数量 > 0 且与本次改动相符
- [ ] 没有跳过、没有收集报错
- [ ] 没有修改代码
```
