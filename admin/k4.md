K4 repo 第二次修正，做完出完整《完成报告》，中途不用停：

一、KbJobRepo
1. mark_job_succeeded、mark_job_retry、mark_job_failed 都增加必填参数 expected_attempts: int，
   WHERE 统一为：id == job_id、status == "processing"、attempts == expected_attempts、未删除
2. mark_job_retry 修正：WHERE 不再判断 status == "pending"（按第 1 条）；
   SET：status="pending"、error_code、error_message、heartbeat_time=None、update_time=now
3. mark_job_retry、mark_job_failed 增加可选参数 stale_before: int | None = None；
   不为 None 时，WHERE 再加 heartbeat_time < stale_before（用于心跳超时回收）
4. list_pending_job_ids 按 create_time 升序、id 升序排序（先来先处理）
5. list_stale_jobs 返回的对象中能取到 attempts、max_attempts、document_id（确认即可，没有就补）

二、KbDocumentRepo
1. 新增 mark_document_requeued(self, document_id: str, error: str | None, now: int, *, commit: bool = True) -> bool
   WHERE：id 相等、status == "processing"、未删除
   SET：status="pending"、last_error=error、update_time=now
2. mark_document_processing 的 WHERE 增加 status.in_(["pending", "processing"])
3. mark_document_indexed、mark_document_failed 的 WHERE 增加 status == "processing"

三、在 KbJobRepo 类的文档字符串里用中文写明调用顺序（给 K7 用，不实现 worker）：
   先更新任务（带 expected_attempts），返回 True 才更新文档；两步都传 commit=False，最后统一 commit；
   任务更新返回 False 时 rollback，不更新文档

四、测试（fake 或现有方式，不连数据库）：
- mark_job_retry：processing + attempts 一致 → True；attempts 不一致 → False；status 为 pending → False
- mark_job_succeeded / mark_job_failed：attempts 不一致 → False
- stale_before 传入时，生成的 SQL 中带有 heartbeat_time 条件（可断言 str(stmt) 或 fake 记录的条件）
- mark_document_requeued：processing → True；indexed → False
- mark_document_indexed：status 不是 processing → False
