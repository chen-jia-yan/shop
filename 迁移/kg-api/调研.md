二、统一规范（全部照 TAP）
1. 前缀 /tap/ai/kg。详情用 GET /{id}，其余全部用 POST
2. 响应格式、错误码完全照第一步第 6 条的 TAP 规范。出错时 HTTP 状态码仍是 200，响应体为 {code, message}；找不到资源时用和 TAP 相同的业务错误码
3. 分页：请求 page（默认 1，最小 1）、page_size（默认 20，范围 1–100）；返回 items、total、page、page_size
4. 所有 POST 请求接受 TAP 的 4 个租户字段（可选，演示阶段不使用，但要能接收，不报错）
5. 图数据统一格式：
   nodes：[{id, name, type, properties, source_files}]
   edges：[{id, source, target, type, properties}]
   字段名固定是这几个，不得改名。SQLite 中没有的字段：properties 给 {}，source_files 给 []
6. 子图类接口必须有数量上限：overview 节点最多 300 个；expand 最多 2 跳、最多 200 个节点。超过上限时截断，并在 data 中返回 truncated: true

三、7 个接口
1. POST /tap/ai/kg/stats：节点总数、关系总数、各节点类型的数量、各关系类型的数量
2. POST /tap/ai/kg/files/list：分页。每个来源文件一行：文件名、节点数、关系数
3. POST /tap/ai/kg/graph/overview：请求 source_file（可选）、node_types（可选，数组）、limit（默认 100，最大 300）；返回 nodes、edges、truncated
4. POST /tap/ai/kg/nodes/search：请求 keyword（按名称模糊匹配）、node_type（可选）、分页；返回 items（不含 properties）
5. GET /tap/ai/kg/nodes/{node_id}：节点完整信息，加上它的关系数量
6. POST /tap/ai/kg/nodes/expand：请求 node_id、depth（1 或 2，默认 1）、limit（默认 100，最大 200）；返回 nodes、edges、truncated（包含中心节点本身）
7. GET /tap/ai/kg/chunks/{chunk_id}：切片原文、来源文件、页码。SQLite 中没有切片原文的话，这个接口统一返回业务错误"当前数据中没有切片原文"，并在接口文档中注明
