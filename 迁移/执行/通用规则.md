【通用规则（每次都必须遵守，违反任何一条都视为任务失败）】

一、工作方式：两步走
1. 第一步"开工前确认"：只读文件、运行检查命令，然后输出《开工前确认》，内容包括：
   a. 你读了哪些文件
   b. 你打算照抄的现有写法：每一项贴出原文代码（文件:行号）
   c. 本阶段要新增、修改的文件清单
   d. 本提示词中与仓库实际情况不符、或你拿不准的地方
   e. 基线结果：在修改任何代码之前，运行下面四条命令，贴出每条命令的最后 30 行原始输出
      uv run ruff check .
      uv run ruff format --check .
      uv run pytest -q
      uv run mypy src
   输出确认后停下，不要修改任何文件。等我回复"继续"后，才能进入第二步
2. 第二步"实施"：严格按提示词实现，完成后输出《完成报告》（格式见第七条）

二、必须先读的文件（每个阶段开始都要读）
- .github/copilot-instructions.md
- docs/代码导读-主流程与分层.md
- docs/API-文档.md
- 本阶段提示词里点名的文件
仓库规范与本提示词冲突时，不要自己选择，停下来告诉我

三、git
- 只允许运行只读命令：git status、git diff、git log、git branch
- 不切换分支、不提交、不推送、不合并、不 stash、不 reset。所有写操作由我本人执行

四、修改范围
- 只能新增或修改本阶段提示词列出的文件
- 对已有文件只允许"追加"：bootstrap.py、persistence/models.py、api/dto.py、config/settings.py、.env.example，以及提示词明确允许的文件。不得修改或删除已有代码
- 不得修改：现有测试、pyproject.toml（不得新增依赖）、ruff / mypy / pytest 配置、其他功能模块（会话、聊天、文件等）
- 觉得必须改上面这些地方才能完成任务时，停下来说明原因，不要自己改

五、禁止事项
- 不执行任何 SQL；不连接 MySQL、Redis、Azure、大模型；不读取 .env
- 不修改旧项目 jap-cycle-poc 的任何文件，只能从里面复制代码
- 不使用 # type: ignore、# noqa、pytest.skip、pytest.mark.xfail
- 除非提示词明确允许，不留 pass、TODO、NotImplementedError 这类占位实现
- 不对整个仓库运行 ruff format（不带 --check）。修排版只对本阶段新增的文件运行
- 提示词没提到的功能一律不做，不要"顺手优化"
- 不确定就停下来问，不要猜

六、代码规范
- 分层：api → application → core → contracts。core 只能依赖 contracts，不得 import persistence、plugins、prompts、api；application 不得 import api
- 注释和文档字符串用中文（遵守 copilot-instructions.md）
- 配置只能写在 config/settings.py
- 业务错误使用仓库现有的 BusinessError，错误码一律用 CCB001，不新造错误码
- 命名、文件组织、类型注解风格，全部照抄提示词指定的参考文件

七、《完成报告》格式
1. 改动文件清单：每个文件标明"新增"或"修改"，以及新增/删除的行数
2. 验收清单：把本阶段提示词里的验收清单逐条复制过来，每条标 ✅ 或 ❌，✅ 要附证据（文件:行号，或测试名称），❌ 要写原因
3. 偏离说明：所有和提示词不一致的地方及原因。没有就写"无"
4. 四道关结果：四条命令各自的最后 30 行原始输出，并和基线逐项对比（新增了哪些失败）
5. 需要我做的事
