【第二步要做的】
一、application/library_chunks.py：ChunkReviewService
构造参数：settings、draft_repo、chunk_source: ChunkSourcePort | None、publisher: ChunkPublishPort | None、now_ms: Callable[[], int]

1. 查看（chunk_source 为 None 时，三个方法都报"切片数据源未配置"）
   - list_files(req) -> LibraryFileListData
   - get_file(file_id) -> LibraryFileDetailData；返回 None 时报"文件不存在"
   - list_chunks(req) -> LibraryChunkListData；文件不存在时报"文件不存在"
2. 新建草稿 add_draft(req) -> ChunkDraftData
   - chunk_source 为 None → "切片数据源未配置"；get_file 返回 None → "文件不存在"
   - 用 list_chunks 分页取出该文件的全部切片：page_size=200，从第 1 页开始，直到取到的条数等于 total
   - total 超过 5000 → "文件切片数量超过上限"
   - 每条切片转成 DraftChunk(chunk_id=原 chunk_id, page_or_sheet=原值, content=原值, origin="source")，顺序保持不变
   - 写入草稿：status=draft、base_chunk_count=total、source_file、operator=请求里的 user_id
3. 查询：list_drafts(req)、get_draft(draft_id)；不存在时报"草稿不存在"
4. 修改 update_draft(req) -> ChunkDraftData
   - 草稿不存在 → "草稿不存在"
   - 当前状态不是 draft 或 publish_failed → "草稿当前状态不允许此操作"
   - 内容校验，任一条不满足就报"草稿内容不合法"：
     · origin 为 "source" 或 "edited" 时 chunk_id 不能为空
     · origin 为 "added" 时 chunk_id 必须为 None
     · content 去掉首尾空白后不能为空
     · 同一个 chunk_id 不能出现两次
   - 用 update_chunks 保存，状态回到 draft
5. 删除 delete_draft(req)
   - 草稿不存在 → "草稿不存在"；状态为 submitted → "草稿当前状态不允许此操作"；否则软删除
6. 提交 submit_draft(req) -> ChunkDraftData，按顺序：
   a. 草稿不存在 → "草稿不存在"
   b. 状态不是 draft 或 publish_failed → "草稿当前状态不允许此操作"
   c. settings.library_chunk_publish_enabled 为 False → "落库功能未启用"
   d. publisher 为 None → "落库服务未配置"
   e. chunk_source 为 None → "切片数据源未配置"
   f. 过期检查：get_file(file_id) 返回 None，或返回的 chunk_count 不等于草稿的 base_chunk_count → "文件已重新入库，请重新创建草稿"
   g. transition_status(from=[draft, publish_failed], to=submitted, submitted_time=now)；返回 False（被别的请求抢先提交了）→ "草稿当前状态不允许此操作"
   h. 调用 publisher.publish(file_id=..., chunks=草稿全部切片, operator=请求里的 user_id)，只调用一次
      - 返回 success=True → 状态改为 published，写 published_time，publish_result 存 PublishResult 的内容
      - 返回 success=False → 状态改为 publish_failed，publish_result 存 PublishResult 的内容
      - 抛出 Exception → 状态改为 publish_failed，publish_result={"success": false, "message": "{异常类名}: {异常信息}"}（最多 2000 字）；不把异常抛给前端
   i. 返回最新的草稿
   - 不在本阶段做知识图谱同步（写进 P5 的已知限制）
