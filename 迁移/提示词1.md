## 分層依賴方向 (單向)
```
api → application → contracts ← plugins
          ↑
          core
          ↑
     persistence
```
- api 只調用 application 和 contracts (請求模型)
- application 調用 persistence (repo) 和 contracts
- core 只依賴 contracts (Protocol)，不依賴任何具體實現
- plugins 實現 contracts 中的協議

## 2.1 關鍵子系統補充
### Skill 系統（plugins/skills/、registries/）：
- Skill 鏈 (Skill Chain) 是工具之外的另一條能力路徑
- 數據流：`capability → skill_index → skill_catalog → SkillSpec`
- 核心組件：`LocalSkillCatalog` (本地索引)、`SkillSyncService` (啟動時同步預置 Skill)
- 零 Skill 部署合法：`skill_index` 在就緒探針中標記為可選組件

### 工具系統（plugins/tools/、plugins/executor/）：
- `ToolRegistry` 從 `ToolSpec + EffectPolicy` 組裝工具
- 三大受限執行器：`shell` (沙箱命令)、`http` (受控 HTTP)、`workspace` (文件操作)
- `stream_progress=True` 的工具可通過 SSE token 事件（`stage-progress`）上報執行進度（限流 1 次/秒、單條 ≤200 字符）


### 附件系统（plugins/attachments/、plugins/storage/）：
- 上传时可指定 `conversation_id` 绑定会话，也可不指定进入暂存态
- 暂存附件在首次被消息引用时延迟绑定到对应会话
- 启动时自动清理超过 24h 的孤儿附件（元数据 + 存储字节）

# 4. 接口规范
## 4.1 统一返回格式
- 业务错误统一返回 HTTP 200 + `{"code": "...", "message": "..."}`
- 证据：`src/tap_ai/core/errors.py:11-17 — BusinessError` 异常类
```python
class BusinessError(Exception):
    def __init__(self, code: str, message: str) -> None:
        self.code = code
        self.message = message
```
- 全局异常处理器：`src/tap_ai/bootstrap.py:79-95`
```python
@app.exception_handler(BusinessError)
async def _business_handler(request, exc):
    return JSONResponse(status_code=200, content={"code": exc.code, "message": exc.message})
```
- 成功响应：普通接口直接返回 Pydantic model（自动 JSON 序列化），无外层包装。例如会话列表返回 `ConversationListData`（含 `items`、`total`、`page`、`page_size`）。
- 内部异常返回 HTTP 500 + `{"code": "CCB500", "message": "服务内部错误"}`

## 4.2 错误码
- 业务错误码示例：`CCB001`（会话不存在）、`CCB500`（内部错误）
- 格式：`CCB` 前缀 + 3 位数字
- 错误通过 `BusinessError` 抛出，由全局异常处理器统一捕获

## 4.3 分页
- 请求模型：`ListConversationsRequest`（`contracts/conversations.py:44-53`）
```python
page: int = Field(default=1, ge=1)
page_size: int = Field(default=20, ge=1, le=100)
```

- 返回：`ConversationListData`（`api/dto.py:31-37`）— `items`、`total`、`page`、`page_size`
- 仓储层：repo.py:174-222 — ConversationRepo.list() 使用 offset + limit，先 count 总数再分页

# 7. 耗时任务
- 无独立任务队列（没有 Celery、arq、BackgroundTasks 等）
- 长时间运行的操作直接在使用 `async / await` 的 FastAPI 请求处理中执行
- 取消机制：通过 Redis 实现分布式取消信号
  - `src/tap_ai/utils/redis.py` — `set_cancel_flag(conv_id)` / `is_cancelled(conv_id)` / `clear_cancel_flag(conv_id)`
  - cancel key 格式：`ai:cancel:conversation:{conversation_id}`
  - 取消原因有三种：`user`（用户主动取消）、`disconnect`（客户端断线）、`timeout`（节点超时）
  - 断线时使用 `asyncio.shield` 保护部分结果落库，确保用户消息始终有对应助手回复（`status=cancelled`、`result_code=CANCELLED`），不会出现悬挂状态
- chat 锁：通过 Redis SET NX + Lua 脚本实现安全的会话级锁
  - lock key 格式：`ai:chat:lock:{conversation_id}`

| Dockerfile-prd | 同上 | 同上 |

共同内容：
- 基础镜像：`python:3.12-slim-bookworm`
- 系统依赖：`gcc`、`curl`、`ca-certificates`、`git` + Node.js 20（安装 GitHub Copilot CLI）
