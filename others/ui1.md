# 追加：在问答界面之外，再实现「知识管理页」和「纯检索索引页」

沿用前述同一技术栈、同一后端、同一保险场景铁律（出处可核实、版本/生效日、绝不编造）。这两个页面主要面向运维/管理员，需与终端用户的问答页做访问区分（问答页给业务员，这两页给管理员，入口/权限分开）。

## 页面 A：知识管理页（运维/管理员）
把后端已有能力做成可视化管理台：
- **上传与批处理进度**：多文件上传后立即返回、后台处理；实时显示批次进度（各文件 pending/processing/completed/failed/dead 计数、当前处理文件、进度条）。数据来自现有批次/任务状态接口。
- **文档列表与管理**：列出已入库文档（文档名、doc_id、版本/生效日、状态、chunk 数、最后更新时间）。行操作：重建索引(reindex)、删除、查看该文档的 chunk。
- **失败与死信**：单独展示 failed/dead 文件及其错误原因，提供"重试"按钮（对应 retry）。
- **健康监控小面板**：内存占用、worker 是否存活、队列积压数、死信数（来自 health 数据）。
- **审批队列**：展示待审批的动作（proposed），提供批准/驳回。删除等破坏性动作必须走这里审批，不能一键直删。
- **增量反馈**：重新扫描/上传时，显示 新增/变更/跳过(未变) 的分类结果。
- **安全约束（务必体现在 UI 上）**：删除等破坏性操作需二次确认且走审批流程；管理入口按 feature flag 控制显隐/可用。

## 页面 B：纯检索索引页（管理员/调试）
直接查 Azure AI Search、只看原始检索结果，不做 LLM 答案合成：
- **搜索框 + 检索模式切换**：关键词(BM25) / 语义(向量) / 混合(hybrid)，可切换对比。
- **筛选器**：产品线、文档类型、生效日期、doc_id。
- **结果列表**：每条命中显示——相关度分数、来源（文档名+页码/章节+版本/生效日）、命中片段（高亮匹配词）、所属 doc_id、"打开原文"。按分数排序。
- **展示当前用的检索模式**，方便对比不同模式的召回差异（用于排查"agent 为什么这么答"和调检索质量）。
- **联动**：某条结果可"带入问答页追问"，把它作为上下文发给问答。
- 明确：此页**不生成答案**，只呈现原始命中，是核对索引内容和调试检索的工具。
