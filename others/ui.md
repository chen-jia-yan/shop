# 任务：设计并实现「保险知识库问答」终端用户界面

## 背景
这是一个基于 RAG 的保险知识库智能助手：后端用 Azure AI Search 检索日文保险文档（产品条款、投保/理赔流程、话术、合规规则），把命中的片段交给模型生成答案。现在要做**面向终端用户的问答界面**。沿用项目现有前端技术栈（modern_chat_page.js 所在那套），不要引入新框架或重依赖；复用现有的问答接口。

## 目标用户与场景
主要用户是**保险业务/代理人员**。典型场景：他们常常在**面对客户或通话过程中**，需要**快速**查到"某产品的条款、投保流程、能不能这样赔、该怎么跟客户解释"，并且**必须能确认答案的出处**才敢对客户讲。所以界面要同时满足：快、可信、可核实。

## 保险场景的 5 条设计铁律（最重要，优先于美观）
1. **答案必须带出处，且可点开原文**：每个回答下方/侧边列出引用来源（文档名、页码/章节、命中片段），可一键跳转或展开原文。业务员要能当场核对再对客户说。
2. **绝不编造，查不到就明说**：检索无相关内容时，明确显示"未找到相关依据"，不要让模型硬编。这是保险场景的红线。
3. **显示版本与生效日期**：保险条款有版本和生效日，答案和来源要标注"依据文档版本/生效日"，并优先引用最新有效版本；引用到旧版本要给出提示。
4. **合规免责**：答案区固定标注"仅供参考，最终以正式资料/主管部门确认为准"，避免被当成对客户的正式承诺。
5. **为速度设计**：输入框始终聚焦、支持回车即问；提供常用问题/收藏问题快捷入口和最近提问历史，减少重复打字。

## 界面结构
- **顶部**：知识范围/产品线选择器（如按险种、文档类型）、全局提问框。
- **主区（问答）**：对话式或问答卡片式；每条回答包含——答案正文（关键结论加粗）、答案里对应句子的引用角标、下方"引用来源"区。
- **引用来源区**：每条来源显示 文档名 + 页码/章节 + 命中片段摘录 + "打开原文" + 版本/生效日 + 相关度；点击可展开或跳转。
- **侧栏**：最近提问历史、常用/收藏问题、筛选器（产品线、文档类型、生效日期范围）。
- **关键状态**：检索中（loading）、未找到依据（明确空状态）、低置信度（给出"依据较弱，请人工确认"提示）、出错（可重试）。
- **答案操作**：一键复制答案（业务员常要粘进备注或给客户的邮件）、对答案打分（👍/👎，用于改进检索）、"报告错误答案"。

## 视觉与可用性
- 风格：专业、可信、克制（保险行业观感），不要花哨。清晰区分"AI 生成的答案"与"引用的原文证据"两个区域，视觉上一眼分得清。
- 高可读性：日文文本渲染正确、字号和行距适合长文阅读；重点信息（结论、金额、期限、条件）易扫读。
- 响应式：以桌面为主（业务员多在电脑前），兼顾平板；键盘可达、符合基本无障碍（对比度、焦点态）。
