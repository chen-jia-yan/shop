## 3. KG 的 schema
### 节点
非Chunk节点（Concept / Product / System / Process / Data / Document / Role / Channel）只有3个字段：
```json
{"id": "System:SFDC", "type": "System", "label": "SFDC"}
```

Chunk节点多一个 metadata：
```json
{
  "id": "74baf908182e",
  "label": "#15_SFDC.pptx / slide-6",
  "type": "Chunk",
  "metadata": {
    "source_file": "#15_SFDC.pptx",
    "page_or_sheet": "slide-6",
    "cell_range": ""
  }
}
```

## 4. 每个节点/边有没有记录来源？
非Chunk节点：只有 id/type/label，无 source_file、doc_id、document_id、content_hash。
Chunk节点：有 metadata.source_file、metadata.page_or_sheet、metadata.cell_range。
边：只有 source/target/type，无结构化来源字段。少数边有 bridge_reason（字符串），182条有 metadata。

实例（Chunk节点的 provenance）：
```json
{
  "id": "74baf908182e",
  "type": "Chunk",
  "label": "#15_SFDC.pptx / slide-6",
  "metadata": {
    "source_file": "#15_SFDC.pptx",
    "page_or_sheet": "slide-6",
    "cell_range": ""
  }
}
```

## 5. 文档新增/更新/删除时，KG会不会跟着变？
不会。目前只能全量重建。
- kb_admin/worker.py、process_one_file.py、kb_poc/ingestion/ingestor.py 均无任何 KG 写入逻辑。
- KG 是静态 JSON，与 ingestion 管线完全解耦。
- get_default_kg() — knowledge_graph.py:338-379：每次调用重新读盘，换文件即生效，但无自动重建机制。

def query_business_graph(self, entity_name, relation_type=None, max_hops=2, include_types=None):

    node = kg.find_node(entity_name) or kg.fuzzy_match(entity_name)[0]  # L299-301
    nodes, edges = kg.subgraph([node["label"]], max_depth=max_hops, ...) # L313-318

### 其他调用点
