目标：让 rag_eval 的评估结果里带上「每维评分理由 + 判官总评 + 检索到的 chunk 正文」，使分析页面能展示检索内容、评分及原因。约束：不碰 Azure 索引、不重新入库；改动走 plan mode 给 diff；向后兼容（解析失败能降级）；判官温度保持 0.0。

阶段A·只读确认（先做，停）：
1. 贴出 _judge() 当前的判官 prompt 原文、它要求的输出格式、以及解析分数的代码位置。
2. 贴出一条评估结果 result 的真实 JSON 结构（现在有哪些键：actual_output / scores / retrieval_context 等）。
3. 确认检索侧每个 hit/CitationItem 现在有哪些字段（source_file、score、term_coverage、content_preview 等）。
→ 输出简短确认，停。

阶段B·判官输出每维理由 + 总评：
1. 改判官 prompt，要求返回严格 JSON：
   {
     "faithfulness":{"score":1-5,"reason":"一句话理由"},
     "answer_relevance":{"score":1-5,"reason":"..."},
     "completeness":{"score":1-5,"reason":"..."},
     "correctness":{"score":1-5,"reason":"..."},
     "summary":"一句话总评"
   }
   温度保持 0.0；理由用日文或中文均可，但要简短（≤1句）。
2. 解析：把 score 填回原来的 scores{dim:int}（保持现有打分逻辑不变），
   新增 result["rationales"]={dim:reason}、result["judge_summary"]=summary。
3. 健壮性：解析失败（非 JSON/缺字段）时降级为"只取分数、理由留空"，不要让整个评估崩。
4. 用开关 KB_EVAL_RATIONALE（默认开）控制是否要求理由，可一键关回旧行为。

阶段C·结果里带检索内容：
在写 result 时，加入 result["retrieval"]={
  "toehold_recall": <该题的 toehold>,
  "context_relevance": <该题的 context_relevance>,
  "sources": [ {"source_file":..., "score":..., "term_coverage":..., "content": content_preview[:600]} ... ]
}
content 用现成的 content_preview，截断到约 600 字即可（给 UI 展示用，别过长）。
