”步骤 3 到底是什么”：它就是把生成的 .cypher 脚本整个运行一遍，本来想用 cypher-shell 跑。但这把事情搞复杂了——其实在 Browser 里粘一条就能建全部关系，根本不用 cypher-shell、也不用粘 4 万行（那 4 万行在文件里，你只粘一条，它自己去读）。

现在就粘这一条，关系立刻出来

在 Neo4j Browser 里跑这一条：
LOAD CSV WITH HEADERS FROM 'file:///edges.csv' AS row

MATCH (a:Node {node_id: row.source_id}), (b:Node {node_id: row.target_id})

CREATE (a)-[:REL {type: row.type, source_docs: row.source_docs, inferred: row.provenance_inferred}]->(b);

如果它报内存/超时，就换成分批版（Browser 里开头要加 :auto⁠）：:auto LOAD CSV WITH HEADERS FROM 'file:///edges.csv' AS row

CALL { WITH row

  MATCH (a:Node {node_id: row.source_id}), (b:Node {node_id: row.target_id})

  CREATE (a)-[:REL {type: row.type, source_docs: row.source_docs, inferred: row.provenance_inferred}]->(b)

} IN TRANSACTIONS OF 5000 ROWS;

跑完验证：MATCH ()-[r]->() RETURN count(r);

应该接近 38610。是这个数就成了。

如果还是 0：那说明 edges.csv⁠ 里的 source_id/target_id 和导入的节点 node_id 对不上（另一种 bug），把 edges.csv 头两行发我，我查。

关于”真实关系类型”（彩色那种）

我之前让按每种类型分开建，是为了让关系显示成”使用/属于”这些真实名字——但那需要 108 条语句（类型太多）或装 APOC 插件，对现在评估 Neo4j 没必要。先用上面这条 ⁠:REL⁠ 把关系建起来，一样能做多跳查询：MATCH p = (a:Node)-[:REL*1..3]-(b:Node) WHERE a.label CONTAINS 'LIFE' RETURN p LIMIT 50;

等你评估完、确定 Neo4j 真要用，再上 APOC 把关系变成彩色真实类型（那是进阶，我到时候教）。

画图时别被 chunk 关系糊住

关系里包含 ⁠mentioned_in⁠（实体→切片），有 3.8 万条。看图时查实体对实体就干净了：MATCH (a:Node)-[r:REL]->(b:Node)

WHERE a.type <> 'Chunk' AND b.type <> 'Chunk'

RETURN a, r, b LIMIT 500;

先把那条 LOAD CSV 跑了，把 count(r)⁠ 的结果告诉我。到 38610 左右，你的实体图就完整了，接下来我带你用它跑几个真实业务的多跳问题，看 Neo4j 到底值不值得上。
