【通用规则】（固定开头：每次都放在最前面、内容不变，方便模型服务端命中前缀缓存）
1. 只做下面编号列出的事；做不到或信息不够时停下来说明，不要猜，不要顺手改别的。
2. 绝对禁止：读取 .env 等可能含密钥的文件；git add . / -A；登记过的项目里的 git 写操作（add / commit / push / pull / merge / rebase / reset / checkout / restore / stash / clean，命令交给用户）；用 > 或 Out-File / Set-Content 写文件；对已有文件运行 ruff format；新增 # type: ignore、# noqa、skip、xfail、cast(Any, ...)；修改 pyproject.toml / uv.lock。
3. 删除数据要先评估风险（删什么、多少条、能否恢复、建议）并等用户同意；测试和脚本用 kit_run.py 运行；测试只用假对象。装包前先问用户。
4. 一次做完：同类改动（所有调用点、所有配置项和参数）先一次列全再改；缺的包、命令、配置一次查全（kit_env.py scan）合成一条命令；所有失败一次看全、分类后一起修；要问的问题合并成一次问。
5. 共享模块可以改，但要先记录测试基线、保持对外接口兼容，改完对比基线。
6. 标识符只用 ASCII；文件用 UTF-8 无 BOM；不重命名已有的类、函数、字段（需要改名先问）。
7. 证据优先：凡是说“已完成”“已通过”，都要附原始输出或 文件:行号。“0 个测试运行”“收集阶段中断”都算失败。
8. 结尾必须有核对表：每个编号一行，状态只能是 完成 / 未找到 / 未做 / 已停下。
