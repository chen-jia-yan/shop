# 11 2.0 / 2.1 新功能

## 2.1 的变化（先看这里）
2.1 解决两件事：守卫打断太多次、桌面机器人占地方而且结束后看不了数据。

### 守卫：少打断，要问就当场问
| 情况 | 2.0 | 2.1 |
|---|---|---|
| 删缓存、构建目录、临时文件（`__pycache__`、`.pytest_cache`、`build`、`dist`、`*.log`、`*.pyc`、`tmp_*`……），以及这次会话里新建的文件 | 每次都问 | **直接放行** |
| 删源码等普通文件 | 每次都问 | **当场弹确认框**，你选同意就接着做 |
| 删数据（SQL / Cypher / HTTP DELETE、删除接口、测试里的清理代码） | 拦下 → AI 停下来问你 → 你回复“同意” → AI 重新跑 | **当场弹确认框**（附风险评估），你选同意就执行，任务不中断 |
| 改方案外的文件 | 拒绝，AI 停下来说明 | **当场问你**，同意后自动加进修改范围，同一个文件不再问 |
| 直接跑 pytest / python 脚本（没套 kit_run.py） | 拒绝，要求改写 | **自动套上** kit_run.py 禁删保护，不打断 |
| 删 .git、整个项目目录、家目录、`rm -rf ./` | 问 | **直接拒绝** |
| 被拒绝之后 | AI 停下来 | AI **跳过这一步继续做其余部分**，最后在报告里写明需要你做什么 |

确认框出现时：
- 选“同意”（Yes）：执行这一条，AI 接着往下做。
- 选“不同意”：可以顺手写一句原因或替代做法（例如“先只读计数”“只删 run_id=t1 的”），AI 会照着调整，不会停下来。
- **不要选“Yes, and don't ask again”（以后不再询问）**：那样之后同类操作都不会再问你。
- 机器人会在头顶弹橙色泡泡提醒“该你了：Copilot 在等你确认”，方便你在别的窗口时也能注意到。

如果你的 Copilot 版本不弹确认框（例如命令直接被拒绝、提示里看不到风险评估），在 `kit.config.json` 里改两项就能回到 2.0 的做法：
```json
"guard":    { "ask_mode": "deny" },
"nodelete": { "auto_wrap": false }
```
- `ask_mode: "deny"`：删数据回到“拦下 → 你在对话里回复同意 → 重跑”，改方案外的文件回到直接拒绝。
- `auto_wrap: false`：不自动给命令套 kit_run.py，回到“拦下并提示改写”。
- 再加几种算中间产物的目录名或文件名：`guard.extra_scratch_dirs`、`guard.extra_scratch_files`（可以用 `*`）。
- 在自动驾驶模式（autopilot）下，确认框会被 Copilot 自动拒绝；AI 会跳过这一步，把命令写进报告交给你。

### 桌面机器人：泡泡提醒 + 随时能看的数据面板
- **机器人变小**，只占一小块地方；右键 → 设置 → 机器人大小可以调。
- **“该你了 / 执行中”改成头顶的对话泡泡**：
  - 执行中：每换一个阶段弹一个小泡泡，几秒后自己消失；
  - 该你了（等你确认方案、Copilot 弹了确认框、要不要删数据、等提交）：橙色泡泡，带一键复制的回复（例如“确认”），事情处理完自己收起；点一下泡泡也能收起，再点机器人可以重新看；
  - 一轮做完：蓝色泡泡，带“看数据”按钮。
- **去掉了固定的任务进度框和“说需求”输入框**：任务只在 Copilot 终端里说。想看进度就单击机器人。
- **数据面板随时能打开**（任务结束后也能看）：双击机器人、点机器人右下角的小图标、或右键 → 打开数据面板。
  - 顶上一排按钮切换：总览（时长、Token、上一轮、守卫）/ 时间 / 能力 / 工具 / Token / 最近几轮。默认不自动轮播，右键面板可以打开轮播。
  - 默认背景透明，只显示动态进度条和带底色的小标签；右键面板 → 背景：深色，或调整体透明度。
  - 拖标题栏移动；拖右下角的小三角（或右边、下边的边框）调大小，内容跟着放大缩小；大小和位置都会记住。拖机器人时面板跟着走。
  - Token 那一条的参考额度默认每天 100 万，可以在 `kit.config.json` 的 `metrics.token_budget_day` 改。
- 2.0 的问题“一轮结束后面板被提醒卡盖住、点不动”已经修掉：提醒都改成泡泡，面板只显示数据。

以下是 2.0 的内容（守卫和删除的部分以上面 2.1 的说明为准）。

这一版主要解决五件事：规则太死、技能代理要手动选、数据可能被乱删、做事碎步耗时、看不到时间和 token 花在哪。下面每节都写了“它怎么工作”和“你需要做什么”（大多数情况下什么都不用做）。

## 一、三种模式
| 模式 | 什么时候 | Copilot 怎么做 |
|---|---|---|
| 随手问 | 不在任何项目目录里，只是问问题、查资料 | 直接回答；要改文件先问你 |
| 工作台 | 普通目录：写文档、写脚本、整理资料、写技能 | 当前目录里放手做，大改动先给 3~5 行方案；装包、git 写操作、写到目录外先问你 |
| 项目开发 | 登记过的项目或自动识别的 git 仓库 | 按 /kit-autopilot 完整流程：方案 → 你回复“确认” → 执行 → 验证 → 评审 → 你提交 |

- 自动判断，会话开头会写明当前模式。
- 想手动切换：机器人右键 → 模式。
- 不管哪种模式，只是提问、解释代码时都直接回答，不走流程。

## 二、守卫三档：拒绝 / 先问你 / 放行（2.1 起多了“中间产物直接放行”，见最前面）
- **拒绝**：一定不能做的（读 .env、git add .、项目里 ruff format、写屏蔽检查的标记……）。
- **先问你**：可以做但要你点头的（工作台里装包、写到目录外、随手问模式里改文件……）。
- **放行**：其余的都放行，不打扰。
- **同一类只问一次**：例如这次会话里你已经允许过装包，后面再装包就不会反复问。递归删除和自定义确认规则每次都问。

## 三、删除数据：先评估风险，等你同意（2.1 起改成当场弹确认框；下面是 ask_mode=deny 时的做法）
删数据不是不行，是不能乱删。流程是这样的：
1. Copilot 要运行一条会删数据的命令（SQL DELETE / DROP / TRUNCATE、Cypher DELETE / REMOVE、HTTP DELETE、删除接口、`rm -r` 等）时，守卫先拦下，规则是 `delete-needs-consent`。
2. 它必须先告诉你风险评估：
   ```
   风险：高 / 中 / 低
   要删除：……
   影响范围：……（先做一次只读计数）
   能否恢复：……
   删之前建议：先用同样的条件做一次只读查询，确认条数和内容……
   ```
   风险等级是这样定的：DROP、TRUNCATE、删全部节点、没有 WHERE 的 DELETE、连云上或生产环境，都算高；本地库而且没有高风险特征的，算低。
3. 你在会话里回复：
   - **“同意”**（或“可以删”“删吧”）：放行**这一条**命令，只放行一次；
   - **“不要删”**（或“别删”“取消”）：它不会换个写法再试；
   - **“等一下”“先查一下有多少条”**：它先去做只读检查，再来问你。
4. 测试和脚本里的删除走同一套流程：
   - 测试和脚本要用 `kit_run.py` 运行，带禁删保护。数据可以写，真要删的那一刻会被拦下，什么都不会删。
   - 你同意以后，它用 `kit_run.py --allow-delete -- <原命令>` 重跑，每一次删除都会记日志。
5. 绕过会被拒绝：没经你同意就加 `--allow-delete`，或者在命令里改保护用的环境变量（`nodelete-tamper`），都会直接拒绝。

机器人面板上会出现“等你决定：要删除数据”的卡片，可以点“复制‘同意’”或“复制‘不要删’”，粘贴回 Copilot 就行。卡片上的“看风险评估”会把评估全文显示出来。

检查保护在项目环境里是否生效：`python tools\kit_run.py --check`（或机器人右键 → 更多工具 → 工具 → 删除保护检查）。

## 四、一次做完，不要碎步
原则：动手前先把同一类的事列全，再一起做。只有后一步确实取决于前一步的结果时才分步，并说明原因。适用于：
- 缺的包和命令；
- 要加或改的配置项、参数；
- 要改的调用点和同类写法；
- 测试和检查的所有失败；
- 要问你的问题。

两道保障：
1. **全量体检** `python tools\kit_env.py scan`：一次查出项目缺的包（按 import 对比当前环境）、Python 版本、缺的命令、代码里用到但没设置的环境变量名（只看名字，不读 .env），最后合成一份清单和一条命令。
2. **碎步提醒**（钩子，每种只提醒一次，每次你发新消息后重新计数）：
   - 同一个文件这一轮改了 3 次 → 提醒它把这个文件要改的一次列全；
   - 这一轮改了 7 处 → 提醒它先搜全同类改动再批量改；
   - 同一个测试或检查命令跑了 3 次 → 提醒它一次看全所有失败（去掉 -x、整个目录一起跑）；
   - 分 2 次装包 → 提醒它先全量体检，合并成一条命令；
   - 分 2 次设配置 → 提醒它列全所有配置项，合并成一次。

## 五、共享模块（和同事一起开发的代码）
以前叫“受保护区域”，完全不能改。现在可以改、可以优化，但不能改坏：
1. 改之前记录测试基线：机器人右键 → 自动流程 → 记录共享模块测试基线。没记基线就改，守卫会拦下（`shared-baseline`），并告诉它先记基线。
2. 保持对外接口兼容：函数签名、返回结构、配置名不随便改；要改就先加新的、保留旧的。
3. 改完对比基线：原来通过的测试必须还通过。

技能 /kit-shared-change 会带着做这三步。真的完全不能碰的目录，可以在配置里写成 `locked_areas`（锁定区域）。

## 六、技能和代理自动选
- 每个技能和代理都写了“用户会这样说”（触发说法）和“不适用”（什么时候不该用）。安装时会生成能力目录 `~/.ai-dev-kit/catalog.json`。你自己装在 `~/.copilot/skills`、`~/.agents/skills` 里的技能也会收进来。
- 你每发一条消息，钩子都在本地用这份目录匹配一次，不花额度，然后在消息末尾附一句很短的“[ai-dev-kit 提示]”作为参考。
- 只读的（查、解释、评审、出方案）直接用，并说一句“我用 X 来……”；会改文件或运行命令的，先问“我打算用 X，因为……，可以吗？”。
- 查看能力目录：机器人右键 → 更多工具 → 技能试用台 → 能力目录。

## 七、技能试用台（写给别人用的技能）
```
python tools\kit_skill.py check <技能目录>     # 校验：格式、编码、触发说法、不适用、引用文件、密钥、脚本语法
python tools\kit_skill.py add <技能目录>       # 挂到本机试用（复制到 ~/.copilot/skills，自动更新能力目录）
python tools\kit_skill.py try <名字或目录>     # 试自动匹配：每句“用户会这样说”能不能匹配上、“不适用”会不会误触发
python tools\kit_skill.py pack <技能目录>      # 打包成 zip，附安装说明，发给别人
python tools\kit_skill.py list                 # 列出本机所有技能，标出工具包的 / 你自己的 / 试用台挂的
python tools\kit_skill.py remove <名字>        # 取下试用台挂的技能（先备份）
```
挂上以后在 Copilot 里输入 `/skills reload`。想让 AI 帮你写或修技能，用代理 kit-skill-smith，或技能 /kit-skill-lab。

## 八、方法沉淀
- 任务结束时，如果出现了以后还会用到的做法或教训，它会按 /kit-retro 起草**最多 1 条**方法，问你要不要收。
- 你同意后，先过一遍试用台的校验和匹配测试，再存到 `~/.ai-dev-kit/methods/my-*`，下次能被自动匹配。
- 不同意就丢弃，不会自己偷偷加。

## 九、桌面机器人和数据面板（2.1 起改成泡泡提醒 + 单独的面板，见最前面）
- 小猫删掉了，只保留机器人。机器人右边是数据面板（设置里可以关掉）。
- 面板上面是 4 个数字块，中间是进度条：有步骤时按“第几步 / 共几步”分段显示，没有任务时显示空状态。
- 下面是 4 个频道，每 6 秒轮播一次，点击可以切换：

  | 频道 | 显示什么 |
  |---|---|
  | 时间都去哪了 | 按项目统计用时，以及等你回复花了多久 |
  | 用到的技能和代理 | 次数排行 |
  | 工具调用 | 次数排行 |
  | token 去向 | 按项目统计。能从会话记录读到真实用量就用真实值，读不到时标“估算” |

- **轮到你时**（等确认方案、有问题问你、选修哪些、等提交、等你决定删不删），面板停在提醒卡片上，并响一声。
- 统计范围可以选“今天”或“最近 7 天”。
- **没有任何示例数据**：刚装好时面板是空的，用过之后才有数字。统计存在 `~/.ai-dev-kit/metrics/`。
- 自测和体检都在临时目录里运行，不会往这里写东西。
- 查看统计：`python tools\kit_metrics.py today` / `week`。确认 token 能不能读到真实值：`python tools\kit_metrics.py probe <会话记录文件>`。

## 十、钩子分成两个文件
| 文件 | 事件 | 说明 |
|---|---|---|
| `~/.copilot/hooks/ai-dev-kit.json` | 会话开始、发消息、调用工具前、调用工具后、会话结束 | 核心，所有版本都要能用 |
| `~/.copilot/hooks/ai-dev-kit-extra.json` | 消息改写（附能力提示）、工具失败、回合结束、子代理开始/结束、通知、压缩 | 扩展：计时、token、“该你了”提醒、环境报错提示 |

如果旧版本（例如 1.0.75）启动时提示扩展文件里有不认识的事件，**核心功能不受影响**，只是面板上的计时和提醒会少一些。把提示原文告诉我就行。
