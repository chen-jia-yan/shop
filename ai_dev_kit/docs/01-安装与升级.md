# 01 安装与升级

## 前提（你已经核实过的）
- Python：`C:\Program Files\Python312\python.exe`（3.12，自带 tkinter；检查命令是 `python -c "import tkinter"`，注意是小写 `-c`，上次的 `-C` 是拼写问题）
- git：已安装
- Copilot CLI：bat 启动的 1.0.75（额度多），PATH 里的 1.0.105
- 没有 pwsh（PowerShell 7）：**没关系**，钩子用 `exec` 方式直接调用 Python，不经过任何 shell

## 第一次安装
1. 把工具包放到一个固定位置，例如 `C:\Users\234393\ai-dev-kit`（以后不要挪，挪了要重新安装）。
   - 用单文件安装包：`python install_ai_dev_kit.py C:\Users\234393\ai-dev-kit`
2. 进入目录运行：
   ```
   cd C:\Users\234393\ai-dev-kit
   python tools\install.py --dry-run      # 先预演，看它会改哪些地方
   python tools\install.py                # 正式安装
   ```
3. 打开 `kit.config.json`，修改：
   - `profiles.quota.launcher`：公司 bat 的完整路径
   - 两个项目的 `path`（已按你的电脑填好，核对一下）
   - 测试命令：如果项目不是用 `uv run pytest tests/unit -q`，按实际改
4. 关闭所有 Copilot 窗口，重新打开。
5. 体检和自测：
   ```
   python tools\kit_doctor.py
   python tools\selftest.py
   python tools\run_evals.py
   ```
   把三段输出发给我，我根据结果修。
6. 手动确认四件事（脚本没法替你看，在 1.0.75 上做，结果告诉我）：
   - 在 Copilot 会话里输入 `/skills list`，能看到 kit- 开头的技能；输入 `/agent`，能看到 kit- 开头的代理。
   - 在会话里说“读一下 .env 文件”，应该看到 ai-dev-kit 守卫的拒绝提示。两个版本（bat 和 PATH）都试一次。
   - **自动流程**：在 tap-ai-backend 目录里开会话，直接说一个小需求（例如“给 README 加一行说明”），应该先出方案、问你“确认”，而不是直接改。
   - **子代理委派**：回复“确认”后，看输出里有没有出现委派给 kit-implementer 的记录（会显示子代理的名字或任务）。没有也没关系，总调度会自己执行，只是上下文会长一些。

## 安装做了什么（都可以撤销）
| 位置 | 内容 |
|---|---|
| `~/.copilot/skills/kit-*`、`style-*` | 技能（把 `{{KIT_ROOT}}`、`{{PYTHON}}` 换成你电脑上的真实路径） |
| `~/.copilot/agents/kit-*.agent.md` | 自定义代理 |
| `~/.copilot/copilot-instructions.md` | 在标记段内写入个人规则；你原有内容保留 |
| `~/.copilot/hooks/ai-dev-kit.json` | 三个钩子 |
| `~/.ai-dev-kit/` | 安装清单、备份、日志、缓存、桌面机器人状态 |

被覆盖的文件先备份到 `~/.ai-dev-kit/backups/时间戳/`。

## 两个版本共用一套配置
1.0.75 和 1.0.105 都读同一个 `~/.copilot` 目录，所以装一次两边都生效。区别只在“模式”：
- 会话开头注入哪种模式，看环境变量 `AI_DEV_KIT_PROFILE`；没设置时用 `default_profile`（默认 quota，也就是公司 bat）。
- 用 PATH 里的新版本时，在 cmd 里这样启动就会自动变成省 token 模式：`set AI_DEV_KIT_PROFILE=latest && copilot`（也可以把这一行存成一个 `copilot-latest.bat` 放桌面）。
- 机器人右键里的“版本”只影响机器人生成的提示词是完整版还是精简版。

## 如果旧版本不认 exec 方式的钩子
现象：1.0.105 里拦截正常，1.0.75 里“读 .env”没有被拦截。
做法：
```
python tools\install.py --hook-style powershell
```
这会改用 Windows 自带的 PowerShell 5 调用 Python（不需要 pwsh）。再测一次两个版本。
即使钩子在某个版本里完全不生效，第二道防线仍然在：个人规则里写了禁止项，验证阶段 `checks.py` 也会发现禁止标记、越界改动、编码问题。

## 升级
拿到新版本后覆盖工具包目录（`kit.config.json` 和 `memory/` 会保留），然后：
```
python tools\install.py
python tools\kit_doctor.py
```

## 卸载
```
python tools\install.py --uninstall
```
只删除安装清单里记录的东西；工具包目录、记忆、日志保留。

## 常见问题
| 现象 | 原因与处理 |
|---|---|
| `/skills list` 看不到 kit- 技能 | 没重启 Copilot；或 COPILOT_HOME 指向了别的目录。输入 `/skills reload` 或重启 |
| 所有工具调用都被拒绝 | 守卫脚本出错（钩子出错时 Copilot 默认拒绝）。先 `install.py --no-hooks` 恢复使用，把 `~/.ai-dev-kit/logs` 里的日志发给我 |
| 钩子好像没生效 | 跑 `kit_doctor.py` 看“钩子通信”一项；再试 `--hook-style powershell` |
| 桌面机器人双击没反应 | 看 `~/.ai-dev-kit/logs/widget_crash.log`；或在命令行运行 `python widget\dev_widget.pyw` 看报错 |
| 中文乱码 | 所有脚本都按 UTF-8 输出；在 cmd 里先运行 `chcp 65001` |
