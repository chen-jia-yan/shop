# 05 记忆系统

## 你的问题：市面上记忆方法很多，哪种最有效、最科学、最可持续？

### 常见的几类
| 类型 | 代表 | 怎么工作 | 优点 | 对你的问题 |
|---|---|---|---|---|
| 规则文件 | copilot-instructions.md、AGENTS.md | 每次会话全文注入 | 简单、可控 | 越写越长，占额度、模型抓不住重点；不会过期提醒 |
| 向量数据库 | Mem0、Letta、Zep 等 | 把对话切块向量化，按相似度检索 | 自动、规模大 | 需要向量化模型和服务（离线电脑没有）；记了什么不透明；错的记忆难发现 |
| 知识图谱记忆 | Zep/Graphiti 等 | 抽取实体关系 | 能回答关系类问题 | 依赖大模型抽取，成本高、难审查 |
| **带引用的文件记忆 + 使用时核对** | GitHub Copilot Memory 的做法 | 每条记忆带出处；使用前检查出处是否还成立 | 准确、透明、能发现过期 | 规模中等（几百条以内足够） |

### 选择：第四种，理由
1. **最有效**：编程场景里最危险的不是“记不住”，而是“记错了还在用”（代码改了，记忆没改）。GitHub 公开的 Copilot Memory 设计正是为此：记忆带代码引用，**使用时即时核对**，引用不成立就不用。工具包照这个思路实现。
2. **最科学**：每条记忆可追溯（出处）、可验证（自动核对）、可纠正（取代而不是覆盖，保留历史）。
3. **最可持续**：纯文本 markdown，一条一个文件，人能读能改，能用 git 管理、能发给同事；不依赖任何服务和模型，离线可用，十年后也打得开。
4. **省额度**：会话开始只注入少量“仍然有效、优先级高、最近核对过”的条目（默认 ≤1200 字），不是全部。

```
原因：……
怎么用：……
```

## 五种类型
lesson 教训 / decision 决定 / convention 约定 / fact 事实 / preference 偏好。只记“以后还会用到”的。

## 引用核对怎么判断
| 状态 | 含义 | 会话里还用吗 |
|---|---|---|
| ok | 文件在，锚点文字还在原位置附近（±20 行） | 用 |
| moved | 锚点还在，但挪到别的行 | 用（建议 verify --write 更新） |
| user | 来自你口述（`user:日期 说明`） | 用 |
| stale / missing | 锚点找不到 / 文件不在了 | **不用**，等你确认 |

## 防止记忆变成垃圾场
- 新增时：主题 ≤60 字、事实 ≤400 字；像密码/密钥/连接串的内容直接拒绝；内容相近会提示“是不是重复”。
- 更新：`supersede 旧id --by 新id`，旧的标记为被取代，不删除。
- 清理：`prune --days 30` 列出长期失效的，确认后 `--write` 归档。
- 每周：机器人右键 → 记忆 → 核对是否过期。
