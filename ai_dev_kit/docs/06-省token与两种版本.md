# 06 省 token 与两种版本

## 两种模式
| | quota（额度充足） | latest（省 token） |
|---|---|---|
| 启动 | 公司 bat，1.0.75 | PATH 里的 copilot，1.0.105 |
| 为什么用 | 额度多 | 新功能多，但要省 |
| 提示词输出要求 | 完整：原始输出、理由、核对表 | 精简：结论、改动摘要、失败行和汇总行、核对表 |
| 钩子注入的模式说明 | “完整模式” | “精简模式：不复述代码、不重复贴输出” |
| 切换 | 机器人右键 → 版本；或 kit.config.json 的 default_profile | 同左 |

## 工具包里已经做好的省 token 措施（不需要你操作）
| 措施 | 原理 | 在哪里 |
|---|---|---|
| 固定前缀 | 提示词缓存要求开头内容**完全相同**且足够长（OpenAI 约 1024 token 起）；命中部分约按 10% 计费（GitHub 用量文档） | 所有模板都以同一段【通用规则】开头，一字不差 |
| 验证结果哈希缓存 | 对 HEAD + 改动文件内容算指纹，没变就直接返回上次结果，不重跑测试、不把长输出再读进上下文 | run_checks.py（`--force` 强制重跑） |
| 输出裁剪 | 只给模型看失败行、汇总行和识别出的问题；完整日志存文件 | run_checks.py |
| 小而准的会话注入 | 只注入当前项目要点 + 有效记忆，总共 ≤3600 字，且不含时间戳（不破坏缓存） | session_start.py |
| 技能按需加载 | 平时只占一行描述，用到才读全文 | skills/ |
| 代理分工 | 规划和评审用只读代理，不会把探索过程的大量编辑塞进上下文 | agents/ |
| 不花额度的工具 | 体检、补全 R3、静态检查、编码检查、提交方案都是本地脚本 | 桌面机器人右键菜单 |

## 你需要养成的习惯（GitHub 官方用量建议）
1. **按阶段隔开上下文**：执行和评审交给子代理（总调度会自动这样做），各自有独立上下文。公司 bat 只能开一个会话也适用；上下文变长时用 `/compact`。
2. **同一会话里不要切换模型或推理强度**，也不要中途改工具设置：会让缓存失效。
3. **`/context` 看占用，`/compact` 压缩**：超过一半、或开始重复读同样的文件时压缩。
4. **便宜的事给便宜的模型**：搜索、列文件、总结日志。可以在代理开头加 `model:` 指定。
5. **一次说清楚**：提示词写清任务、上下文、停止条件，是减少重试最有效的办法（先用需求体检）。
6. **不要把大段代码贴进提示词**：写 `文件:行号`，让它自己读。

## 额度充足模式下也要注意
上下文越长，模型越容易漏掉前面的要求。所以“交给子代理、压缩、一次一件事”对 1.0.75 一样有效，只是不用刻意压缩输出。

## 公司 bat 只能开一个会话、换模型要重启，怎么办
- **不用换模型也能分工**：执行、评审由子代理完成，主会话的模型不变，缓存也不会因为切换模型失效。
- **想让评审用另一个模型**：可以在 `agents/kit-reviewer.agent.md` 开头加一行 `model: 模型名`（名字以 `/model` 列表里显示的为准），重新运行 install.py。子代理用自己的模型，主会话不用重启。这一点需要你在 1.0.75 上确认是否支持：如果加了以后评审时报错或没变化，删掉这一行即可，不影响其他功能。
- **上下文太长**：`/compact`，不用重开窗口。
