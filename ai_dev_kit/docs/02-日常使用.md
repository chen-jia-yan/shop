# 02 日常使用

## 一个任务的标准流程（挂件“工作流”页按顺序排好了）
```
① 规划任务  →  ② 锁定修改范围  →  ③ 执行一步  →  ④ 一键验证  →  ⑤ 评审  →  ⑥ 按评审修复（需要时）  →  ⑦ 生成提交命令
```
| 步骤 | 谁来做 | 权限 | 你要做什么 |
|---|---|---|---|
| ① 规划 | kit-planner | 只读 | 在任务框写需求，点按钮；Copilot 窗口打开后粘贴；确认计划 |
| ② 锁定范围 | 你 | — | 把计划第 1 步的文件填进表单（或者点“从输出框的提示词锁定范围”） |
| ③ 执行 | kit-implementer | 读 + 改 + 执行 | **开新会话**（按钮会新开窗口），粘贴提示词 |
| ④ 验证 | 工具（不用 AI） | — | 点按钮，看输出框；内容没变会直接用缓存 |
| ⑤ 评审 | kit-reviewer | 只读 | 把执行报告和 diff 贴给它 |
| ⑥ 修复 | kit-implementer | 读 + 改 + 执行 | 把评审结果贴进任务框，点按钮 |
| ⑦ 提交 | 工具 + 你 | — | 照输出里的命令逐条执行，核对文件清单后 commit；然后“清除修改范围” |

为什么分这么细：
- 规划和评审用**没有编辑权限**的代理，它们想“顺手改”也改不了；
- 每个阶段开新会话，上下文干净，模型注意力集中，也更省 token；
- 修改范围由守卫强制执行，越界的写入当场被拒绝。

## 不用挂件也可以
```
copilot --agent kit-planner                       # 直接用某个代理开会话（1.0.105）
/agent                                            # 会话里列出代理并选择
python tools\prompt_builder.py --action implement --project tap-ai-backend --task "……" --copy
python tools\scope.py set --project tap-ai-backend --task "K2a" --files src/tap_ai/application/library_kg.py
python tools\run_checks.py --project tap-ai-backend
python tools\commit_helper.py --project tap-ai-backend --message "K2a: 图谱按 saas_id 过滤 scope"
```

## 挂件的其他页
- **提示词**：需求体检（不花额度）、补全为 R3、提示词教练（AI）、只生成各类提示词、额度建议
- **工具**：修改范围的查看与清除、静态检查、编码检查、提炼风格卡片、体检、自测、评估、重新安装
- **记忆**：搜索、新增、列出、核对是否过期、预览会话摘要、让 AI 总结值得记的
- **设置**：透明度、置顶、无边框、代理按钮的行为（新开窗口 / 只复制）

小技巧：
- 双击标题栏折叠成一条；右键标题栏有菜单；
- 鼠标停在按钮上会显示说明；
- 任务框里的文字会自动保存，下次打开还在。

## 被守卫拒绝了怎么办
Copilot 会看到一句以 `ai-dev-kit` 开头的拒绝原因，例如：
- `[out-of-scope] src/b.py 不在本次允许修改的文件名单里` → 如果确实要改，用“锁定修改范围”把它加进去，让 Copilot 重试；
- `[git-write] ……` → git 写操作你自己执行；
- `[protected-file] 禁止读取……` → 需要知道某个配置项时，你告诉它名字和是否设置，不要给值。
所有拦截都记在 `~/.ai-dev-kit/logs/` 里（敏感内容已脱敏）。

## 每天结束时（可选，2 分钟）
1. 记忆页点“让 AI 总结值得记的”，粘贴到当天的会话里；
2. 挑 1～3 条有价值的，用“新增一条记忆”保存；
3. 每周点一次“核对是否过期”。
