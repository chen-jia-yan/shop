# 02 日常使用

## 先说结论：直接用大白话说
你不需要记技能名、代理名，也不需要选模式：
- 会话开头会自动判断模式：随手问、工作台或项目开发（见 docs/11 第一节）；
- 你的话会在本地匹配合适的技能和代理。只读的直接用；会改文件或运行命令的，会先问你；
- 只是问问题、解释代码、查资料时，直接回答。

## 项目开发：说需求，剩下的交给总调度
例如：
> 知识库重复上传同一个文件时，不要生成第二份数据

接下来会自动发生（你只在几个地方说话）：
```
分析需求、查代码 → （有查不到的才问你，一次问完，带选项）→ 写出方案（同类改动、环境准备都列全）
        → 【你回复“确认”】
→ 每一步：锁定修改范围 → 执行 → 跑验证（一次看全所有失败）→ 评审（只读评审代理）
        → 【你决定修哪些】→ 修完再验证、再评审
→ 给出提交命令 → 【你自己提交】→ 下一步 … → 总结 + 最多 1 条值得沉淀的方法
```
| 你要做的 | 什么时候 |
|---|---|
| 回复“确认”（或者说要改哪里） | 方案出来后。确认前它不会改任何文件 |
| 选修哪些问题 | 每次评审后 |
| 在确认框里选“同意”或“不同意” | 要删除数据、删源码、改方案外的文件时，Copilot 当场弹确认框（删数据附风险评估）；不同意时可以写一句原因，它会照着调整、接着做。不要选“以后不再询问” |
| 执行提交命令 | git 写操作一直由你来做 |

如果发现它没按流程（比如没出方案就开始改），说一句“按 /kit-autopilot 流程来”，或会话开始时 `/agent` 选 `kit-orchestrator`。

## 工作台：写文档、写脚本、整理资料、写技能
在非项目目录里打开 Copilot 就是工作台模式：当前目录里可以直接写文件，大改动先给 3~5 行方案；装包、git 写操作、写到目录外会先问你（同一类只问一次）。写给别人用的技能，见 docs/11 第七节“技能试用台”。

## 只有一个窗口也没关系（公司 bat 版本）
1.0.75 只能开一个会话、不方便换模型，所以流程设计成**全程在一个会话里完成**：
- 执行、评审交给**子代理**，子代理有独立的上下文，也不用开新窗口；
- 上下文变长时输入 `/compact` 压缩，再继续；
- 如果不支持委派子代理，总调度会自己按同样的规则执行。

## 桌面机器人和数据面板
双击 `widget\start_widget.bat`，屏幕右下角会出现机器人，右边是数据面板。

机器人的样子告诉你进行到哪：
| 它的样子 | 表示 |
|---|---|
| 轻轻浮动、眨眼 | 空闲 |
| 头顶冒“…” | 在分析需求 / 写方案 |
| **蹦蹦跳、天线闪橙光、冒气泡** | **该你了**：确认方案、回答问题、选修哪些、提交、决定删不删 |
| 专心敲键盘 | 在改代码 |
| 戴眼镜、拿放大镜 | 在评审 |
| 星星眼、撒花 | 完成 |
| 冒汗 | 卡住了 |
| 举红色盾牌 | 守卫刚拦住一次危险操作（等你同意的删除不举盾，改成提醒卡片） |

数据面板：
- 上面是 4 个数字块；
- 中间是进度条（第几步 / 共几步）；
- 下面 4 个频道每 6 秒轮播一次：时间都去哪了、用到的技能和代理、工具调用、token 去向。点击频道可以切换，点击右上角可以切换“今天 / 最近 7 天”；
- **轮到你时停在提醒卡片上**，并响一声；
- 刚装好时是空的（不放示例数据），用过之后才有数字。

操作：
| 动作 | 结果 |
|---|---|
| 单击机器人 | 告诉你现在进行到哪、**你现在该做什么** |
| 拖动 | 换个位置（会记住） |
| 双击 / 右下角小图标 | 打开 / 关闭数据面板（随时能看，任务结束后也能看） |
| 右键 | 现在进行到哪了 / 打开数据面板 / 常用按钮 / 更多工具 / 模式 / 设置 / 退出 |

- “更多工具”里分组放着：自动流程、手动模式、提示词、工具（全量体检、删除保护检查、今天的统计……）、技能试用台、记忆。
- “设置”里可以：显示或关闭数据面板、统计范围、提示词版本、大小、置顶、安静模式。

机器人不会控制 Copilot，它只读进度、统计和守卫日志。

## 项目怎么选、怎么更新（不用手动选）
| 你在哪里打开 Copilot | 工具包怎么处理 |
|---|---|
| 登记过的项目（tap-ai-backend、fwd-tap-ingest） | 用登记的设置：测试命令、共享模块（问答插件）、注意事项、风格包；项目开发模式 |
| 没登记的 git 仓库（新项目） | **自动识别**：按 pyproject / uv.lock / tests 推断测试和 lint 命令；项目开发模式 |
| 不是代码仓库的目录 | 工作台模式，不注入项目信息 |

只有这些情况才需要登记（机器人右键 → 更多工具 → 工具 → 把当前项目登记下来，或 `python tools\kit_project.py add`）：
- 要设置共享模块或锁定区域；
- 要写项目注意事项；
- 自动识别的测试命令不对。

## 想单独用某个代理（手动模式）
机器人右键 → 更多工具 → 手动模式，或会话里 `/agent` 选择：
| 代理 | 用途 | 权限 |
|---|---|---|
| kit-orchestrator | 总调度（默认推荐） | 全部，靠流程和守卫约束 |
| kit-planner | 只做规划 | 只读 |
| kit-implementer | 执行一步 | 读、改、执行 |
| kit-reviewer | 评审 | 只读 |
| kit-verifier | 只跑验证 | 读、执行 |
| kit-debugger | 排障 | 读、改、执行 |
| kit-prompt-coach | 写提示词 | 读、执行本地体检工具 |
| kit-skill-smith | 写 / 修技能，跑试用台 | 读、改、执行 |

## 不用机器人也可以（命令行）
```
python tools\prompt_lint.py "需求原话"
python tools\run_checks.py                      （在项目目录里运行）
python tools\kit_env.py scan                    （缺包、缺命令、缺配置一次查全）
python tools\kit_run.py -- python -m pytest -q  （带禁删保护跑测试）
python tools\kit_metrics.py today               （今天的统计）
python tools\commit_helper.py --message "K2a: 图谱按 saas_id 过滤 scope"
python tools\kit_status.py show
```

## 被守卫拒绝了怎么办
Copilot 会看到一句以 `ai-dev-kit 守卫` 开头的原因：
- `[data-delete]`：它要删数据，确认框里有风险评估，你选同意或不同意（旧做法 ask_mode=deny 时显示 `[delete-needs-consent]`，要你在对话里回复“同意”或“不要删”）；
- `[need-kit-run]`：测试和脚本要通过 kit_run.py 运行，它会自己改写命令；
- `[shared-baseline]`：要改共享模块，先记录测试基线；
- `[out-of-scope]`：越界修改。如果确实要改，告诉它“把 xxx 加进这一步的范围”；
- `[git-write]`：git 写操作你自己执行；
- `[protected-file]`：需要知道某个配置时，告诉它配置名和是否已设置，不要给值。

所有拦截都记在 `~/.ai-dev-kit/logs/`，敏感内容已脱敏。

## 每次任务结束时
- 总调度会建议值得记住的内容，以及最多 1 条值得沉淀的方法；你说“保存”就行，不说就不存。
- 也可以机器人右键 → 记忆 → 记住一件事。
- 每周点一次“核对是否过期”。
