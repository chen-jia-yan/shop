# 03 钩子与自定义代理

## 零、它们是自动触发的吗？
| 东西 | 会不会自动 | 说明 |
|---|---|---|
| 钩子（守卫、改后检查、会话注入） | **一定自动** | Copilot 每次调用工具、每次会话开始都会执行，不依赖模型 |
| 个人规则 | **一定自动** | 每个会话都会读 |
| 技能 | 自动 | 每条消息都在本地匹配能力目录（“用户会这样说”），把合适的技能附在提示里；你输入 `/kit-xxx` 时一定加载 |
| 自定义代理 | 自动 | 同样按你的原话匹配；只读的直接委派，会改文件的先问你；`/agent` 选择或 `--agent` 启动时一定生效 |

所以工具包这样安排：
- 会话开头注入“可以用的技能和代理”清单，每条消息末尾附一句本地匹配的“[ai-dev-kit 提示]”，**你只要说话，不用点名**；
- 想百分之百确定走开发流程，就在会话开始时 `/agent` 选 **kit-orchestrator**；
- 总调度再把执行、评审委派给其他代理，你不用自己去切换。

## 一、自定义代理（回答你的问题：/agent 和 “set agent - configure custom agents” 怎么用）

### 它是什么
一个代理 = 一个 `.agent.md` 文件：开头写名字、说明、**能用哪些工具**，正文写它的职责和边界。
你上次输入 `/agent` 后它直接开始执行任务，是因为你选中了某个现成代理（或者把后面的文字当成了任务）。现在工具包装好了 8 个自己的代理：

| 代理 | 工具权限 | 用途 |
|---|---|---|
| **kit-orchestrator** | 不限制（靠流程规则和守卫约束） | **总调度：项目开发默认用它** |
| kit-planner | read, grep, glob | 只读规划 |
| kit-implementer | read, grep, glob, edit, execute | 按计划写代码 |
| kit-reviewer | read, grep, glob | 只读评审 |
| kit-verifier | read, grep, glob, execute | 只跑验证，不改代码 |
| kit-debugger | read, grep, glob, edit, execute | 排障 |
| kit-prompt-coach | read, grep, glob, execute | 写提示词 |
| kit-skill-smith | read, grep, glob, edit, execute | 写 / 修技能，跑试用台校验和匹配测试 |

总调度不限制工具，是因为它需要“委派子代理”和“向你提问”这两个工具，而这两个工具在不同版本里的名字可能不一样，限制死了反而可能用不了。它不会乱改文件，靠的是三样东西：流程规则（确认前不改）、修改范围（守卫硬拦截越界）、只读的评审代理。

### 三种用法
1. **会话里选择**：输入 `/agent`，在列表里选 kit-xxx，然后再输入任务（先选，再说任务）。
2. **启动时指定**（1.0.105；bat 版本要看 bat 是否把参数传下去）：`copilot --agent kit-planner`
3. **让主代理自己判断**：直接说“用 kit-reviewer 代理评审这次改动”。

### “configure custom agents” 按钮
它是 Copilot 自带的“新建代理”向导，会问你名字、说明、工具，然后在 `~/.copilot/agents/`（个人）或项目的 `.github/agents/`（项目）下生成一个 `.agent.md`。
**建议不用这个向导，改用脚手架**，因为脚手架生成的格式固定、会自动检查，还能顺手加机器人菜单按钮：
```
python tools\kit_new.py agent kit-sql-reviewer "只读审查 SQL 和迁移脚本。用于新增表或改索引之后。" --tools read,grep,glob --button "SQL 评审"
python tools\install.py
```
同名时，个人/项目里的代理优先于插件里的代理。

### 文件格式（工具包里的写法）
```
---
name: kit-reviewer
description: 一句话说清做什么、什么时候用（模型靠它判断要不要用这个代理）
tools: ["read", "grep", "glob"]
strict-tools-list: true            # 严格按列表，不额外给工具
include-custom-instructions: true  # 同时遵守个人规则
---
正文：职责、边界、交付格式
```
需要给某个代理指定便宜的模型时，在开头加一行 `model: 模型名`（模型名以 `/model` 列表里的为准）。

## 二、钩子（硬拦截）

### 为什么要钩子
规则写在提示词里，模型可能忘、可能“理解错”；钩子是 Copilot 在**每次调用工具之前**执行的程序，它说“不行”，这次调用就不会发生。这是唯一不依赖模型自觉的防线。

### 钩子一览（两个配置文件）
核心文件 `~/.copilot/hooks/ai-dev-kit.json`（所有版本都要能用）：
| 钩子 | 时机 | 做什么 | 超时 |
|---|---|---|---|
| session_start.py | 会话开始 | 注入：当前模式、红线、项目信息（共享模块和基线状态、锁定区域、注意事项）、删除和一次做完的规则、本次修改范围、可以用的技能和代理、有效记忆（总共 ≤3600 字） | 10 秒 |
| kit_events.py prompt | 你发消息时 | 识别你对待删除请求的回复（同意 / 不要删 / 等一下）；计时；碎步计数清零 | 5 秒 |
| guard.py | 每次调用工具前 | 三档判断：拒绝 / 先问你 / 放行（见下表） | 5 秒 |
| post_edit.py | 修改文件后 | 检查刚改的文件：编码、隐形字符、Python 语法 | 10 秒 |
| kit_events.py tool | 每次调用工具后 | 统计；测试里被禁删保护拦下时登记待同意；环境报错给提示；碎步提醒 | 5 秒 |
| kit_events.py end | 会话结束 | 收尾统计 | 5 秒 |

扩展文件 `~/.copilot/hooks/ai-dev-kit-extra.json`（新版本的事件，旧版本不认识也不影响核心）：
| 事件 | 做什么 |
|---|---|
| userPromptTransformed | 在你的消息末尾附一句本地匹配的“[ai-dev-kit 提示]”（模式、可能适用的技能和代理、需求缺的部分），≤240 字 |
| postToolUseFailure | 工具失败时同样做环境报错提示 |
| agentStop | 一轮结束：记用时，从会话记录读 token |
| subagentStart / subagentStop | 子代理开始时附上红线；统计用到的代理 |
| notification | Copilot 弹出权限确认或提问时，面板显示“该你了” |
| preCompact | 记录压缩次数 |

### 守卫规则
| 规则 | 档位 | 什么情况 | 怎么处理 |
|---|---|---|---|
| protected-file | 拒绝 | 读/改/打印 .env、.env.*、密钥、证书、providers.json | .env.template / .env.sample 放行；只问配置名 |
| delete-needs-consent | 拒绝并登记 | 要删数据（SQL / Cypher / HTTP DELETE / 删除接口 / rm -r 数据目录） | 给出风险评估，等你回复“同意” |
| delete-approved | 放行一次 | 你已经同意过这一条命令 | 用掉这次同意并记日志 |
| delete-rejected | 拒绝 | 你说了“不要删” | 不换写法再试 |
| delete-needs-flag | 拒绝 | 同意后跑的是测试或脚本，但没加 `--allow-delete` | 改成 `kit_run.py --allow-delete -- <原命令>` |
| nodelete-tamper | 拒绝 | 命令里改禁删保护的环境变量 | — |
| need-kit-run | 拒绝 | 项目里直接跑 pytest 或项目脚本 | 改成 `kit_run.py -- <原命令>` |
| shared-baseline | 拒绝 | 改共享模块但还没记录测试基线 | 先记基线；`shared_allow` 里的文件不限制 |
| locked-area | 拒绝 | 改配置里写明的锁定区域 | — |
| out-of-scope | 拒绝 | 改修改范围以外的文件 | 告诉它把文件加进范围 |
| outside-write | 先问你 | 写当前工作目录以外的位置 | — |
| chat-write | 先问你 | 随手问模式里改文件 | — |
| git-add-all | 拒绝 | git add . / -A / --all | 只 add 具体文件 |
| git-write | 项目里拒绝，其他先问你 | commit/push/reset/checkout 等 | 项目里由你执行；status/diff/log 放行 |
| package-install | 项目里改锁文件的拒绝，其余先问你 | uv add/sync/lock、pip install、npm 等 | 先全量体检，合并成一条命令 |
| locked-file | 项目里拒绝，其他先问你 | 改 pyproject.toml、uv.lock、requirements*.txt | 修改范围里允许时放行 |
| recursive-delete | 先问你 | 递归删除文件或目录 | 删数据目录时按删除同意流程 |
| shell-write | 项目里拒绝，其他先问你 | `>`、`>>`、Out-File、Set-Content | `2>&1`、`> $null` 放行 |
| ruff-format | 拒绝 | ruff format | ruff check 放行 |
| forbidden-marker | 拒绝 | 写入 `# type: ignore`、`# noqa`、skip、xfail、`cast(Any,` | 照抄 `# type: ignore[import-untyped]` 放行 |
| invisible-char / fullwidth-space | 拒绝 | 写入隐形字符、全角空格 | — |
| custom-deny / custom-ask | 拒绝 / 先问你 | 配置 `guard.extra_deny_command_patterns` / `extra_ask_command_patterns` | — |

**同一类只问一次**：“先问你”的规则，这次会话里你在确认框里允许过一次，同类操作后面就不再问。递归删除和自定义确认规则（custom-ask）每次都问；删除数据走上面的同意流程，每条命令单独同意。

### 安全设计（风险都考虑过）
- **守卫自己出错**：Copilot 对“命令型钩子出错”的处理是**拒绝**（宁可挡住）。为了不因为守卫的 bug 让你什么都做不了，守卫内部捕获所有异常，出错时记日志并放行（`guard.on_error`，默认 allow）；同时 kit_doctor 和 selftest 会提前发现守卫问题。真实删除还有第二道防线：测试和脚本运行时的禁删保护。
- **超时**：超时会被当作放行。所以守卫只做纯文本判断，不访问网络、不运行 git，通常几十毫秒完成。
- **自动驾驶模式**：Copilot 在 autopilot 下会把“先问你”当成拒绝，这是安全的方向。
- **紧急关闭**：`python tools\install.py --no-hooks`，或在 kit.config.json 里 `guard.enabled: false`。
- 拦截日志脱敏：日志里的口令、密钥、连接串会被替换掉。

### 测试守卫
```
python hooks\guard.py --selftest        # 内置用例 + 删除同意流程 12 步
python tools\run_evals.py --only guard  # 事故用例
python tools\kit_run.py --check         # 禁删保护在当前项目环境里是否生效
```
