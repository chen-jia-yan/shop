# 08 团队分发

工具包首先是你个人用的，但设计上可以分享给同事。

## 哪些可以分享，哪些不能
| 可以分享 | 不能分享 |
|---|---|
| 整个工具包目录（技能、代理、钩子、工具、模板、风格包、评估用例、文档） | `kit.config.json`（含你的路径和 bat 位置） |
| `memory/_global` 和项目记忆（先自己看一遍） | bat 里的 API Key、Neo4j 密码、数据库连接串 |
| `kit.config.example.json` | `~/.ai-dev-kit/`（日志、缓存、备份） |

`.gitignore` 已经排除了 `kit.config.json` 和缓存。记忆系统会拒绝保存像密钥的内容，但分享前仍请自己翻一遍 memory 目录。

## 方式一：同事各自安装（推荐）
1. 把工具包放到内部 git 仓库或共享盘；
2. 同事复制一份，运行 `python tools\install.py`，按自己情况改 `kit.config.json`；
3. 有更新时拉取新版本，重新运行 `install.py`。
好处：路径自动渲染、钩子自动注册、能卸载。

## 方式二：Copilot 插件市场（只分发技能和代理）
工具包根目录有 `plugin.json` 和 `.github/plugin/marketplace.json`，可以作为本地插件市场添加：
```
copilot plugin marketplace add C:\共享路径\ai-dev-kit
copilot plugin install ai-dev-kit@ai-dev-kit-local
copilot plugin list
```
限制（所以只作为备选）：
- 插件里的技能不会渲染 `{{KIT_ROOT}}`、`{{PYTHON}}`，技能里调用工具脚本的命令需要同事手动改路径；
- 钩子、个人规则、挂件不会随插件安装；
- 同名时个人/项目里的技能和代理优先于插件。
你核实过 `copilot plugin --help` 有 install / marketplace 等命令；具体参数以 `copilot plugin marketplace --help` 为准。

## 方式三：放进项目仓库（项目级）
- `instructions/AGENTS.template.md` → 项目根目录 `AGENTS.md`（团队共享的项目说明）；
- 风格包可以复制到项目的 `.github/skills/`（项目级技能，所有用这个仓库的人都能用）；
- 钩子可以放 `.github/hooks/*.json`，但钩子指向的是 Python 脚本路径，每个人的工具包位置不同，**不建议**放进项目仓库。
放进项目仓库之前先和负责人确认，避免影响同事。

## 版本管理
- 改动写进 `CHANGELOG.md`，`plugin.json` 的 version 同步加一；
- 每次发布前跑 `kit_lint.py`、`selftest.py`、`run_evals.py`，全部通过再发。
