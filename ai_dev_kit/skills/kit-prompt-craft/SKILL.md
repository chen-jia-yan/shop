# 提示词助手

## 用户会这样说
- 帮我写个提示词
- 这个需求怎么跟 Copilot 说清楚
- 我表达不清楚，帮我整理一下
- 帮我优化一下这段需求描述
- 把这个任务写成 R3 格式
风险：只读

## 不适用
- 直接帮我把功能做了（用 /kit-autopilot）

## 什么时候用
- 用户的需求只有一句话，或者有“优化一下”“完善下”“搞一下”这类含糊词。
- 一句话里包含了好几件事。
- 上一轮 Copilot 做偏了，需要把需求重新说清楚。

## 依据（为什么这样做）
- GitHub 官方的用量优化建议：提示词写清“任务、上下文、停止条件”，能减少来回重试，是最直接的省额度办法。
- Anthropic、OpenAI 的提示词指南共同点：说清目标和成功标准、给足上下文、写明约束、给例子、规定输出格式；模型不确定时应该先问而不是猜。
- 本项目经验：Copilot 注意力有限，用“编号条目 + 绝对禁止 + 原始输出 + 最后核对表”（R3 格式）执行效果最好。详见 references/r3-template.md。

## 绝对禁止
1. 绝对禁止替用户编造他没说过的业务事实（文件名、字段名、规则）。不知道的写成【待补充：……】或者问用户。
2. 绝对禁止一次问超过 5 个问题；只问会改变做法的问题。
3. 绝对禁止输出“万能模板”；结果必须是针对这个需求填好的提示词。
4. 绝对禁止在这个阶段修改任何代码文件。

## 步骤
1. **体检**：运行
   `{{PYTHON}} {{KIT_ROOT}}/tools/prompt_lint.py "<用户的原话>"`
   得到 8 个维度（目标、位置、上下文、约束、完成标准、验证、输出、例子）的得分、含糊词和任务数量。
2. **自己先查**：能从代码里查到的（文件在哪、现有函数叫什么、测试放在哪个目录），用 grep / glob / view 查清，不要问用户。
3. **拆任务**：任务数量 > 1 时，建议拆成多条提示词，每条只做一件事；给出拆分方案让用户确认。
4. **只问查不到的**：用 ask_user 工具一次性问清（最多 5 个），每个问题给 2～4 个具体选项 + 推荐项。常问的：
   - 做完以后怎么判断“做对了”？（完成标准）
   - 哪些地方绝对不能动？（约束）
   - 有没有可以参照的现成写法？（例子）
   参考 references/vague-signals.md：每个含糊词该追问什么。
5. **生成提示词**：按 references/r3-template.md 的结构输出；可以先运行
   `{{PYTHON}} {{KIT_ROOT}}/tools/prompt_lint.py "<补充后的需求>" --r3 --project <项目名>`
   拿到骨架，再把查到的信息和用户的回答填进去。如果当前是省额度模式（会话开头写了“精简模式”），加 `--lean`。
6. **复检**：把生成的提示词再体检一次，得分应 ≥ 80；仍有【待补充】的地方明确告诉用户。
7. 需要时参考 references/prompt-patterns.md 选择合适的模式（例如“先计划后执行”“先复现后修复”“只读评审”）。

## 输出格式
```
【原始需求体检】得分 N / 100；缺：……；含糊词：……
【我已经查到的信息】（文件:行号）
【拆分建议】（只有一个任务就写“无需拆分”）
【完整提示词】（可直接复制）
……
【还需要你补充的】（没有写“无”）
```
