# R3 提示词结构

R3 = 编号条目（Numbered）+ 绝对禁止（Restrictions）+ 原始输出（Raw output）+ 最后核对表。
固定的“通用规则”放在最前面、每次都一字不差，这样新版 Copilot 能命中提示词缓存（缓存部分按约 10% 计费）。

```
【通用规则】
（templates/_rules.md 的内容，原样放在最前，不要改动顺序和字词）

【任务 <编号>：<一句话标题>】
目标：做完以后，<谁> 能看到 <什么变化>。

【背景】
1. 相关代码：<文件:行号 — 作用>
2. 参照写法：<文件:行号>
3. 已知问题/上一轮结果：<……>

【本次允许修改的文件】
1. <完整路径>
2. <完整路径>
（scope.py from-prompt 会读取这一段自动锁定修改范围）

【具体要求】
1. ……
2. ……

【绝对禁止】
1. 绝对禁止修改上面清单以外的文件。
2. 绝对禁止 <本任务特有的禁区，例如：修改问答插件 / 写入只读索引>。
3. ……

【完成标准】
1. <可以被命令或断言证明的结果，例如：重复上传同名文件返回 status == "skipped">
2. ……

【验证】
1. 运行：<具体命令，具体到测试文件或 -k>
2. 贴出原始输出最后 30 行；collected 为 0 视为失败。

【输出要求】
1. 改了哪些文件、每个文件改了什么（一句话）
2. 验证命令和原始输出
3. 没做完或不确定的地方
4. 最后附核对表，逐条写“是/否 + 证据”：
   - [ ] 只改了允许的文件
   - [ ] 完成标准 1：……
   - [ ] 完成标准 2：……
   - [ ] 测试数量 > 0 且全部通过
   - [ ] 没有使用禁止的标记、没有装依赖、没有 git 写操作
```

## 省额度模式（新版本）
- 输出要求改成：只列改动文件、验证原始输出最后 15 行、核对表；不要复述需求、不要解释思路。
- 背景只写文件:行号，不要贴大段代码（让模型自己去读）。
- 同一会话里不要切换模型和推理强度，否则缓存失效。

## 额度充足模式（1.0.75）
- 可以要求“先列计划再执行”“每一步说明理由”，换取更稳的执行。
