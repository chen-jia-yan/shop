# 按项目风格写代码

## 什么时候用
- 有明确的步骤和文件清单，需要动手写代码。
- 迁移代码（例如从 POC 搬到后端），需要“长得像”目标项目已有代码。

## 绝对禁止
1. 绝对禁止修改范围外的文件（范围见会话开头的“本次修改范围”或 `.ai-dev-kit/scope.json`）。需要改别的文件时停下来说明原因，等用户同意。
2. 绝对禁止读取或打印 .env / .env.example / 密钥文件；测试里绝对禁止依赖真实 .env、真实数据库、真实外部服务——一律用假对象（fake）。
3. 绝对禁止使用 `# type: ignore`、`# noqa`、`pytest.skip`、`xfail`、`cast(Any, ...)` 来让检查通过（唯一例外：照抄项目里已有的 `# type: ignore[import-untyped]`）。
4. 绝对禁止修改 pyproject.toml、uv.lock、requirements*.txt、工具配置；绝对禁止安装依赖；缺依赖就在报告里说明。
5. 绝对禁止执行 git 写操作（add / commit / checkout / restore / reset / stash / clean / pull / push / merge）。
6. 绝对禁止用 PowerShell 的 `>`、`Out-File`、`Set-Content` 写文件（会产生 UTF-16 编码）；只用编辑工具改文件。
7. 绝对禁止对已有文件运行 `ruff format`；只允许 `ruff check`。
8. 绝对禁止在 Python 标识符里用中文或全角字符；文件一律 UTF-8 无 BOM。

## 步骤
1. **找参照**：动手前，在目标项目里找 1～2 个同类功能的现成代码（同一层、同一种写法），写出 `文件:行号`。有风格包就加载风格包，按对应卡片的“必须/禁止/检查项”写。
2. **先读后改**：每个要改的文件先完整 view 一遍相关部分，确认：
   - 现有的类、函数名（改名会让别处的导入报错——改名前用 grep 找出所有引用）；
   - 模型类是否在模块顶层（ORM 类绝对不能嵌套在另一个类里）；
   - 导入关系（新增导入前想清楚会不会形成循环导入）。
3. **小步改**：一次只改一处逻辑，改完立刻想“这一处怎么验证”。
4. **写测试**：
   - 测试断言要比较“具体的值”，不要写 `assert x == x`、`assert True`、只断言“不报错”。
   - 断言用相等（`==`）证明结果，`in` 只用于确实只需要包含关系的地方。
   - 新功能至少覆盖：正常路径、一个边界、一个失败路径。
5. **验证**：运行会话开头给的验证命令（或配置里的 run_checks 命令）。
   - 看清“收集到几条测试、通过几条”。**0 条测试 = 失败**，不是通过；全部 skipped 也不算通过。
   - 失败时先读完整错误，再定位根因，不要盲目改测试来迎合代码。
6. **自查**：对照下面的核对表逐条确认。

## 输出格式
```
【改了什么】（文件 — 改动一句话）
【参照了哪里】文件:行号
【验证】
命令：……
原始输出（最后 30 行，不要改写、不要总结代替）：
……
【没做完/不确定的地方】（没有写“无”）
【核对表】
- [ ] 只改了范围内文件（列出文件清单）
- [ ] 没有新增禁止的标记（type: ignore / noqa / skip / xfail / cast(Any)）
- [ ] 测试数量 > 0 且全部通过（贴了原始输出）
- [ ] 没有改名导致的残留引用（grep 过）
- [ ] 没有嵌套 ORM 类、没有新的循环导入
- [ ] 没有读 .env，测试没有依赖真实外部资源
- [ ] 没有执行 git 写操作、没有安装依赖
```

## 不要做
- 不要“顺手”重构、改格式、改无关的命名。
- 不要把失败说成成功；没跑的验证就写“没跑”，并说明原因。
- 不要为了通过检查删除或弱化已有测试。
