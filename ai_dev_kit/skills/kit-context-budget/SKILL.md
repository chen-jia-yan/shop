# 上下文与额度管理

## 用户会这样说
- 额度快不够了
- 会话太长了，回答越来越差
- 怎么省 token
- 要开始一个大任务，怎么安排会话
- 什么时候该压缩
风险：只读

## 不适用
- 统计一下今天用了多少 token（看桌面机器人面板，或运行 kit_metrics.py today）

## 两种模式（会话开头会注入当前模式）
| | 额度充足模式（quota） | 省 token 模式（latest） |
|---|---|---|
| 启动方式 | 公司 bat，Copilot 1.0.75 | PATH 里的 copilot（1.0.105） |
| 计费特点 | 额度多，按请求次数 | 按 token，缓存命中部分便宜 |
| 输出要求 | 完整：计划、理由、核对表 | 精简：改动清单、原始输出最后 15 行、核对表 |
| 重点 | 一次做对，减少返工 | 减少每次读写的 token、提高缓存命中 |

## 省 token 的做法（依据：GitHub 官方“优化 AI 用量”文档 + OpenAI 提示词缓存规则）
1. **固定前缀**：通用规则放在提示词最前面、每次一字不差。缓存要求前缀完全相同且足够长（约 1024 个 token 以上），命中部分按约 10% 计费。工具包的模板已经这样排好。
2. **同一会话不要切换模型、推理强度、工具集**：切换会让缓存失效。
3. **按阶段隔开上下文**：用子代理（task 工具）执行和评审，各自有独立上下文；只能开一个窗口时（公司 bat），一个阶段结束用 `/compact` 压缩，不必重开。上一阶段的结论用一小段文字带过去，而不是整个对话历史。
4. **用 `/context` 看占用，用 `/compact` 压缩**：占用超过一半、或者开始重复读同样的文件时压缩。
5. **便宜的事交给便宜的模型**：搜索、列文件、总结日志这类子任务可以用较便宜的模型（自定义代理可以单独指定 model）。
6. **不要把大段代码贴进提示词**：写 `文件:行号`，让模型自己去读需要的部分。
7. **验证结果有缓存**：`run_checks.py` 会对“代码状态”算哈希指纹，没变就直接返回上次结果，不重复跑测试、不重复把长输出读进上下文。
8. **输出裁剪**：验证工具只把失败行和汇总行给模型看，完整日志存到文件里需要时再读。
9. **技能按需加载**：技能平时只占描述那一行，用到时才读全文；不要把所有规则都塞进个人指令。
10. **一次做完**：同类改动一次列全再改、所有失败一次看全再修、要问的问题合并成一次问。碎步来回是最费额度的用法（每一轮都要重新读上下文）。
11. **看实际消耗**：桌面机器人右侧面板有今天的时间、token、工具调用排行；命令行 `{{PYTHON}} {{KIT_ROOT}}/tools/kit_metrics.py today`。拿不到真实 token 时标“估算”。

## 额度充足模式下仍然要注意的
- 上下文过长时质量会下降（模型抓不住重点），所以“按阶段交给子代理”“压缩”同样适用。
- 宁可多要一次计划确认，也不要一次做太多。

## 步骤
1. 看会话开头注入的模式行（“额度充足模式”或“精简模式”）；没有就问用户用的是哪个版本。
2. 估算任务规模：涉及文件数、需要读的代码量、要跑的测试。
3. 给出建议：是否先计划、是否拆成多个会话、什么时候压缩、哪些子任务交给便宜模型。
4. 生成提示词时按对应模式选择输出要求（提示词构建工具的 `--profile quota|latest`）。

## 输出格式
```
【当前模式】……
【任务规模估计】……
【建议】
1. ……
【下一步提示词】（按当前模式生成）
```
