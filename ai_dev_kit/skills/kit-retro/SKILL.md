# 复盘与方法沉淀

## 用户会这样说
- 总结一下这次的经验
- 以后遇到这种情况都这样处理
- 把这个做法沉淀下来
- 这次踩的坑记一下
- 复盘一下这个任务
风险：会改文件

## 不适用
- 记一条简单的事实或约定（用 /kit-memory）
- 写团队周报、个人总结（用 /kit-workbench）

## 为什么
规则是写不完的。与其不停加规则，不如把做对过的方法沉淀成技能：模型遇到类似情况时会通过“用户会这样说”自动匹配到它，按里面的步骤做。方法库越用越厚，规则保持简短。

## 方法还是记忆？
| 沉淀成 | 判断 | 例子 |
|---|---|---|
| 记忆（/kit-memory） | 一个事实、一条约定、一个教训，一两句话说得清 | “SDK 只在 ingest 项目的环境里” |
| 方法（新技能） | 一套有步骤的做法，下次可以照着做 | “批量上传失败的排查步骤：按错误分类 → 先查数量最多的一类 → ……” |
| 都不用 | 一次性的信息 | “今天跑了 3 次测试” |

## 绝对禁止
1. 一次任务沉淀超过 1 条（多了会稀释，挑最有价值的）。
2. 没经用户确认就写进方法库或记忆。
3. 方法里写密钥、真实数据、个人路径。
4. 把只成功过一次、没有验证的做法写成“必须这样做”。

## 步骤
1. **回顾**：这次任务里，哪一步最费时间？哪个判断最关键？有没有“如果一开始就这样做就好了”的地方？
2. **挑一条**：最可能再次遇到、而且照着做能明显省时间的那一条。没有就说“这次没有值得沉淀的”。
3. **起草**：
   - 记忆：给出完整的 `mem.py add` 命令（见 /kit-memory）。
   - 方法：按 references/method-template.md 起草一个技能，名字用 `my-` 开头（和工具包自带的区分），放到 `~/.ai-dev-kit/methods/<名字>/SKILL.md`。
4. **问用户**：给出草稿，选项：收下 / 改一下再收 / 不要。
5. **试用后收下**（方法）：
   `{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py check <方法目录>` →
   `{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py add <方法目录>` →
   `{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py try <名字>`；
   提醒用户 `/skills reload`。之后它会出现在能力目录里，下次自动匹配。
6. **更新旧方法**：发现已有方法过时或有更好的做法时，改它的源目录再 add 一次，不要另起一个重复的。

## 输出格式
```
【这次最值得沉淀的】一句话
【沉淀成】记忆 / 方法 / 不需要
【草稿】（记忆命令或方法 SKILL.md 全文）
【收下后怎么验证】……
```
