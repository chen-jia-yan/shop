# 提炼风格卡片

## 用户会这样说
- 把项目里接口的写法总结成规范
- Copilot 写的代码风格和项目不一样
- 给新项目建一个风格包
- 核对一下风格卡片还准不准
风险：会改文件

## 不适用
- 把这次排障的经验记下来（用 /kit-memory 或 /kit-retro）

## 为什么用卡片而不是直接贴代码
- 直接贴整段代码：占额度、代码一改就过时、模型会照抄无关细节。
- 卡片只保留“规则 + 10～30 行精简样例 + 来源路径”，来源路径让模型需要时自己去读最新代码；核对日期让我们知道什么时候该复查。

## 绝对禁止
1. 绝对禁止编造项目里不存在的写法；每条“必须/禁止”都要能在来源文件里找到依据。
2. 绝对禁止把密钥、内部地址、真实数据复制进卡片。
3. 绝对禁止精简样例超过 30 行。
4. 绝对禁止修改项目代码；这个技能只读项目、只写风格包里的卡片（写卡片前把内容给用户确认）。

## 步骤
### 新建卡片
1. 确定主题（一种写法一张卡，例如“接口层写法”“仓储的条件更新”“后台任务”）。
2. 用 grep / glob 找到项目里这种写法的 **2～3 个**实例，记下 `文件:行号`。只有一个实例时，说明它可能还不是约定，向用户确认。
3. 对比这些实例：**共同点**写进“必须”；**都避免的做法**写进“禁止”；不一致的地方问用户以哪个为准。
4. 写精简样例：从最典型的实例里删掉业务细节，只保留结构（10～30 行）。
5. 写反例：AI 最可能写错的样子（可以参考 kit-code-review 技能里的 AI 常见错误清单）。
6. 写检查项：写完代码后可以逐条打勾的问题。
7. 按 references/card-format.md 的格式输出；建议用户用脚手架创建文件再粘贴内容：
   `{{PYTHON}} {{KIT_ROOT}}/tools/kit_new.py card <风格包名> <编号-英文名> "<中文标题>"`
8. 把新卡片加到风格包 SKILL.md 的卡片目录里。

### 核对旧卡片
1. 读卡片的“来源”段，逐个 view 来源文件。
2. 对比“必须/禁止/精简样例”和当前代码：一致 → 更新核对日期；不一致 → 列出差异，给出修改后的卡片内容让用户确认。
3. 运行 `{{PYTHON}} {{KIT_ROOT}}/tools/kit_lint.py` 确认格式正确。

## 输出格式
```
【主题】……
【找到的实例】文件:行号（2～3 个）
【不一致的地方，需要你决定】……（没有写“无”）
【卡片内容】（按 card-format 格式）
【核对表】
- [ ] 每条规则都能在来源里找到依据
- [ ] 精简样例 ≤ 30 行，没有密钥和真实数据
- [ ] 七个段落齐全，写了核对日期
- [ ] 没有修改项目代码
```
