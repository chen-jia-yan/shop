# 怎么写一个会被自动用上的技能

## 目录结构
```
<技能名>/
  SKILL.md            必须，文件名大写
  references/         可选：长的清单、模板、示例（正文里用到才读，省 token）
  scripts/            可选：技能要运行的脚本
```
技能名只用小写字母、数字、连字符，和目录名完全一致，最长 64 个字符。

## SKILL.md 模板
```markdown
---
name: my-skill
description: 做什么（一句话）。用于……的时候（列 3~5 种场景，用用户会说的词），以及用户说“……”时。不用于……。
---

# 标题

## 用户会这样说
- （3~8 句用户的原话，口语化，像真的会这么打字）
风险：只读          （或：会改文件）

## 不适用
- （2~3 句容易误触发的说法，以及应该用什么）

## 绝对禁止
1. ……

## 步骤
1. ……

## 输出格式
……
```

## description 怎么写（模型只看它决定用不用）
- 先写“做什么”，再写“用于什么时候”，场景用用户会说的词（“报错了”“跑不起来”），不要只写术语。
- 写上“不用于……”，减少误用。
- 不超过 1024 字；里面有英文冒号时整段加双引号，或者改成中文冒号。
- 坏例子：`description: 数据处理工具`（太泛，模型不知道什么时候用）
- 好例子：`description: 把多个 Excel 按表头合并成一个，自动对齐列名、去重。用于用户说“合并这些表格”“把几个 Excel 拼起来”的时候。不用于数据库导入。`

## 正文怎么写
- 步骤编号、每步一个动作；需要运行的命令写完整。
- “绝对禁止”写最容易出事的 3~5 条。
- 正文控制在 500 行以内，长内容放 references/，并在正文里写明“见 references/xxx.md”。
- 不要在 allowed-tools 里放 shell / bash / powershell。

## 交付前自查
- [ ] `kit_skill.py check` 没有 ✗
- [ ] `kit_skill.py try` 应触发全中、误触发为 0
- [ ] 在 Copilot 里真实用过一次
- [ ] 没有密钥、内部地址、个人路径
