# 技能试用台

## 用户会这样说
- 我写了个技能，帮我测一下
- 这个技能为什么调不起来
- 提示不是内嵌 skill，无法调用
- 技能要发给同事，先帮我验证
- 为什么模型没有自动用这个技能
- 帮我写一个新技能
风险：会改文件

## 不适用
- 用已经装好的技能做事（直接用对应技能）
- 提炼项目代码风格（用 /kit-extract-pattern）

## 为什么技能会“调不起来”
Copilot 只从固定位置加载技能（`~/.copilot/skills/<名字>/SKILL.md`、仓库的 `.github/skills/` 等）。放在别的目录里的技能不会出现；格式不对的会被静默跳过。最常见的原因：
1. 目录不在加载位置；2. 文件名不是 `SKILL.md`；3. `name` 和目录名不一致；4. 开头不是 `---` 或者带 BOM；5. description 超过 1024 字或里面的冒号导致 YAML 解析失败；6. 装完没有 `/skills reload`。

## 绝对禁止
1. 没校验就交付；没在 Copilot 里真实用过一次就说“可以用了”。
2. 在 allowed-tools 里预先放行 shell（别人装上后这个技能可以不经确认执行任何命令）。
3. 技能里写死密钥、内部地址、个人路径。
4. 覆盖别人已有的同名技能（试用台会拦，除非用户明确加 --force）。

## 步骤
1. **校验**（只读）：`{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py check <技能目录>`
   有 ✗ 的一次全部改掉再继续（不要改一个查一次）；! 是建议，尽量处理。
2. **挂到本机**：`{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py add <技能目录>`，然后提醒用户在会话里输入 `/skills reload`（代理要重启 Copilot），再用 `/skills list` 确认能看到。
3. **试自动匹配**：`{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py try <名字>`
   它用“## 用户会这样说”里的每句话试本地匹配，用“## 不适用”里的话试误触发。没命中的句子：把关键词写进 description；误触发：在 description 里写清“不用于……”。
4. **真实试一次**：让用户在 Copilot 里用“用户会这样说”里的一句话提问，看模型开头有没有说“我用 X …”、步骤是否按技能走。没用上就回到第 3 步改 description。
5. **打包交付**：`{{PYTHON}} {{KIT_ROOT}}/tools/kit_skill.py pack <技能目录>`，生成 zip（附安装说明），排除 .env 和缓存。
6. 源目录改了以后，再运行一次 add 同步到本机。

## 写一个好技能
按 references/skill-authoring.md 写：description 写“做什么 + 什么时候用 + 用户会怎么说”，正文写“用户会这样说 / 不适用 / 绝对禁止 / 步骤 / 输出格式”，细节放 references/。

## 输出格式
```
【校验】✗ N 个 / ! N 个（列出）
【挂载】已挂到 ……；请输入 /skills reload
【匹配试用】应触发 a/b，误触发 c/d
【真实试用】（用户反馈）
【交付】zip 路径
```
