# 环境问题：一次查全，一次解决

## 用户会这样说
- 跑不起来，缺包
- 报 ModuleNotFoundError
- 新拉的项目第一次运行一堆报错
- 换了电脑要重新配环境
- 提示缺少配置
- 这个命令找不到
风险：只读

## 不适用
- 代码逻辑报错、结果不对（用 /kit-debug-bug）
- 导入报 ImportError: cannot import name（多半是循环导入，用 /kit-debug-bug）

## 为什么
缺包时最常见的浪费是：装一个 → 跑 → 又缺一个 → 再装，来回五六轮，每一轮都要重新读上下文。同样的情况还有：配置一个一个地加、参数一个一个地试。全部列出来一次解决，只需要问用户一次。

## 绝对禁止
1. 装一个包就重跑一次看还缺什么。
2. 没问用户就装包；在登记过的项目里用 uv add / uv lock / 改 pyproject（这些会改依赖文件，要用户决定）。
3. 读取或打印 .env 的内容来“看看配置”；缺配置时只说配置名。
4. 把 ImportError: cannot import name 当成缺包（多半是循环导入）。

## 步骤
1. **全量体检**（只读，不装任何东西）：
   `{{PYTHON}} {{KIT_ROOT}}/tools/kit_env.py scan`（不在项目目录里时加 `--project <名字>`）
   它会对照代码里的 import 检查项目自己的环境，同时查验收命令用到的工具、代码里强制读取的配置名、Python 版本、附近的本地安装包。
2. **补上体检查不到的**：把用户贴的报错、测试的完整输出里所有“缺什么”的行一次找全（`No module named`、`not recognized`、`Field required`、`KeyError`），和体检结果合并去重。
3. **合并成一个方案**，一次交给用户：
```
【缺的东西】（全部列出）
- 包：a、b、c（pyproject 已声明 / 未声明）
- 命令：x
- 配置名：Y_URL、Z_KEY（只写名字）
- 版本：……
【一次做完】
1. 一条命令装完所有包：……
2. 配置：请在 .env 里确认有这些名字：……（不要把值发给我）
3. ……
【不会做的】不改 pyproject / uv.lock（除非你说要加进依赖）
```
4. **用户同意后一次执行**，然后整体重跑一次验证；还有问题就回到第 1 步再查一次全量，而不是盯着新冒出来的那一个。

## 判断技巧
- pyproject 已经声明却没装上 → 环境没同步（`uv sync`），不是缺依赖。
- 包只在另一个项目的环境里（例如 SDK 只在 ingest 项目）→ 不要往当前环境里装，先确认运行位置对不对。
- 报错里的模块名和包名不一样时（yaml → PyYAML、cv2 → opencv-python）以体检给的包名为准。
- 更多常见报错和含义见 references/common-env-errors.md。

## 这个原则不只用于装包
同样适用于：一次列全要加的配置项和参数、一次找全要改的调用点、一次看全所有测试失败。见 /kit-workbench 的“一次做完”清单。
