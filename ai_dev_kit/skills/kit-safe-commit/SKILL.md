# 安全提交（只出方案，用户执行）

## 用户会这样说
- 可以提交了，给我命令
- 帮我生成 git add 和 commit
- 工作区有别的改动，怕提交错
- 这次该提交哪些文件
风险：只读

## 不适用
- 帮我直接提交（登记过的项目里提交由用户执行）

## 什么时候用
- 验证通过，准备提交。
- 工作区里混着别的改动（子模块脏、同事的文件、临时文件），怕提交错。

## 绝对禁止
1. 绝对禁止执行 git add / commit / push / restore / checkout / reset / stash / clean（守卫也会拦截）。
2. 绝对禁止写 `git add .`、`git add -A`、`git add -u`、`git commit -a`。
3. 绝对禁止把 .env、密钥、pyproject.toml、uv.lock、子模块指针放进提交清单（除非用户明确说要）。
4. 绝对禁止在 develop / master / main 分支上直接提交；发现在这些分支上要先提醒用户建分支。

## 步骤
1. 运行提交助手：
   `{{PYTHON}} {{KIT_ROOT}}/tools/commit_helper.py --project <项目名> --message "<一句话说明>"`
2. 检查输出的分类：
   - **可提交**：在修改范围内的文件；
   - **范围外**：不在范围内的改动——逐个说明是什么、建议怎么处理（多半是不该改的，需要用户确认）；
   - **子模块**：子模块有改动——不要提交指针，除非用户明确要；
   - **敏感 / 锁定**：绝不放进本次提交。
3. 核对提交说明：一句话写清“做了什么”，可以带上步骤编号（例如“K2a: 修正图谱 scope 过滤”）。
4. 把助手输出的命令整理给用户，提醒用户：执行 `git --no-pager diff --cached --stat` 后，对照“期望的文件清单”确认一致再 commit。

## 输出格式
```
【当前分支】……（如果是 develop/master/main，先写警告）
【可提交文件】……
【需要用户确认的文件】……
【请你自己在终端执行】
（助手生成的命令，原样贴出）
【提交前核对】
- [ ] diff --cached --stat 的文件清单与“可提交文件”完全一致
- [ ] 没有 .env / 密钥 / 锁定文件 / 子模块
- [ ] 不在 develop/master/main 分支
```
