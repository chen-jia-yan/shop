# 清单：测试是否真的证明了行为

“测试通过”不等于“功能正确”。下面任何一条是“否”，测试结论都不可信。

## 测试有没有真的跑
- [ ] 输出里能看到“collected N items”且 N > 0？**0 条 = 失败。**
- [ ] 没有 “ERROR collecting”“Interrupted”？（收集阶段报错，后面全部没跑）
- [ ] 不是全部 skipped？
- [ ] 跑的是正确的目录/文件？（曾出现测试放错目录，pytest 根本没收集到）

## 断言有没有意义
- [ ] 没有 `assert x == x`、`assert True`、`assert result is not None` 这种几乎永远成立的断言？
- [ ] 比较的是具体期望值（`== "skipped"`、`== 3`），而不是 `in`（`"ok" in text` 在 "not ok" 里也成立）？
- [ ] 失败路径真的断言了错误类型或错误码，而不是只要“抛了异常”就算过？
- [ ] 测试名字说清了在测什么行为？

## 测试和实现是否互相“抄答案”
- [ ] 期望值不是从被测代码里算出来的（例如用同一个函数生成期望值再比较）？
- [ ] mock 没有把要测的逻辑本身替换掉？

## 隔离
- [ ] 不读取真实 .env、不连真实数据库/搜索服务/图数据库/大模型？一律用 fake。
- [ ] 测试之间没有共享可变状态（全局变量、同一个临时文件）？
- [ ] 不依赖执行顺序、当前时间、网络？

## 覆盖
- [ ] 新功能：正常、边界、失败各至少一条？
- [ ] 修 bug：有一条“修之前会失败、修之后会通过”的回归测试？
- [ ] 改名/删除：引用它的测试一起更新了？
