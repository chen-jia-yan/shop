# 清单：安全（OWASP Top 10 中与后端最相关的部分）

AI 生成的代码在这一块最容易出问题（Veracode 2025：约 45% 含 OWASP Top 10 类漏洞），每条都要过。

## 注入
- [ ] SQL 是否全部用参数化 / ORM 表达式？有没有用 f-string、`%`、`+` 拼接用户输入进 SQL？
- [ ] 搜索服务的过滤表达式（例如 Azure Search 的 filter、Neo4j 的 Cypher）有没有拼接用户输入？应当用参数，或者对输入做白名单/转义。
- [ ] 有没有把用户输入传给 `subprocess`、`os.system`、`eval`、`exec`？`shell=True` 一律视为严重问题。
- [ ] 文件路径：用户传入的文件名有没有做规范化，防止 `../` 跳出目录？

## 密钥与敏感信息
- [ ] 代码、测试、日志、注释里没有出现真实的密码、API Key、连接串？
- [ ] 日志里没有打印完整请求体、令牌、个人信息？异常信息返回给前端前有没有去掉内部细节？
- [ ] 配置从 settings 读取，而不是在代码里写死？

## 权限与数据范围
- [ ] 读写数据时带上了正确的范围条件（例如 saas_id / scope / 租户）？有没有可能读到、改到别的范围的数据？
- [ ] 删除、覆盖类操作是否限定了范围？只读资源（例如只读索引、别的团队的数据）在代码路径上确实不会被写？
- [ ] 新接口是否和同类接口一样经过了鉴权依赖？

## 输入校验
- [ ] 请求参数有类型和长度限制（Pydantic 模型的约束）？
- [ ] 上传文件：大小、类型、加密/带锁文件有没有在解析前过滤？
- [ ] 外部返回的数据在使用前有没有校验（字段缺失、类型不对）？

## 依赖与资源
- [ ] 没有新增依赖；确需新增时已在报告里说明，由用户决定？
- [ ] 打开的文件、连接、会话在异常时也会被关闭（with / finally）？
- [ ] 外部调用都设置了超时？
