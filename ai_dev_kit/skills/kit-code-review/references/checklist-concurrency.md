# 清单：并发、后台任务与超时

文档解析、入库这类长任务最容易在这里出问题。

## 后台任务
- [ ] 任务状态有明确的状态机（例如 pending → processing → done / failed），状态更新用条件更新，防止两个工作线程抢同一条？
- [ ] 任务失败时状态一定会被写成 failed（try/except/finally），而不是永远卡在 processing？
- [ ] 进程重启后，卡在 processing 的任务能被识别并重试（有超时回收机制）？
- [ ] 重试有次数上限，失败原因被记录？

## 线程与进程池
- [ ] 线程/进程池大小来自配置，而不是写死？
- [ ] 进程池里执行的函数是模块顶层函数、参数可序列化？
- [ ] 不在线程之间共享数据库 Session / 非线程安全的客户端？
- [ ] 用 Semaphore 等限制同时调用外部服务（大模型、向量化）的数量，避免被限流？

## 超时
- [ ] 每个外部调用都有超时？超时后是重试还是失败，有明确处理？
- [ ] **不要**用“开一个线程跑任务，然后 join(timeout)”来实现超时——超时后线程还在后台跑，会继续写数据（真实事故）。应当用库自带的超时参数，或者在进程里执行并能终止进程。
- [ ] 大文件有大小上限或分块处理，避免单个任务占满内存/时间？

## 锁与幂等
- [ ] 同一文件重复上传、同一任务重复触发，结果是幂等的（不会产生两份数据）？
- [ ] 如果用了锁，锁有超时释放，异常时一定释放？
- [ ] 先删后写的操作，在中途失败时不会留下“已删除但未写入”的空洞？
