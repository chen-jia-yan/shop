# 一次做完：怎么一次找全

## 找全所有要改的地方
- 改名：`grep -rn "旧名字" src tests`（再查一遍字符串里、配置里、文档里有没有）
- 改配置项：`grep -rn "settings\.旧字段\|旧字段名" src tests`，加上配置类的定义处
- 改接口参数：找定义、所有调用点、测试、接口文档四个地方
- 同类写法：先找一个，再用它的特征（函数名、装饰器、关键字）搜出所有同类

## 一次看全所有失败
- pytest：`kit_run.py -- uv run pytest tests -q --tb=line`（不要 -x；--tb=line 每个失败一行，方便分类）
- 只看失败的名字：在上面的结果里找 `FAILED` / `ERROR` 开头的行
- ruff：`uv run ruff check src tests`（一次全目录）
- mypy：`uv run mypy src`（一次全目录）
- 编码：`check_chars.py src tests`
- 一键：`run_checks.py`（以上全部，加上静态检查）

## 分类后一起修
把失败按原因分组（例如：导入错误 3 个、断言值变了 5 个、缺配置 2 个），每组找一个共同原因，一组一组地改，全部改完再跑一次完整验证。

## 什么时候确实要分步
- 后一步的做法取决于前一步的结果（例如先查数据量，再决定用批量还是逐条）
- 风险很大，需要用户看完第一步再决定（例如迁移数据）
- 用户明确要求一步一步来
分步时说明原因，而且每一步内部仍然一次做完。
