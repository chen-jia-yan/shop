# 工作台：直接做，一次做完

## 用户会这样说
- 帮我写个脚本把这些 Excel 合并
- 整理一下这份文档
- 帮我写个小工具
- 这个目录里的配置帮我改一下
- 写一份使用说明
- 把这些文件批量重命名
风险：会改文件

## 不适用
- 在登记过的项目里做功能开发（用 /kit-autopilot）
- 只是问个问题（直接回答）

## 做法
1. **判断大小**：不超过 3 个文件、没有风险 → 直接做完，最后说明改了什么、怎么验证。更大或有风险（批量改很多文件、装包、碰共享数据、删东西）→ 先给 3~5 行方案，等用户说可以。
2. **先列全**：开始前把这件事涉及的所有同类内容一次找出来（见下面的清单），列成表再动手。
3. **一次做完**：按清单批量处理，中途不要每改一处就停下来问或者重跑。
4. **统一验证一次**：全部做完后运行一次能证明结果的命令（运行脚本、打开文件检查、跑测试），把结果给用户。
5. **交付**：改了哪些文件、怎么用、怎么验证、还有什么没做。

## “一次做完”清单
| 情况 | 碎步的做法（别这样） | 一次做完的做法 |
|---|---|---|
| 缺包、缺命令 | 装一个跑一次 | `kit_env.py scan` 一次查全，合成一条命令问一次 |
| 加配置项 / 参数 | 加一个、试一次、再加一个 | 先列出所有需要的配置名、用途、默认值，一次改完 |
| 改名、改调用 | 改一处、报错、再改一处 | 先 grep 找全所有引用，列成清单批量改 |
| 测试 / 检查失败 | 修一个跑一次 | 一次跑完整（不加 -x），所有失败分类后一起修，最后再跑一次 |
| 格式、编码问题 | 一个文件一个文件地修 | 用 check_chars.py 扫整个目录，一次列全 |
| 要问用户的问题 | 问一个等一个 | 合并成一次提问（最多 5 个，带选项和推荐） |
| 批量处理文件 | 一个一个处理 | 先列出全部文件和要做的操作，写一个脚本一次处理 |
只有“后一步必须看前一步的结果才能决定”时才分步，并且说明原因。详细的检查方法见 references/one-pass.md。

## 边界（任何模式都一样）
- 不读 .env；删除数据要先评估、等用户同意（/kit-data-safety）；删文件、写工作目录外的位置会弹确认。
- 写脚本时，脚本里如果有删除数据的语句，运行前要先告诉用户。
- 写给别人用的技能，用 /kit-skill-lab 校验和试用后再交付。
