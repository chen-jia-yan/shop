# 长期记忆

## 用户会这样说
- 记住这个
- 以后都这样做
- 上次是怎么定的
- 这条规则过时了，更新一下
- 看看有哪些记忆
风险：会改文件

## 不适用
- 把这种做法收进方法库（可复用的做法用 /kit-retro）

## 这套记忆是怎么工作的（给用户解释时用）
- 每条记忆是一个 markdown 文件，存在工具包的 memory 目录里，按项目分文件夹；人能直接打开读、能改、能用 git 管理。
- 每条记忆带**引用**（`文件路径:行号#锚点文字`，或者 `user:日期 用户说明`）。使用前会自动核对：引用的代码还在，就可信；代码变了，就标为“可能过期”，不再自动注入。这参考了 GitHub Copilot Memory 的做法——“带引用存储、使用时即时核对”。
- 每次会话开始，只注入“仍然有效、优先级高、最近核对过”的少量记忆（默认不超过 1200 字），不会把所有记忆都塞进去浪费额度。

## 绝对禁止
1. 绝对禁止在记忆里写密码、API Key、连接串、个人信息（工具会拒绝保存，但你也不要尝试）。
2. 绝对禁止把一次性的信息记成记忆（例如“今天跑了 3 次测试”）。只记**以后还会用到**的。
3. 绝对禁止直接编辑或删除 memory 目录里的文件；一律通过下面的命令操作，并且由用户确认后再执行新增/取代/归档。
4. 绝对禁止没有引用就记“代码事实”类记忆；来自用户口述的用 `user:` 引用。

## 什么值得记（五种类型）
| 类型 | 记什么 | 例子 |
|---|---|---|
| lesson 教训 | 踩过的坑和避免办法 | PowerShell 的 > 会写出 UTF-16 |
| decision 决定 | 用户拍板的方案和理由 | 图谱按 saas_id 筛选 scope |
| convention 约定 | 项目的写法规范 | 配置直接用 settings.xxx |
| fact 事实 | 不容易查到的环境事实 | SDK 不在后端的虚拟环境里 |
| preference 偏好 | 用户的工作习惯 | 提示词用 R3 格式 |

## 命令（都在工具包目录下运行）
- 查：`{{PYTHON}} {{KIT_ROOT}}/tools/mem.py search "关键词" --project <项目名>`
- 看一条：`{{PYTHON}} {{KIT_ROOT}}/tools/mem.py show <id>`
- 新增：
  ```
  {{PYTHON}} {{KIT_ROOT}}/tools/mem.py add --project <项目名> --type lesson --subject "一句话主题" --fact "事实本身" --why "为什么重要" --how "以后怎么做" --cite "src/路径.py:行号#锚点文字" --tags "标签1,标签2" --priority normal --source "来自哪次任务"
  ```
  不填 --project 表示全局记忆（所有项目都适用）。
- 核对是否过期：`... mem.py verify --project <项目名>`（加 `--write` 把结果写回文件）
- 新的取代旧的：`... mem.py supersede <旧id> --by <新id>`
- 归档：`... mem.py archive <id>`；清理长期过期的：`... mem.py prune --days 30`（先看结果，确认后加 `--write`）
- 统计：`... mem.py stats`；看会话摘要：`... mem.py digest --project <项目名>`

## 步骤
### 用户说“记住……”时
1. 先 search，看有没有相近的；有的话问用户是“更新旧的”还是“新增一条”。
2. 判断类型；写 subject（≤60 字）、fact（≤400 字）、why、how。
3. 找引用：代码事实用 grep 定位 `文件:行号#锚点`（锚点选一段不太会变的文字，例如函数名）；用户口述用 `user:日期 用户说明`。
4. 把完整的 add 命令给用户看，确认后再执行（或者让用户自己执行）。
5. 新增返回 3 表示有相近记忆，按提示处理；返回 2 表示内容不合规（太长、像密钥）；返回 4 表示引用核对失败。

### 任务结束时
1. 回顾这次任务：有没有踩坑、有没有用户拍板的决定、有没有发现新的约定。
2. 有的话列出 1～3 条“建议记住的内容”（类型、subject、fact、引用），让用户选择要不要记。

### 发现记忆和现实不符时
1. 运行 verify 看是哪条过期。
2. 和用户确认现在的正确做法，新增一条新的，再用 supersede 取代旧的（旧的不删，保留历史）。
