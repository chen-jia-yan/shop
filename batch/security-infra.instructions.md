# 安全基础设施编码规则(security infra)

本目录是整个系统的安全入口层,处理密钥、PII 脱敏、加密与安全日志。这里的每一行代码都按**受监管的保险个人数据**对待,**安全性高于功能与性能**。默认原则:**fail-closed**——任何安全环节失败,必须阻断流程并抛出安全异常,严禁"降级放行"或吞掉异常继续。

## 密钥与凭据(Secrets)
- 密钥/连接串/API key **只**从 Azure Key Vault(生产,配合 Managed Identity)或环境变量(本地开发)读取。严禁硬编码、写进默认参数、拼进 URL、留在注释或示例里。
- 严禁把密钥写入日志、异常消息、堆栈、错误返回、缓存或临时文件;序列化对象前必须剔除敏感字段。
- 密钥只在使用的最小作用域内存在,用完不长留内存;不得跨模块传递明文密钥,传引用/句柄。
- 支持轮换:代码不得假设密钥不变;读取走统一的 `SecretProvider` 接口,便于轮换与 mock。
- 测试**禁止**使用真实密钥;用固定假值或本地 mock。

## PII 检测与脱敏(Masking)
- 送往 Azure OpenAI(或任何外部服务)之前,**必须**先过 PII 检测与脱敏。这条没有例外;未经脱敏的内容不得出域。
- 保险场景的 PII 至少包括:姓名、住址、电话、邮箱、生年月日、证件号(マイナンバー/证件)、保单号、证券番号、金额与账户信息、健康/病历信息、受益人信息。检测规则集中维护,不在业务代码里散落正则。
- 脱敏优先**不可逆掩码**;确需在结果中回填(保持可追溯)时用**确定性 token 化**(同一实体映射同一 token),映射表本身视为机密、加密存储、设访问控制与保留期。
- 脱敏是**幂等**且**可测试**的纯函数;输入输出都要有类型与单元测试。
- 脱敏或 PII 检测组件抛错时**fail-closed**:阻断该内容外发,记录安全事件(不含原文),绝不"检测失败就原样发出"。

## 加密(Crypto)
- 禁止自研加密算法与协议。只用经过验证的库与标准算法(如 AES-256-GCM 静态加密、TLS 1.2+ 传输);密钥来自 Key Vault。
- 静态:本地缓存、中间产物、token 映射表一律加密落盘并设保留期与安全删除。
- 传输:所有外呼强制 TLS,校验证书,禁止关闭校验或降级明文。
- 不要用 MD5/SHA1 做安全用途;哈希口令类用专用 KDF。随机数用密码学安全来源(`secrets`),不用 `random`。

## 安全日志与可观测
- 结构化日志经统一的**脱敏过滤器**输出;严禁 `print`。日志中不得出现 PII 明文、密钥、完整请求体。
- 记安全事件(脱敏失败、密钥读取失败、越权尝试)时只记类型、时间、调用方、脱敏后的最小上下文,便于审计且不泄密。
- 面向用户/上游的错误信息不得泄露内部实现、路径、密钥存在性或数据结构。

## 送入 LLM 内容的信任边界
- 一切文档内容与用户输入视为**不可信**。本层负责在内容外发前做脱敏与清洗,不得让内容触发工具调用、命令执行或改写系统指令。
- 检索片段与系统指令严格分区;拼 prompt 时对不可信内容做隔离标注。

## 数据驻留与合规
- 遵守日本个人情報保護法(APPI)与数据驻留要求;确认 Azure 部署区域合规,跨境传输需事先授权。按 `sensitivity`(public/internal/confidential/regulated)分级施策。

## 依赖与测试
- 加密/安全相关依赖锁版本、纳入 SCA 扫描;不引入未审计的三方安全库。
- 本目录**测试覆盖率要求高于全局**;必须含脱敏正/负向测试向量、fail-closed 行为测试、日志不泄密断言。
- 测试夹具**严禁**使用任何真实个人数据;用合成数据。
- 本目录代码变更必须经额外的安全 review 才能合并。

## 给 agent 的默认行为
在本目录写代码时:默认 fail-closed;先脱敏再外发;密钥走 provider 不硬编码;不自研加密;不记敏感明文。任何要"临时跳过脱敏/校验以便调试"的做法都不允许写进代码,如需调试用显式的本地开关且默认关闭并有测试覆盖。
