# 维护方法（给团队成员和 AI）

规则会越用越多。这里说明遇到判错时怎么补、补完怎么确认没有改坏别的用例。

## 一、三样东西

| 东西 | 在哪 | 谁改 | 作用 |
|---|---|---|---|
| 判断规则（关键字、弹窗清单、数值） | `config/rules.json` 的 `rules` | 页面“配置 → 判断规则” | 内置规则用到的文字清单 |
| 自定义规则 | `config/rules.json` 的 `custom` | 页面“配置 → 自定义规则” | 团队补的判断，优先于内置规则 |
| 纠错样本 | `config/corrections.json` | 用例详情“加入纠错样本”，或改分类时勾选 | 判错过的真实用例 + 正确答案，每次改规则都重新判一遍 |

每次保存都要填修改人和修改说明，写进 `rules.json` 的 `changelog`（页面“配置 → 修改记录”）。同事的页面发现规则文件变了，会在顶部提醒“判断规则已更新”。

## 二、遇到判错时

1. 打开这个用例，看判断依据和证据，确认正确分类。
2. 点“确认 / 改分类”，写原因，勾选“同时加入纠错样本”。
3. 到“配置 → 纠错样本”，这条显示“判错”。按情况补规则：
   - 新的弹窗文字 → “判断规则”里的干扰弹窗或业务报错清单；
   - 新的环境报错 → `env_patterns`；新的锁单、缺配置提示 → `lock_messages`、`config_messages`；
   - 某个系统特有的报错，要固定判成某类 → “自定义规则”，新增一条，先点“试一下”看会命中哪些用例。
4. 保存。页面显示有多少用例分类变了、纠错样本判对多少；有样本判错会跳到纠错样本页。全部判对才算补好。

写条件的注意：
- 照抄报错里稳定不变的那一段，不要带编号、日期、人名。
- 普通文字至少 3 个字；`re:` 开头是模糊匹配，例如 `re:record \d+ not found`。
- 只想在日志里找就只勾“日志和报错”；截图文字识别可能有误，勾了它命中时结论会是“待复核”。

## 三、同步给团队

`config/` 在 skill 目录里，和 skill 一起放在共享位置或代码库里即可。也可以在“判断规则”页点“下载”发给同事，对方“导入”。

## 四、改代码（ta_engine.py 等）

1. 改 `scripts/ta_engine.py`（判断顺序、新规则编号）时同步改 `references/taxonomy.md`；新规则编号加到 `RULE_NAMES`、`brief()`，以及 `ta_jira.py` 的 `english()`、`jira_phrase()`、`cause_phrase()`。
2. 运行：
   ```
   python scripts/ta.py check      规则写法 + 纠错样本 + 基准样本
   python evals/selftest.py        导入、工作区、Jira、本机服务
   ```
3. 基准样本有差异：逐条确认是不是有意的改进；是，再运行 `python evals/check_consistency.py --update` 更新标准答案，并在提交说明里写清楚。
4. 页面（`assets/`）只做显示和操作，不要在里面写判断逻辑。需要新数据就在 `ta_store.cases_view()` / `state()` 里加字段。

## 五、给 AI 的维护指令

用户说“这条判错了，帮我补规则”时：
1. 用 `python scripts/ta.py show <批次> --json` 读这条用例的证据和当前结论。
2. 优先建议改关键字清单；需要自定义规则时，给出完整的一条（`id`、`name`、`when`、`then`、`note`），让用户在页面上添加并“试一下”。不要直接改 `rules.json`，除非用户明确要求。
3. 直接改了文件时，必须运行 `python scripts/ta.py check`，把输出原样告诉用户；有“✗”就说明没有完成。
4. 不删除、不修改别人加的纠错样本；样本本身错了，请用户确认后再删。
