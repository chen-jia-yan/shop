【接口】统一前缀 /tap/ai/library/kg，全部是 POST，请求体都带 scope（第 1 个接口除外）

1. POST /scopes/list：可以切换的图谱
   返回 items：scope、entity_count、relation_count、chunk_count、document_count、last_updated（取 Entity.updated_at 的最大值，没有就是 null）
   scope 列表取 Neo4j 中实际存在的 Entity.scope；不需要任何配置

2. POST /overview：左侧面板
   返回：entity_types（type、zh 中文名、count）、relation_types（type、zh、count）、
   related_raw_types（RELATED_TO 中出现最多的 20 种原始关系名及次数）、document_count

3. POST /documents/list：文档列表
   请求：scope、keyword（可选，按文件名包含）、page、page_size（1–100，默认 20）
   返回 items：document_id、filename、chunk_count、entity_count；以及 total、page、page_size

4. POST /entities/list：按条件筛选实体
   请求：scope、types（实体类型列表，可选）、keyword（可选）、document_id（可选）、page、page_size
   keyword 先用 SDK 的 normalize_label 处理，再与 label_norm 做包含匹配
   返回 items：id、type、type_zh、label、degree（关系数）、updated_at；以及 total、page、page_size

5. POST /subgraph：子图（前端画图用）
   请求：scope；以下三项必须且只能提供一项：entity_ids（1–20 个）、document_id、无（返回关系最多的前 50 个实体作为起点）
   另外可选：depth（1 或 2，默认 1）、relation_types、entity_types、limit（边数上限，1–500，默认 300）
   返回：nodes（id、type、type_zh、label）、edges（id、source、target、type、label：raw_types 第一个不为空就用它，否则用中文名）、truncated（是否被 limit 截断）
   depth 不能作为参数传进 Cypher：depth=1 和 depth=2 分别写一条固定语句

6. POST /entity/detail：实体详情
   请求：scope、id
   返回：实体的全部属性（不含 embedding）、按关系类型统计的数量、最多 20 个提到它的切片（chunk_id、source_file、page_or_sheet、preview）
   实体不存在 → CCB001 "实体不存在"

7. POST /changes/list：增量
   请求：scope、since_ms（必填）、page、page_size
   返回 items：kind（entity 或 relation）、id、label、type、updated_at，按 updated_at 倒序；以及 total、page、page_size
   没有 updated_at 的数据不返回

【中文名】
在 contracts/library_kg.py 中定义 ENTITY_TYPE_ZH 和 RELATION_ZH 两个字典（这是临时的，注释写明"以后统一改由 SDK 的 kg_schema 提供"）：
- 实体：Concept 概念、Product 产品、System 系统、Process 流程、Data 数据、Document 文档、Role 角色、Channel 渠道、Stage 阶段、Step 步骤、Action 动作
- 关系：NEXT 下一步、HANDLED_BY 负责人、PART_OF 属于、CONTAINS 包含、USES 使用、REQUIRES 需要、RELATED_TO 相关
- 查不到的类型，中文名就用英文原名

【规则】
1. 只读：所有查询只能用 MATCH / OPTIONAL MATCH / WITH / WHERE / RETURN / ORDER BY / SKIP / LIMIT / UNWIND / count / collect 等读操作，
   用只读会话（execute_read 或 default_access_mode=READ）执行。不得出现 CREATE、MERGE、SET、DELETE、REMOVE、DROP
2. 每条查询都带 scope 参数（第 1 个接口除外）；请求里的 scope 必须在第 1 个接口的列表里，否则返回 CCB001 "图谱不存在"。scope 列表缓存 60 秒
3. 类型筛选用参数（e.type IN $types、type(r) IN $relation_types），不得拼接字符串；传入的类型先按 ENTITY_TYPE_ZH、RELATION_ZH 的键校验，不在里面的返回 CCB001
4. 没有配置 neo4j_uri 时：路由照常挂载，所有接口返回 CCB001 "图谱未配置"。不新增任何开关
5. 分层：api 只调用 application；application 只依赖 contracts 里的接口；Neo4j 的实现放在 kg_browse.py；在 bootstrap.build_app 中组装
6. 返回格式、错误处理、分页写法全部照抄 api/library_kb.py
