【任务 ② 追加 · 评测结果结构化落盘（给看板读）】

目标：每跑完一轮评测，除了打印报告，再写一份结构化 JSON，供本地看板读取。只读评测、只写本地文件，不上传任何云端。

要求（只实现写文件，不要动评分逻辑本身）：

1. 落盘位置：evals/results/<run_id>.json
   - run_id = 运行开始时间，格式 YYYYMMDD-HHMMSS（例：20261009-224015）
   - 目录不存在则创建；绝不覆盖已有文件（同名则后缀 -2）

2. JSON 结构（严格按此 schema，看板依赖这些字段名）：
{
  "run_id": "20261009-224015",
  "started_at": "2026-10-09T22:40:15+08:00",
  "sample_size": 30,
  "pass_threshold": 4.0,
  "aggregate": {
    "answer_quality": 4.2,      // 头条：忠实/相关/完整/正确 的均值
    "faithfulness": 4.4,
    "answer_relevance": 4.3,
    "completeness": 3.8,
    "correctness": 4.1,
    "toehold_rate": 0.73        // 诊断用，0~1
  },
  "ab": {                        // 同一命中、两种上下文的分组均值
    "fragment":  {"faithfulness":2.9,"answer_relevance":3.4,"completeness":2.3,"correctness":3.1,"answer_quality":2.9},
    "rebuilt":   {"faithfulness":4.4,"answer_relevance":4.3,"completeness":3.8,"correctness":4.1,"answer_quality":4.2}
  },
  "counts": {"pass":22,"warn":5,"fail":3},
  "questions": [                 // 逐题
    {
      "id": "q01",
      "question": "……",
      "expected_source": "4-1 システム関連図 (slide-4)",
      "toehold": "hit",          // hit | partial | miss
      "fragment":  {"faithfulness":2.7,"answer_relevance":2.9,"completeness":2.4,"correctness":2.8,"answer_quality":2.7},
      "rebuilt":   {"faithfulness":4.7,"answer_relevance":4.6,"completeness":4.3,"correctness":4.5,"answer_quality":4.6},
      "verdict": "pass"          // pass | warn | fail
    }
  ]
}

3. 判定规则（与 ② 的 rubric 一致，不要新造）：
   - verdict：复原组 answer_quality ≥ 4.0 且 toehold ≠ miss → pass；
     answer_quality 在 3.0~4.0，或 toehold=partial → warn；其余 → fail
   - aggregate.answer_quality = 所有题 rebuilt.answer_quality 的均值
   - toehold_rate = (hit 计 1 + partial 计 0.5) / 题数

4. 不改历史：这是新增写文件，旧的打印报告保持原样；不引入之前修过的 bug（query-expansion 路径、中段物料计分、passed_count 运算符）。

5. 实现完先只跑一次小样本（3~5 题）确认 JSON 能正常生成、字段齐全，再给我看文件内容，别直接全量。
