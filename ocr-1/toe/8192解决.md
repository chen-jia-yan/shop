【任务：设计「超长 segment 的 embedding 分段」方案（plan mode 给设计+diff+测试；本任务不 re-ingest、不落地）】

定位：这是**针对大 sheet/slide 的鲁棒性改进**，不是当前 gold 题低分的原因（当前瓶颈是检索排序，已由 RRF 处理）。本任务独立、排在 RRF 验证之后，先把方案做扎实。

问题：切块是「整张 sheet/slide 作一个 segment」。小的没事，但大 sheet 超 embedding 8192 token 上限时会被截断或 embedding 失败，导致后半内容检索不到。

红线：只出设计 + diff + 单元测试，plan mode 给我看；本任务**不执行 re-ingest、不写线上索引、不改检索/评分**。全部行为用 feature flag 包起来、可回退；关掉 flag 即回到现状。

设计要求：
1. 两级结构：
   - 逻辑父 segment = 整张 sheet/slide（保持现状，供上下文/复原使用，不变）。
   - embedding 子块：**仅当父 segment 的 token 数超过预算**才拆；预算用项目 embedding 的 tokenizer 量，设 ~6000（给 8192 留余量）。小的完全不拆。
2. 送 embedding 前加**硬门**：任何要 embed 的文本超预算，必须先拆，绝不把超限内容发给 embedding（杜绝截断/失败）。
3. 拆分规则（在**结构化层**上拆，不要在原始带坐标乱文本上拆）：
   - 先按**块类型**切：表格区 / 流程图区 / 小节；
   - **流程图/图 = 原子块，绝不拆**；超预算时用「节点 + A→B 边列表」的压缩表示，再不行按连通子图/泳道切，保证每个节点连它的边不拆散；
   - **表格**按**行段**切：不切行中间；**每段重复带表头/列名**；优先在自然缝隙断（空行、首列分类变化、合并单元格小标题）；单个逻辑组仍超预算才在组内按行数切；段间留 1 行或组标签的小重叠；
   - 嵌入图片的 OCR 文字当整体，不跨段切。
4. 元数据：每个子块记 parent_segment_id、part_index、total_parts、source_file，保证子块能映射回父 segment、能按序重组。
5. 检索/上下文分离：检索命中子块 → 回答时可取回父 segment（或相关部分）作上下文；即"检索单元可以是子块，上下文单元仍是完整 segment"。
6. feature flag（如 KB_SEGMENT_SPLIT）默认关；关掉即现状。

交付（plan mode，别落地）：

- 涉及文件的 diff；
- 一个单元测试：构造一个超 8192 的 sheet（含一个表格 + 一张流程图），验证：产出多个子块、每块 token ≤ 预算、都能成功 embedding、流程图整块未被拆、父子映射与重组正确。
