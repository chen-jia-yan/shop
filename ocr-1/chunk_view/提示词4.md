# 提示词 4/4:应用生效(复用现有入库) + 切参效果评估

## 前置
在 3/4 完成之后做。**这一段会触及主链路的"编排层",风险最高,务必小步 + 可回退。**

## 目标
1. **应用生效**:把草稿(参数/编辑)真正落到知识库。
2. **效果评估**:调参前后,用一组测试问题比对检索效果,避免"切得顺眼、问答变差"。

## 参考
- RAG-TUI https://github.com/rasinmuhammed/rag-tui — 抄"用一组问题测命中率"的评估思路(离线做)。

## 具体改动
1. **应用生效 = 复用现有入库入口,把参数透传进去重新入库该文件**,而不是重写 worker/索引逻辑。要有:
   - 参数策略持久化(全局默认 / 按类型 / 单文件覆盖),并明确优先级;
   - **版本记录 + 一键回退**(新切片不好能退回旧版本)。
2. **效果评估**:给一组测试问题,跑现有检索,对比不同参数下的命中/结果,离线完成(复用现有 retriever)。

## 明确不做 / 护栏
- 不重写切片、解析、embedding、索引的**核心逻辑**;只做"透传参数 + 复用现有入库 + 加版本回退"。
- 应用生效要能**单文件试点**,不要一上来全量重跑。

## 保持不变
断点续跑 / 重试 / 幂等 / 单实例锁 / 解释器不变。

## 验收
- 对单个文件"应用"后,知识库确实用上新切片;不满意能一键回退。
- 能看到调参前后测试问题的检索对比。

## 验证方式
先单文件试点验证;确认稳了再谈批量。可控前提下再跑 worker。
