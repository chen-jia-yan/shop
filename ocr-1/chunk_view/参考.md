# 任务:chunk 可视化工作台 Phase 1(独立模块 + 参考成熟项目)

## 参考项目(先去看,再动手)
1. **RAGFlow** — https://github.com/infiniflow/ragflow
   抄这一点:客户向的 **chunk 展示与手动编辑 UX**——chunk 以可读卡片分层展示、能点开查看/调整。
2. **ChunkViz** — https://github.com/gkamradt/ChunkViz
   抄这一点:**滑块调 chunk_size/overlap → 实时重切 → 在原文上用颜色叠加标出每块边界**的交互范式。
3. **RAG-TUI** — https://github.com/rasinmuhammed/rag-tui （原理文章:https://dev.to/rasinmuhammed/i-built-a-tui-to-visualize-rag-chunking-because-chunksize1000-is-a-lie-1dg0）
   抄这一点:用 **🟢🟡🔴 标每一刀切得好不好**(干净/半截/硬切)+ 每块的 token/长度指标 + 离线设计思路。

## 怎么抄(方法,必须遵守)
- **先看后抄**:先打开这三个仓库的 README/截图/示例,各用两三句说清"它这个功能长什么样、值得借鉴哪一点",再动手。
- **抄模式,不抄整段代码**:用我们自己的技术栈(Python 后端 + 现有结构化元数据)最小化重写;不要引入它们的依赖、不要整仓照搬;若参考到具体代码,尊重其开源许可,只借思路、不粘贴。
- **适配我们的约束**:全离线(不调任何外部服务)、复用我们已有的 `title_path/block_type/artifact_path/ocr_blocks` 元数据、复用我们真正的切片器(见下)。

## 范围(严格隔离,别扩散)
- 新建**独立模块 `kb_chunk_studio/`**(自己的接口 + service + 前端页面/tab)。
- **不改主 UI(modern_chat_page)、不改 worker / 索引内部。**
- 只通过**两个细口子**接触现有代码:① 读已落盘的 artifact / chunk JSON;② 调用 `_chunk_document()` 重切。

## 唯一允许的核心改动(极小、向后兼容)
- 给 `_chunk_document()` 和 `_chunk_profile()` 加**可选 override 参数**(如 `profile_overrides=None`):
  - 不传 = **完全维持现有行为,生产路径零影响**;
  - 传了 = 用临时的 chunk_size/overlap 覆盖,供预览用。
- **禁止用 monkey-patch 临时改全局常量**那种做法(隐藏副作用、不安全)。

## 功能(Phase 1 = 预览沙盒,不写正式索引)
- 左:结构树(slide/sheet → block);中:参数面板(chunk_size / overlap / 内容类型 profile);右:chunk 卡片。
- chunk 卡片:**颜色标切得好不好**(抄 RAG-TUI)+ **显示每块 token 数**(把超长块暴露出来)+ 点击溯源 `title_path/block_type/artifact_path`。
- **解析只做一次**(读已落盘 artifact / 缓存 segments),**切片随参数重跑**(便宜)——不要每次重新 parse+OCR。
- 支持**新旧参数并排对比**。
- **不写正式索引、不入库**(那是 Phase 2)。

## 验收标准
- 独立模块——删掉它,主流程不受任何影响。
- 预览用的是**真的 `_chunk_document()`**,和生产切法一致(不是另写一套)。
- 生产路径行为不变(override 默认不传时)。
- 页面能:结构树 + 调参实时重切 + 颜色质量标记 + token 数 + 新旧对比。

## 验证方式
静态检查 + 单文件小测,**不要真跑整个 worker**。
