【任务】实现"检索命中后回填所在表格区域"（small-to-big），放在开关后面，默认关闭。

【安全规则（必须遵守）】
- 不改入库、切分、向量化逻辑；不对 jp-poc 索引做任何写入、删除、重建
- 新功能全部放在开关 KB_RETRIEVAL_EXPAND 后面，默认 off；off 时行为必须与现在逐字节一致
- 测试只用 fixtures / 内存数据，绝不连真实索引
- 不要自己运行端到端评估、不要自己改开关为 on，这些由我本人执行

【设计】
1. 位置：在"检索返回 top-K"之后、"组装交给大模型的 context"之前插入一个 expand 步骤（LLM 链路和 agent 链路共用）
2. 对每个命中的 Excel 单元格级 chunk：
   a. 找到同一 (source_file, sheet) 下的兄弟 chunk（数据来源按调查结论：优先本地 jsonl 只读加载；或对索引做只读 filter 查询）
   b. 回填范围 = 表头行 + 命中行 + 上下各 N 行（KB_EXPAND_NEIGHBOR_ROWS，默认 3）
      - 表头行：若切分时已识别表头就用它；否则取该表区域的第 1 行
   c. 按原表顺序拼成一个"区域块"，标注：文件名 / sheet 名 / 单元格范围
3. 合并去重：同一区域被多个命中引中，只回填一次，保留最高分
4. 长度预算：单个区域块不超过 KB_EXPAND_MAX_CHARS（默认 1500）；总 context 不超过现有上限。超了就收缩邻居行，表头和命中行永远保留
5. 非 Excel 的 chunk（pptx 等）原样不动
6. 留痕：work_logs 里记录每个区域块由哪些 chunk_id 组成、回填了哪个范围（后续评估要用，判官也要能拿到这份证据）

【测试（fixtures）】
- 开关 off：输出与改动前完全一致
- 命中中间某行：区域块包含表头 + 命中行 + 邻居行，顺序正确
- 两个命中在同一区域：只回填一次
- 超长：表头和命中行保留，邻居行被裁
- 非 Excel chunk：不受影响
- 找不到兄弟 chunk：退回原 chunk，不报错

【交付】
改动文件清单 + 每处改动说明 + 测试结果。不要提交，不要改开关。
