# A部分：表格父segment存在性
## A1. 是否存在包含整张表所有行的父segment？
不存在。Excel解析后每个sheet按行生成segment（每个segment对应一个locator，即sheet名），然后在 `_chunk_document()` 中对每个segment的text做按行切（`_split_text()`）。一张sheet的所有文本以一个segment的text形式传入，但被切成多个chunk。没有一个独立的「父segment」对象存有整张表的完整文本。

但原始segment的text本可以包含整张表的所有行——只是 `_split_text()` 将其切割成了多子chunk，每个chunk最大700字符（CHUNK_SIZE）。

探测验证结果：
- 对【业务设计要约】Medical Revision2 2023_FWDnavi_ver1.0.xlsx 的「业务设计要约」sheet，索引中共有若干chunk
- 含「新契约一览」的chunk a0a1bbb94559 确实存在于索引中(sheet=业务设计要约)，内容包含：
```
[行] 业务设计要约!A25:CG25: S25-8 | Z25-D2040 | AD25-システム管理
[行] 业务设计要约!A26:CG26: S26-9 | T26-新契约 | Z26-D3010 | AD26-新契约一览
[行] 业务设计要约!A27:CG27: S27-10 | Z27-D3020 | AD27-新契约照会
```
- 问题[7]的检索结果中，这个chunk没有进入top-10。top-1的 cc6012761217 只覆盖了表的开头部分（行10-19），没覆盖到D3010所在行（行2526）。

## A2. 子块的metadata中有没有能链回父segment的字段？
有间接方式，但没有直接锚位。每个chunk的metadata包含：

|字段|值示例|用途|
| ---- | ---- | ---- |
|source_file|【业务设计要约】Medical Revision2 2023_FWDnavi_ver1.0.xlsx|定位文档|
|page_or_sheet|业务设计要约|定位sheet|
|cell_range|(空——当前Excel chunk未填充此字段)|按理想定位行范围|
|block_type|cell|区分类型|

注意：`cell_range` 在所有探测到的chunk中均为空字符串，无法用其区分同一sheet内的不同行范围。没有 `parent_segment_id` 或 `segment_id` 这种直接指标。

## A3. 能否程序化取回完整父segment文本？
不能直接取回一个「父segment」对象——因为入库时没有保留未切分的原始segment文本。但可以做到近似还原：

方式：按 `source_file + page_or_sheet` 从Azure Search取回同一sheet的所有chunk，然后按行号排序拼接。

验证可行性的证据：
- Azure Search 的 `delete_chunks_by_source_file()` 和 `count_chunks_by_source_file()` 都已有按 `source_file` 过滤的能力
- `_METADATA_FIELDS` 包含 `page_or_sheet`，但不是 filterable（当前的 index schema 中 `page_or_sheet` 是 SearchableField，需要确认是否有 filterable 属性）

最小取回方式（伪代码）：
```python
# 按 source_file + sheet 获取所有 chunk
store_search_client.search(
    search_text="",
    filter=f"source_file eq '{source_file}'", # page_or_sheet 可能无法过滤
    select=["chunk_id", "content", "page_or_sheet"],
    top=500,
)
# 手动筛选出同一 sheet 的 chunk，按内容中的行号 [行] sheet!A25 排序拼接
```

限制：`page_or_sheet` 字段在 index schema 中未设为 filterable（只设为 SearchableField），所以无法直接 `filter=page_or_sheet eq 'xxx'`。需要取回整个文档的所有chunk后手动筛选。

## A4. 同一张表的所有子块能否拼回完整表？
能。同一sheet（业务设计要约）的所有chunk共享相同的 `source_file`，每个chunk内容中的行标记如 `[行] 业务设计要约!A25:CG25:` 提供了行号。按行号排序即可拼回完整表。

但当前 `cell_range` metadata字段为空，需要从内容文本中正则提取行号来排序。

## B2. 传给 _judge 的「被评测答案」是什么？
代码调用链（runtime.py:97-131）：
```python
# 第 102 行: 赋值

# answer 是 LLM completion 的返回值

# 第 109-118 行: 传给裁判
scores = self._judge_or_mark_failed(
    question=question,
    expected_answer=expected_answer,
    expected_source=expected_source,
    retrieval_context=retrieval_context,
    actual_output=answer,        # ← LLM 生成的答案
    client=client,
    ...
)

# 第 130 行: 也存入结果
"actual_output": answer,
```

裁判prompt中引用为（runtime.py:404）：
```
【系统生成的答案】{actual_output or "(生成失败)"}
```

结论：传给裁判的 `actual_output` 是 LLM 的 completion 输出，不是检索上下文原文。
