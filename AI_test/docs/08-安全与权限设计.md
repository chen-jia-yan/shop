# 安全与权限设计

> **文档版本**：v1.0  
> **适用范围**：AI-Powered Intelligent Testing Platform（基于微软生态的智能测试平台）  
> **技术栈**：Power Apps + Power Pages + Copilot Studio + Power Automate + Azure Functions + Dataverse + SharePoint + Azure SQL + Azure Blob Storage + Azure OpenAI + Azure AI Search + Azure DevOps + Teams + Outlook

---

## 1. 身份认证与授权

### 1.1 Azure AD / Entra ID 集成

平台全量集成 Microsoft Entra ID（原 Azure AD），作为唯一身份源。

| 组件 | 认证方式 | 说明 |
|------|----------|------|
| Power Apps | Entra ID + 条件访问 | 用户通过组织账号登录，内置 MFA 支持 |
| Power Pages | Entra ID + 外部身份提供商（可选） | 支持 Azure AD B2C 外部用户认证 |
| Copilot Studio | Entra ID 单点登录 | 支持 Teams / Web 渠道的统一认证 |
| Power Automate | Entra ID + 连接参考（Connection Reference） | 流程运行时使用连接所有者或服务主体身份 |
| Azure Functions | 托管标识 + API Key（次要） | 函数间调用使用托管标识，对外暴露用 API Key + Entra ID |
| Azure OpenAI | Entra ID RBAC + API Key | 后端服务通过托管标识访问，禁止前端直接调用 |
| Azure DevOps | Entra ID + PAT / OAuth | CI/CD 使用服务主体身份 |

**条件访问策略建议**：

- 要求所有用户注册 MFA
- 敏感操作（修改测试计划、管理角色）触发二次验证
- 限制登录 IP 范围（仅在办公网络或 VPN 内可访问管理端）
- 设备合规要求（Intune 托管设备优先）

### 1.2 多租户隔离

平台部署模式为**单租户部署**（Single-Tenant），每个客户独立一套环境。

| 隔离维度 | 策略 |
|----------|------|
| 数据层 | 每个租户独立 Dataverse 环境 + 独立 Azure SQL 数据库 + 独立 Blob 容器 |
| 应用层 | 每个租户独立 Power Apps 应用副本，通过环境隔离 |
| AI 服务 | 共享 Azure OpenAI 实例，通过 RBAC + 数据标签隔离 |
| 文件存储 | 每个租户独立 SharePoint 站点集 |
| 网络 | 每个租户独立 VNet + 私有终结点 |

> **不采用多租户共享数据架构**。原因：客户对测试数据的安全隔离要求高，共享架构引入的数据泄漏风险和复杂度过高。

### 1.3 服务主体管理

| 服务主体名称 | 用途 | 权限范围 |
|-------------|------|----------|
| `ageb-api-sp` | Azure Functions 后台 API | SQL / Blob / Search 数据平面访问 |
| `ageb-automation-sp` | Power Automate 流程自动化 | Dataverse / SharePoint / DevOps API |
| `ageb-cicd-sp` | Azure DevOps CI/CD 流水线 | 资源组部署 / Functions 发布 |
| `ageb-ai-sp` | Azure OpenAI 模型调用 | OpenAI 认知服务访问 |
| `ageb-monitor-sp` | 监控与审计日志采集 | Log Analytics / 审计日志只读 |

**密钥管理**：

- 服务主体密钥有效期不超过 12 个月
- 使用托管标识（Managed Identity）替代密钥（Azure Functions / App Services 场景）
- 必须使用密钥的场景：密钥存入 Key Vault，运行时通过 Key Vault 引用获取
- 每季度轮换一次

### 2.2 权限最小化原则

- 每个角色只分配完成工作所需的最小权限
- 管理员角色仅限 2–3 人
- 定期审计（每季度）清理不活跃账号和过度授权
- 临时提权流程：项目经理可通过审批流程临时获得高权限（24 小时自动回收）

## 3. Dataverse 安全

### 3.1 业务单元设计

```
Root BU: AI Testing Platform
│
├── Production Environments
│   ├── BYD Auto（比亚迪）
│   ├── CATL（宁德时代）
│   └── NIO（蔚来）
│
├── Staging Environments
│   └── Internal Testing
│
└── System Administration
    └── Admin BU
```

- 每个客户（租户）分配独立的业务单元
- 业务单元层级决定数据可见性：上级 BU 可查看下级数据，同级 BU 互不可见
- 系统管理员属于 Admin BU，可跨 BU 操作

### 3.2 安全角色配置

| 安全角色 | 对应平台角色 | 创建位置 | 继承关系 |
|---------|------------|---------|---------|
| `ageb-SystemAdmin` | 系统管理员 | Admin BU | 基础环境管理员权限 |
| `ageb-ProjectManager` | 项目经理 | 客户 BU | 读+写 BU 内数据 |
| `ageb-TestManager` | 测试经理 | 客户 BU | 读+写 BU 内测试实体 |
| `ageb-TestEngineer` | 测试工程师 | 客户 BU | 读+写 BU 内测试用例/执行 |
| `ageb-DevEngineer` | 开发工程师 | 客户 BU | 读 BU 内数据 + 写缺陷 |
| `ageb-ReadOnly` | 只读用户 | 客户 BU | 仅读 BU 内数据 |

**权限层级**：

| 安全角色 | 可见范围 | 创建权限 | 写入权限 | 删除权限 | 共享权限 |
|---------|---------|---------|---------|---------|---------|
| SystemAdmin | 父级：下级 BU | 全局 | 全局 | 全局 | 全局 |
| ProjectManager | 业务单元 | ✅ | ✅ | ❌ | ❌ |
| TestManager | 业务单元 | ✅ | ✅ | ✅ | ✅ |
| TestEngineer | 业务单元 | ✅ | ✅ | ❌ | ❌ |
| DevEngineer | 业务单元 | ❌ | 仅缺陷 | ❌ | ❌ |
| ReadOnly | 业务单元 | ❌ | ❌ | ❌ | ❌ |

### 3.3 字段级安全

以下敏感字段启用字段级安全：

| 表名 | 字段 | 可读角色 | 可写角色 |
|-----|------|---------|---------|
| 项目（Project） | 预算（Budget） | 项目经理及以上 | 项目经理及以上 |
| 项目（Project） | 合同信息（ContractInfo） | 系统管理员 | 系统管理员 |
| 用户（User） | 手机号（Phone） | 本人 + 系统管理员 | 本人 + 系统管理员 |
| 测试计划（TestPlan） | AI 分析结果（AIAnalysis） | 测试经理及以上 | 测试经理 |
| 缺陷（Bug） | 严重等级（Severity） | 所有人 | 测试经理、开发工程师 |
| 配置（Config） | API 密钥占位（ApiKeyRef） | 系统管理员 | 系统管理员 |

### 3.4 层次安全模型

- 测试计划 → 测试用例：层级继承，删除测试计划时级联删除下层用例
- 项目 → 测试计划 → 测试套件：权限沿层级继承
- 用户在所属 BU 内自动获得对应角色的数据访问权限
- 跨团队协作通过**团队（Team）**共享：将外部团队成员加入项目团队后，授予最小必要权限

## 4. 各服务安全配置

### 4.1 Power Apps

| 安全项 | 配置策略 |
|--------|---------|
| 应用共享 | 按 Entra ID 安全组共享，不直接共享给个人 |
| 环境安全 | 每个项目阶段（Dev / Test / Staging / Prod）独立环境 |
| 数据丢失防护 | 配置 DLP 策略，禁止 Power Apps 连接非白名单的外部服务 |
| Canvas App 属性 | 禁用"作为非拥有者运行"，启用"要求用户确认" |
| Model-Driven App | 基于安全角色自动控制 CRUD 权限 |
| 移动端安全 | 启用移动端离线数据加密（Power Apps Mobile） |

### 4.2 Power Pages

| 安全项 | 配置策略 |
|--------|---------|
| 外部访问 | 仅限 Entra ID 认证用户访问 |
| 页面权限 | 按 Web 角色控制页面可见性 |
| 表单权限 | 按 Web 角色 + 记录级权限控制 |
| API 端点 | 启用 CSRF 保护，限制源请求头 |
| IP 限制 | 仅允许企业网络和 VPN IP 访问管理页面 |

### 4.3 Power Automate

| 安全项 | 配置策略 |
|--------|---------|
| 连接引用 | 使用连接引用（Connection Reference）而非硬编码连接 |
| 共享运行 | 即时流程使用"运行用户"身份，避免权限扩散 |
| DLP 策略 | 环境级 DLP：禁止未批准连接器组合 |
| 错误处理 | 配置运行失败告警（Teams 通知），错误信息不暴露敏感数据 |
| 审批流程 | 敏感操作（角色变更、删除数据）必须经过审批 |
| 流所有者 | 使用服务主体或专用服务账号，不使用个人账号 |

**DLP 策略层级**：

```
企业级 DLP（默认策略）
  └── 生产环境 DLP（严格）
      ├── 业务连接器（Dataverse / SharePoint / SQL / DevOps）→ 允许
      ├── AI 连接器（OpenAI）→ 允许
      ├── 协作连接器（Teams / Outlook）→ 允许
      ├── 第三方连接器 → 禁止
      └── HTTP 自定义连接 → 只允许内部域名
  └── 开发环境 DLP（宽松）
      └── 业务连接器 + AI 连接器 → 允许
```

### 4.4 Copilot Studio

| 安全项 | 配置策略 |
|--------|---------|
| 身份验证 | 配置为"仅限经过身份验证的用户"，不使用匿名 |
| 数据隔离 | 主题（Topic）范围限制，禁止跨租户数据访问 |
| 变量保护 | 敏感变量标记为"不记录"，不在对话日志中持久化 |
| 知识源 | 仅连接已授权的 SharePoint / Dataverse 数据源 |
| 发布渠道 | 仅限内部 Teams 渠道和授权 Web 渠道 |
| 内容过滤 | 配置敏感内容过滤规则，防止 Copilot 输出测试凭据等敏感信息 |
| 对话日志 | 启用审核，日志保留 90 天 |

### 4.5 Azure OpenAI

| 安全项 | 配置策略 |
|--------|---------|
| 网络隔离 | 启用私有终结点，限制 VNet 内访问 |
| 身份认证 | 优先托管标识（Managed Identity），次选 API Key |
| API Key 管理 | Key 存入 Key Vault，函数通过 Key Vault Reference 读取 |
| 内容过滤 | 使用 Azure AI Content Safety，配置自定义内容分类 |
| 数据隔离 | 每个客户模型部署实例独立，禁止共享推理上下文 |
| Rate Limiting | 按客户设置 Token 调用配额，防止滥用 |
| 日志记录 | 启用 Request/Response 诊断日志（不记录完整 Prompt 内容） |
| 模型版本 | 固定部署版本号，不自动升级，变更前先在 Staging 验证 |

**内容过滤规则**：

| 过滤类别 | 严重级别阈值 | 动作 |
|---------|------------|------|
| 仇恨言论 | 低 | 阻止 + 记录 |
| 暴力内容 | 中 | 阻止 + 告警 |
| 敏感数据（密钥/密码） | 低 | 脱敏 + 记录 |
| 客户保密数据 | 中 | 阻止 + 告警 + 记录 |
| 模型越狱尝试 | 低 | 阻止 + 记录 + 审计 |

### 4.6 Azure Functions

| 安全项 | 配置策略 |
|--------|---------|
| 托管标识 | 每个 Function App 分配系统托管标识 |
| 网络隔离 | 部署到 VNet，启用 VNet Integration 和私有终结点 |
| 认证 | 对外 HTTP 端点启用 Easy Auth（Entra ID） |
| 访问限制 | IP 白名单：仅允许 Power Automate IP 范围和 VNet IP |
| Key 管理 | Function Key 不使用默认密钥，每个函数独立密钥 |
| 敏感配置 | app settings 中使用 `@Microsoft.KeyVault()` 引用 |
| CORS | 仅允许 Power Apps / Power Pages 域名 |
| 容错 | 启用 Application Insights 异常追踪，错误响应不暴露内部信息 |

### 4.7 Azure SQL

| 安全项 | 配置策略 |
|--------|---------|
| 网络隔离 | 禁用公共访问，仅允许 Azure 服务和私有终结点连接 |
| 身份认证 | 仅 Azure AD 认证，禁用 SQL 身份验证 |
| TDE | 启用透明数据加密（TDE），使用客户管理的密钥（CMK） |
| 行级安全 | 启用 RLS（Row-Level Security），按 TenantId 自动隔离 |
| 动态数据脱敏 | 对敏感列（电话、邮箱、Token）启用脱敏 |
| 审计日志 | 启用 SQL Auditing，日志发送到 Log Analytics |
| 防火墙 | 仅允许 Functions 托管标识和特定 Azure 服务访问 |
| 高级威胁保护 | 启用 Advanced Threat Protection，异常检测自动告警 |

**RLS 策略示例**：

```sql
CREATE SECURITY POLICY TenantFilterPolicy
    ADD FILTER PREDICATE dbo.fn_tenantAccessPredicate(TenantId)
    ON dbo.TestRuns,
    ADD BLOCK PREDICATE dbo.fn_tenantAccessPredicate(TenantId)
    ON dbo.TestRuns;
```

### 4.8 Azure Blob Storage

| 安全项 | 配置策略 |
|--------|---------|
| 网络访问 | 启用私有终结点，禁止公共访问 |
| 认证 | 函数通过托管标识访问，不使用存储账户密钥 |
| 容器隔离 | 每个客户独立容器，容器级权限管理 |
| 加密 | SSE 默认加密，启用客户管理密钥 |
| 软删除 | 启用 Blob 软删除，保留期 30 天 |
| 版本控制 | 启用版本控制，AI 测试报告保留所有历史版本 |
| 访问日志 | 启用存储分析日志，记录所有读/写操作 |

### 4.9 SharePoint

| 安全项 | 配置策略 |
|--------|---------|
| 站点权限 | 每个客户独立 SharePoint 站点，按安全组分配访问 |
| 文档库权限 | 不同库设置不同权限（测试报告库只读 / 模板库可写） |
| 共享策略 | 禁止外部共享，仅允许内部用户使用"特定人员"链接 |
| 版本控制 | 文档库启用版本控制，保留主要版本 50 个 |
| IRM | 敏感文档启用信息权限管理（IRM），禁止下载/打印 |
| 保留策略 | 测试报告保留 2 年，执行日志保留 6 个月 |
| 敏感度标签 | 测试报告自动应用"内部"标签；含客户数据的报告应用"机密"标签 |

## 5. 数据安全

### 5.1 数据分类

| 分类等级 | 定义 | 示例 | 存储约束 |
|---------|------|------|---------|
| 公开（Public） | 可公开的非敏感信息 | 产品名称、公开文档 | 无特殊要求 |
| 内部（Internal） | 仅限组织内部 | 测试用例、测试计划、项目进度 | 标准加密 + RBAC |
| 机密（Confidential） | 泄露有中高影响 | 测试数据、AI 分析报告、客户配置 | 加密 + 字段级安全 + 审计 |
| 高度机密（Highly Confidential） | 泄露有严重影响 | 客户凭据、连接字符串、API 密钥、合同信息 | CMK 加密 + 字段级安全 + 完整审计 + 脱敏 |

### 5.2 传输加密

- 全部通信要求 TLS 1.2 以上
- 内部服务间（VNet 内）同样启用 TLS
- Azure Functions → SQL：强制加密连接（`Encrypt=True; TrustServerCertificate=False`）
- Power Apps → Dataverse：平台自动强制 HTTPS，无需额外配置
- Blob 传输：仅支持 HTTPS，禁用 HTTP

### 5.3 静态加密

| 存储组件 | 加密方式 | 密钥管理 |
|---------|---------|---------|
| Dataverse | 平台默认加密（透明） | Microsoft 托管密钥 或 CMK |
| Azure SQL | TDE | CMK（Key Vault） |
| Azure Blob | SSE | CMK（Key Vault） |
| SharePoint | 平台默认加密 | Microsoft 托管密钥 |
| Azure Functions 配置 | 平台加密 at rest | Key Vault 引用 |
| Azure AI Search | 平台默认加密 | CMK（可选） |

### 5.4 数据保留策略

| 数据类型 | 保留期 | 归档策略 | 删除确认 |
|---------|-------|---------|---------|
| 测试用例 | 永久（项目存续期间） | 不归档 | 项目经理审批 |
| 测试执行记录 | 2 年 | 12 个月后归档到冷存储 | 自动清理 + 审计 |
| AI 分析报告 | 2 年 | 同上 | 自动清理 |
| 日志（调试级别） | 30 天 | 不归档 | 自动清理 |
| 审计日志 | 5 年 | 12 个月后归档到 Log Analytics 长期存储 | 不可删除 |
| 缺陷/变更记录 | 永久（项目存续期间） | 不归档 | 项目经理审批 |
| Blob 附件（截图/日志） | 2 年 | 30 天软删除 | 自动清理 + 审计 |
| Power Automate 运行历史 | 28 天（按平台默认） | 不归档 | 自动清理 |
| Copilot 对话日志 | 90 天 | 不归档 | 自动清理 |

### 5.5 数据脱敏规则

| 字段类型 | 脱敏策略 | 示例 |
|---------|---------|------|
| 电话号码 | 保留后 4 位 | `138****1234` |
| 邮箱地址 | 保留域名 + 首字符 | `j***@company.com` |
| API Key / Token | 保留前 4 位 + 掩码 | `sk-45************` |
| 连接字符串 | 完全掩码 | `********` |
| 真实姓名 | 保留姓氏 | `张**` |
| 身份证号 | 保留后 4 位 | `**************1234` |
| IP 地址 | 保留前 3 段 | `10.0.1.***` |

**脱敏触发场景**：

- 非管理员角色查看详细信息时自动脱敏
- 导出报表到 Excel 时按角色脱敏
- AI 分析日志输出前自动脱敏（使用 Azure AI Content Safety）
- 审计日志中敏感字段脱敏显示

### 6.1 审计日志设计

**审计事件分类**：

| 类别 | 事件 | 记录内容 | 存储 |
|------|------|---------|------|
| 认证事件 | 登录/登出、MFA、令牌刷新 | 用户、时间、IP、设备、结果 | Dataverse Audit + Log Analytics |
| 授权事件 | 角色分配/变更、权限提升 | 操作人、目标用户、新旧角色 | Dataverse Audit |
| 数据操作 | 增/删/改 测试用例、计划、项目 | 操作人、操作类型、实体、时间戳 | Dataverse Audit |
| AI 调用 | OpenAI 请求/响应（摘要级） | 调用方、模型、Token 用量、响应时间 | Application Insights |
| 配置变更 | DLP 策略修改、环境配置修改 | 操作人、变更内容、时间 | Office 365 Audit Log |
| 流程执行 | Power Automate 运行、错误 | 流程名称、触发者、结果、错误详情 | Power Automate Analytics |
| 文件操作 | SharePoint 文件上传/下载/删除 | 操作人、文件名、操作类型 | SharePoint Audit |
| 管理操作 | 服务主体密钥轮换、网络配置修改 | 操作人、操作内容、时间 | Azure Activity Log |

### 6.2 合规检查清单

| 检查项 | 合规要求 | 验证方式 | 频率 |
|-------|---------|---------|------|
| MFA 启用率 | 100% 管理员 + 90% 普通用户 | Entra ID 报告 | 月度 |
| 闲置账号清理 | 90 天未登录账号自动禁用 | Entra ID 自动策略 | 持续 |
| 角色审计 | 管理员账号不超过 5 人 | Entra ID 报告 | 季度 |
| 应用权限 | 无个人账号直接共享应用，仅通过安全组 | Power Platform 管理中心 | 季度 |
| DLP 策略 | 生产环境 DLP 100% 覆盖 | Power Platform 管理中心 | 季度 |
| 密钥轮换 | 服务主体密钥有效期 < 12 个月 | Key Vault + 脚本 | 季度 |
| SQL 审计 | 审计日志持续启用 | Azure Monitor | 月度 |
| 网络隔离 | 生产环境 100% 使用私有终结点 | Azure 网络审查 | 月度 |
| 数据保留清理 | 过期数据按策略删除 | 自动清理任务 + 验证 | 月度 |
| 备份恢复测试 | 每月一次恢复演练 | 手动恢复测试 | 月度 |
| 安全培训 | 全员完成年度安全培训 | HR + IT 协作 | 年度 |
| 渗透测试 | 每年一次第三方渗透测试 | 外部安全团队 | 年度 |

### 6.3 安全事件响应流程

```
检测 → 分级 → 抑制 → 消除 → 恢复 → 复盘
```

**事件分级**：

| 级别 | 定义 | 响应时间 | 上报路径 |
|------|------|---------|---------|
| P1（严重） | 数据泄露 / 权限绕过 / 服务中断 | 15 分钟响应 | 安全团队 + CISO |
| P2（高） | 可疑访问 / 异常大量调用 | 1 小时内响应 | 安全团队 |
| P3（中） | 配置漏洞 / 告警误报 | 1 个工作日内 | 运维团队 |
| P4（低） | 审计提醒 / 策略建议 | 下个迭代 | 迭代计划 |

**响应流程**：

```
[检测]
  ├─ 自动告警（Sentinel / Log Analytics）
  └─ 人工上报
       ↓
[分诊]
  ├─ 确认事件真实性
  ├─ 判定级别（P1–P4）
  └─ 组建响应小组
       ↓
[抑制]
  ├─ 隔离受影响组件（切断连接 / 禁用账号 / 关闭端点）
  ├─ 保留现场证据（快照 / 日志导出）
  └─ 通知相关方
       ↓
[消除]
  ├─ 修复漏洞
  ├─ 轮换受影响密钥/证书
  └─ 恢复服务
       ↓
[恢复]
  ├─ 验证修复有效性
  ├─ 恢复业务运行
  └─ 持续监控 72 小时
       ↓
[复盘]
  ├─ 编写事件报告（5 Why 分析）
  ├─ 更新安全策略和检测规则
  └─ 跟踪整改措施闭环
```

**协同通道**：

- 事件沟通：Teams 专用频道（#security-incident）
- 通知：自动触发 Outlook 邮件通知到安全团队分发组
- 记录：每次事件记录到 Dataverse "安全事件"实体
- 复盘：事件关闭后 7 天内完成复盘
