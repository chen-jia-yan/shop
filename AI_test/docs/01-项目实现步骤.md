### 3.3 Azure SQL 表设计

存放 Dataverse 不适合的数据：大量时序数据、Playwright 执行日志。

```sql
-- 执行日志表
CREATE TABLE ExecutionLog (
    LogId BIGINT IDENTITY PRIMARY KEY,
    ExecutionId UNIQUEIDENTIFIER NOT NULL,
    Timestamp DATETIME2 NOT NULL DEFAULT GETUTCDATE(),
    LogLevel NVARCHAR(20),        -- INFO / WARN / ERROR / DEBUG
    Category NVARCHAR(100),       -- Playwright / AI / Pipeline
    Message NVARCHAR(MAX),
    StackTrace NVARCHAR(MAX)
);
CREATE INDEX IX_ExecutionLog_ExecutionId ON ExecutionLog(ExecutionId);
CREATE INDEX IX_ExecutionLog_Timestamp ON ExecutionLog(Timestamp);

-- 测试指标汇总表
CREATE TABLE TestMetricsSummary (
    MetricsDate DATE PRIMARY KEY,
    TotalRuns INT,
    PassCount INT,
    FailCount INT,
    SkipCount INT,
    AvgDurationMs BIGINT,
    AiGeneratedCases INT,
    AutomationRate DECIMAL(5,2),  -- 自动化覆盖率百分比
    CreatedAt DATETIME2 DEFAULT GETUTCDATE()
);

-- 失败模式聚合表（供 AI 分析使用）
CREATE TABLE FailurePattern (
    PatternId INT IDENTITY PRIMARY KEY,
    ErrorSignature NVARCHAR(500),  -- 去参后的错误签名
    Frequency INT,
    FirstSeen DATE,
    LastSeen DATE,
    CommonRootCause NVARCHAR(MAX),
    CreatedAt DATETIME2 DEFAULT GETUTCDATE()
);
CREATE INDEX IX_FailurePattern_Error ON FailurePattern(ErrorSignature);
```

| 模型 | 部署名 | SKU | 用途 |

关键配置项：

```
# 部署参数

max-tokens: 4096 (gpt-4o-mini 用 16384)
temperature: 0.2 (分析类任务) / 0.7 (生成类任务)
```

设置 Content Filter：
- 分析类 Prompt：默认内容过滤
- 测试脚本文本：关闭代码侧的过滤（否则会误杀合法代码）

### 4.3 Prompt 模板管理

所有 Prompt 模板存于 GitHub 仓库 `ai-models/prompts/`，通过 Azure Functions 加载后调用 OpenAI。

| 文件 | 用途 |
|------|------|
| `analyze-requirement.md` | 需求分析 Prompt |
| `generate-test-cases.md` | 测试用例生成 Prompt |
| `review-test-cases.md` | 用例评审 Prompt |
| `generate-script.md` | Playwright 脚本生成 Prompt |
| `analyze-failure.md` | 失败根因分析 Prompt |
| `generate-report.md` | 报告摘要生成 Prompt |
| `classify-defect.md` | 缺陷分类 Prompt |

示例：`generate-test-cases.md`

```
你是一名资深测试工程师。根据以下需求和已有相关用例，生成测试用例。

## 被测试需求
{requirement}

## 已有相关用例（供参考，避免重复）
{related_cases}

## 输出格式
返回 JSON 数组，每个元素包含：

- steps: 步骤数组

2. 步骤要具体到操作级，不能笼统
```

### 4.4 AI 调用封装

Azure Functions 中封装统一调用层：

| 函数 | 触发 | 调用模型 | 用途 |
|------|------|---------|------|
| AnalyzeRequirement | Service Bus | gpt-4o | 需求分析 |
| GenerateTestCases | Service Bus | gpt-4o | 用例生成 |
| ReviewTestCases | HTTP | gpt-4o | 用例评审 |
| GenerateScript | HTTP | gpt-4o-mini | 脚本生成 |
| AnalyzeFailure | Service Bus | gpt-4o | 失败分析 |

所有函数通过统一的 `AIService` 类调用：

```csharp
// 统一调用模式
public class AIService
{
    private readonly OpenAIClient _client;
    private readonly IPromptLoader _promptLoader;
    private readonly ISearchService _searchService;

    public async Task<AIResult> CallWithContextAsync(
        string promptKey,        // prompt template Key
        object parameters,       // 模板参数
        SearchContext? context)  // RAG 检索上下文
    {
        // 1. 加载 Prompt 模板
        var template = await _promptLoader.LoadAsync(promptKey);

        // 2. 注入 RAG 上下文（如有）
        if (context != null)
        {
            var relatedDocs = await _searchService.SearchAsync(context.Query, context.Filters);
            parameters.relatedContext = relatedDocs;
        }

        // 3. 渲染 Prompt
        var prompt = RenderTemplate(template, parameters);

        // 4. 调用 OpenAI
        var response = await _client.GetChatCompletionsAsync("gpt-4o", prompt);

        // 5. 解析 + 校验
        return ParseResult(response.Value.Choices[0].Message.Content);
    }
}
```

### 5.2 需求管理模块

**前端**：Power Apps Canvas App — `TestRequirementApp`

功能：
- 从 Azure DevOps / Jira 同步需求
- 手动录入需求
- 需求列表 + 详情 + 搜索
- 触发 AI 需求分析

**后端流程**：

```
用户导入需求
    ↓
Power Automate 触发 → 拉取 DevOps Work Item
    ↓
写入 Dataverse UserStory
    ↓
发送 Service Bus 消息 → Azure Functions AnalyzeRequirement
    ↓
AI 分析：提取测试要点、边界条件、风险点
    ↓
回写 UserStory.AnalysisResult
    ↓
通知用户（Teams / Outlook）
```

**Power Automate Flow 要点**：

| 触发器 | Webhook（DevOps → 需求变更） / Power Apps Button |
|--------|-------------------------------------------------|
| 动作 | DevOps REST API → 解析 JSON → 写入 Dataverse → Service Bus |
| 异常处理 | 配置重试策略（3 次指数退避）+ 失败通知到 Teams |

### 5.3 测试用例生成

**触发条件**：
- 新增 UserStory
- 需求分析完成
- 用户在 Power Apps 点击"生成用例"

**流程**：

```
UserStory 进入"待生成"状态
    ↓
GenerateTestCases Function 接收消息
    ├─ (1) 从 AI Search 检索历史相关用例（RAG）
    ├─ (2) 加载 generate-test-cases.md Prompt
    ├─ (3) 调用 gpt-4o → 返回 JSON
    └─ (4) 解析 → 写入 Dataverse TestCase
    ↓
用例状态变为 Draft
    ↓
通知评审人
```

**关键逻辑**：
- RAG 检索相似用例防止重复生成
- 配置 `temperature: 0.3` 保证稳定性
- 每次生成数量限制 20 条，超出分多次调用
- 返回 JSON 失败时自动重试一次（Prompt 末尾加上"确保输出合法 JSON"）

### 5.4 用例评审模块

**前端**：Power Apps — `TestCaseReviewScreen`

功能：
- 展示待审用例列表
- 逐条查看：AI 生成的步骤 + 预期结果
- 操作：通过 / 驳回 / 修改后通过
- 驳回时填写原因（AI 会据此优化下次生成）

**评审状态流转**：

```
Draft ──→ Approved ──→ 可进入脚本生成
  │
  └──→ Rejected ──→ 记录驳回原因 ──→ 用户修改后 Draft
```

### 5.5 脚本生成

**流程**：

```
用例 Approved
    ↓
Power Automate 触发 GenerateScript Function
    ↓
(1) 加载用例步骤 + 页面元素映射
(2) 调用 gpt-4o-mini 生成 Playwright 代码
(3) 写入 GeneratedScript 字段
(4) 上传脚本文件到 Blob
    ↓
脚本状态更新
```

**页面元素映射管理**：

在 Power Apps 中维护一个 ElementMap 表：

| 字段 | 说明 |
|------|------|
| ApplicationId | 所属应用 |
| PageUrl | 页面路径 |
| ElementName | 元素语义名（如"登录按钮"） |
| Locator | 定位器（Playwright: `page.locator('#login-btn')`） |
| LocatorType | CSS / XPath / Text / Role |

AI 生成脚本时自动注入元素映射，提高脚本稳定性。

### 5.6 测试执行

**执行引擎架构**：

```
Power Automate / HTTP Request
    ↓
Azure Functions (Executor)
    ↓
Container Instance (Playwright 环境)
    ├── playwright.config.ts
    ├── test-script.spec.ts
    └── 输出：report.json + screenshot + video
    ↓
    Azure Blob Storage
    ↓
回写 TestExecution
```

**Playwright 执行配置**：

```typescript
// playwright.config.ts
export default defineConfig({
  timeout: 60000,
  retries: 1,

    ['json', { outputFile: 'report.json' }],
```

**并行执行策略**：

- 多个测试用例：workflow 级别并行（Power Automate Parallel Branch）
- 单个用例多个步骤：Playwright Worker 级别并行
- 跨应用：隔离 Container Instance

### 5.7 失败分析

**流程**：

```
TestExecution.Result = Fail
    ↓
Service Bus 消息 → AnalyzeFailure Function
    ↓
输入：错误信息 + 截图 URL + 日志 + 脚本代码
    ↓
调用 gpt-4o（analyze-failure.md）
    ↓
输出：根因分析 + 建议修复方案 + 缺陷分类
    ↓
写入 FailureAnalysis
    ↓
自动创建 Bug（DevOps / Jira）
```

**分析内容示例输出**：

```json
{
  "rootCauseCategory": "ElementNotFound",
  "rootCause": "按钮 '提交' 在页面加载完成前被点击，缺少等待条件",
  "confidence": "High",
  "suggestedFix": "在点击前添加 await page.waitForSelector('#submit-btn')",
  "defectType": "ScriptFlakiness",
  "isProductBug": false
}
```

**分类表**：

| 类别 | 说明 | 自动修复可行性 |
|------|------|--------------|
| ScriptFlakiness | 脚本稳定性问题（等待不足） | 高 |
| EnvironmentIssue | 环境不可用 | 低 |
| DataIssue | 测试数据问题 | 中 |
| ProductBug | 产品 Bug | 低（需人工） |
| ConfigurationIssue | 配置错误 | 中 |

## 6. 自动化流水线

### 6.1 Power Automate 工作流清单

| Flow 名称 | 触发器 | 主要动作 |
|-----------|--------|---------|
| Sync-AzureDevOps-WorkItems | 定时（每 5 分钟） | 拉取 DevOps Work Item 变化 → 同步到 Dataverse |
| AI-Analyze-Requirement | Service Bus | 调用 AnalyzeRequirement Function |
| AI-Generate-TestCases | Service Bus | 调用 GenerateTestCases Function |
| Notify-Review-Pending | 当 TestCase Status=Draft | 发送 Teams Adaptive Card 通知评审人 |
| AI-Generate-Script | 当 TestCase Status=Approved | 调用 GenerateScript Function |
| Execute-TestPlan-Scheduled | 定时 / 日历 | 触发 TestPlan 执行 |
| Collect-Execution-Results | 当 TestExecution 完成 | 汇总结果 → 更新 TestPlan → 通知 |
| Sync-Back-To-DevOps | 当 FailureAnalysis 关联 Bug | 创建/更新 DevOps Bug Work Item |
| Daily-Report-Email | 定时（每日 09:00） | 生成昨日摘要 → 发送 Outlook 邮件 |

**Flow 设计原则**：

1. 每个 Flow 只做一件事
2. 跨 Flow 状态传递通过 Dataverse 状态字段 + Service Bus
3. 错误分支统一发 Teams 通知
4. Flow 内不存储密钥（全走 Key Vault / Environment Variable）

### 6.2 Azure DevOps Pipeline

#### CI Pipeline — `ci-test-generation.yml`

```yaml
              zipAfterPublish: true

      - job: ValidatePrompts
        steps:
          - script: |
              # 检查所有 Prompt 模板中的参数引用是否匹配
              python scripts/validate-prompts.py

      - job: LintPlaywright

  - stage: DeployToDev
```

### 7.2 AI Prompt 测试

Prompt 变更必须有对应的测试用例验证输出质量。

```
ai-models/tests/
├── test-prompts.py              # 测试入口

```

测试指标：

| 指标 | 目标值 | 计算方法 |
|------|--------|---------|

| JSON 解析成功率 | 100% | JSON 格式合法比例 |
| 重复率 | <= 5% | 与历史用例重复的比例 |

### 7.3 质量门禁

在 CI Pipeline 中配置门禁：

```
Build ──→ ✓ 单元测试全部通过
    ──→ ✓ Prompt 验证通过
    ──→ ✓ Playwright 代码 lint 无 Error
    ──→ ✓ 所有连接引用有效
    ──→ → Deploy to Dev
```

### 7.4 端到端验收场景

1. **需求到用例**：在 DevOps 创建 User Story → Flow 同步 → AI 分析 → 生成用例 → 通知评审
2. **用例到脚本**：评审通过 → AI 生成 Playwright 脚本 → 脚本存入 Blob
3. **脚本到执行**：触发测试计划 → 容器执行 Playwright → 结果回写
4. **失败到分析**：测试失败 → AI 分析根因 → 创建 Bug → 通知开发者
5. **报告推送**：测试完成 → 自动生成报告 → Teams + 邮件推送

### 9.1 Application Insights 监控

配置项：

```
APPLICATIONINSIGHTS_CONNECTION_STRING: 从 Key Vault 读取
```

自定义埋点：

```csharp
// 每个 AI 调用记录性能
using (var operation = _telemetry.StartOperation<RequestTelemetry>("AICall"))
{
    operation.Telemetry.ResponseCode = "200";
    operation.Telemetry.Success = true;
    // 记录 Token 消耗
    _telemetry.TrackMetric("AITokenUsage", tokenCount, new Dictionary<string, string>
    {
        {"Model", modelName},
        {"PromptType", promptKey}
    });
}
```

关键仪表盘指标：

| 指标 | 告警阈值 | 说明 |
|------|---------|------|
| Function Failure Rate | > 5% | Function 调用失败率 |
| AI Response Time P95 | > 15s | AI 响应延迟 |
| Test Execution Pass Rate | < 80% | 测试通过率低于 80% |
| Service Bus Dead-Letter | > 0 | 死信队列有消息 |
| OpenAI Rate Limit Hit | > 10 次/小时 | 触发限流 |
| Flow Run Failure | > 3 次/小时 | Power Automate 失败 |

### 9.2 Power Automate 监控

- 使用 Power Automate Analytics（内置）
- 每个 Flow 开启 `Run history` 保留 30 天
- 配置 Action 级别的异常处理：失败时发 Teams 通知 + 写入 Dataverse `FlowErrorLog`
- 每月审计 Flow 运行成本（API 调用次数）

### 9.3 Azure OpenAI 成本监控

```bash
az monitor metrics list \
```
